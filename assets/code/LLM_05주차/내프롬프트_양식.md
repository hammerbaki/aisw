# 내 프롬프트 · 5주차 (쓰는 파일: week05/내프롬프트.md)

실습 1 · 준비 2(선택)에서 **AI가 이 세 개를 만들어 `내프롬프트.md`로 저장합니다.**
AI가 만든 것을 열어 읽고, 아래와 견주어 빠진 곳을 내 말로 채웁니다.
AI가 엉뚱하게 만들었으면 이 파일을 `내프롬프트.md`로 복사해 그대로 써도 됩니다.

    cp -n ~/week05/내프롬프트_양식.md ~/week05/내프롬프트.md

**언제 쓰나** · 이번 실습은 직접 지시로 진행합니다. 만든 프롬프트는 내 프로젝트에서 같은 작업을 할 때 씁니다. 수업 중에 써 보려면 1) · 2)는 실습 1 · 9/9, 3)은 실습 2 뒤에 포트폴리오에서 보냅니다.

**전제** · `내소재.md` 5주차 칸 1) 실행 명령 2) 작업 규칙 후보 4개 3) 금지 사항 2개 4) 검증 지시 한 줄이 채워져 있어야 합니다.

---

## 1) 네 절 채우기 (실습 1 · 9/9 · ~/week05/포트폴리오의 /init 초안 뒤에 보냅니다)

```
CLAUDE.md의 네 절(프로젝트 개요, 실행 명령, 작업 규칙, 금지 사항)을
~/week05/내소재.md 5주차 칸의 실행 명령 2개 · 작업 규칙 4개 · 금지 사항 2개로 채워라.
200줄 이내. 골격의 app/ 규칙처럼 이 폴더에 없는 것은 넣지 마라.
```

**확인할 것** · `!cat CLAUDE.md`로 네 절이 있고 200줄 이내인가. 실행 명령과 금지 사항이 포트폴리오의 파일 이름(index.html · 프로필.md · test_page.py)인가.

---

## 2) 검증 지시 (실습 1 · 9/9 · 고친 CLAUDE.md를 읽은 새 세션에서 보냅니다)

```
index.html의 projects 섹션에 프로젝트 하나를 추가하라.
```

(내소재.md 4)에 쓴 내 문장으로 바꿉니다.)

**확인할 것** · 실습 1 · 7/9와 같이 읽습니다. 구현보다 테스트를 먼저 만드는가(tests/ 수정이 index.html 수정보다 앞). 새 테스트가 `tests/`의 새 파일에 들어가고 고정 테스트 `test_page.py`는 그대로인가(Update 표시에 removed 줄이 없는가). 어긋나면 규칙 문장을 고쳐 한 번 더 시험합니다.

---

## 3) rules로 옮기기 (실습 2 뒤 · ~/week05/포트폴리오에서 보냅니다)

```
CLAUDE.md의 작업 규칙 중 특정 파일에만 해당하는 규칙 하나를 골라
.claude/rules/ 폴더에 파일로 옮겨라. 파일 맨 위에 ---로 감싼 머리말을 두고
paths: - "<그 파일의 경로>"를 적어라. CLAUDE.md에서는 그 줄을 지워라.
```

**확인할 것** · `!cat .claude/rules/*.md`로 첫 줄이 `---`이고 머리말에 paths가 있는가(없으면 경로가 본문에 글로만 적혀 매 세션 읽힙니다). 새 세션에서 그 경로의 파일을 읽는 지시를 보내 「Loaded .claude/rules/…」가 뜨고 규칙이 적용되는가.

---

## 왜 「200줄 이내」와 「없는 것은 넣지 마라」가 있는가

CLAUDE.md는 세션마다 컨텍스트에 실려 토큰 비용을 반복해서 내고, 너무 길면 놓칩니다. 골격의 규칙(app/ 아래에 둔다)을 그대로 두면 포트폴리오에는 app/이 없어 규칙이 헛돕니다. 「모든 세션에 적용되는가」를 통과한 것만 남깁니다.
