# 포트폴리오 점검

요구사항명세서의 REQ 항목마다 화면(index.html)과 테스트(포트폴리오/tests/)에 근거가 있는지 대조해 보고한다.
대상 폴더는 week07/포트폴리오/이다.

## 출력 서식

1. 첫 줄에 대상 폴더 경로를 적는다.
2. 표의 열은 REQ · 내용 요약 · 구현 근거 · 테스트 · 판정 다섯 개다.
3. 표 아래에 명세에 없는데 화면에 있는 섹션을 한 줄로 적는다.

## 절차

1. 요구사항명세서.md에서 REQ-로 시작하는 줄을 모두 읽는다.
2. index.html에서 section의 id와 관련 스크립트를 찾는다.
3. tests/의 테스트 함수 이름과 독스트링을 읽고 REQ에 대응시킨다.
4. REQ마다 판정한다: 구현 · 테스트 모두 있음 / 구현만 있음 / 없음.

## 규칙

- 테스트가 없는 REQ는 구현이 보여도 "구현만 있음"으로 적는다. 왜냐하면 화면에서 본 것은 사람이 확인하기 전까지 검증된 것이 아니기 때문이다.
- 파일을 고치지 말고 보고만 한다. 왜냐하면 점검과 수정을 섞으면 무엇이 원래 상태였는지 알 수 없기 때문이다.

## 환각 방지

- 근거 칸에는 파일 경로와 찾은 id나 함수 이름을 적는다.
- 파일을 열 수 없거나 대응이 확실하지 않으면 추측하지 말고 "확인 필요"로 적는다.
