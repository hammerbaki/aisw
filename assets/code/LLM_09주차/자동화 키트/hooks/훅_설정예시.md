# PostToolUse 훅 설정 예시

프로젝트의 `.claude/settings.json`에 아래 hooks 절을 추가하면, Claude Code가 파일을 쓰거나 고칠 때마다 파이썬 문법 검사가 자동 실행됩니다. 검사가 실패하면 종료 코드 2와 오류 출력(stderr)이 Claude에게 전달되어 스스로 대처합니다. 통과 시에는 아무것도 출력하지 않습니다. 통과 출력(종료 코드 0의 stdout)은 Claude에게 전달되지 않는 것이 훅의 규약입니다.

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "python -m compileall -q . || { echo '훅: 문법 오류 발견. 수정할 것' >&2; exit 2; }"
          }
        ]
      }
    ]
  }
}
```

- 훅은 지시가 아니라 이벤트마다 반드시 실행되는 강제 장치입니다.
- 검사 명령은 프로젝트에 맞게 바꿉니다 (예: `pytest -q`).
- 훅 설정 형식은 버전에 따라 바뀔 수 있습니다. `/hooks`와 [공식 문서](https://code.claude.com/docs/en/hooks-guide)가 우선합니다.
- 설정 변경 후에는 세션을 재시작해야 반영됩니다.

## 통지형 훅 (심화 선택)

검사형 훅이 결과를 대화 컨텍스트로 돌려준다면, 통지형 훅은 결과를 밖(메신저, 모바일)으로 내보냅니다. 예를 들어 긴 작업이 끝날 때 Slack 웹훅으로 알림을 보낼 수 있습니다.

```json
{
  "type": "command",
  "command": "curl -s -X POST \"$SLACK_WEBHOOK_URL\" -H 'Content-type: application/json' --data '{\"text\":\"Claude Code: 작업 완료\"}'"
}
```

- 웹훅 URL도 API 키와 같은 비밀값입니다. 설정 파일에 직접 쓰지 않고 환경변수(`SLACK_WEBHOOK_URL`)로 둡니다.
- 개인 Slack 워크스페이스와 웹훅 발급이 필요하므로 심화 선택입니다. 수업의 기본 실습은 파일 기록 방식의 통지를 유지합니다.
- 완성 예시는 [클로드 코드 마스터 공식 저장소의 slack-notification 샘플](https://github.com/claude-code-expert/lecture/tree/main/samples/slack-notification)에 있습니다(CC BY-NC-ND 4.0, 링크 열람용. 위 예시는 자체 작성입니다).
