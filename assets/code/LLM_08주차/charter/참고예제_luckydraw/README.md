# 참고 예제: Lucky Draw 명세 4종

단일 HTML 파일 하나로 완성되는 럭키 드로우 웹앱에 붙은 완결 명세 세트입니다. 출처는 《클로드 코드 마스터》(한빛미디어)의 공식 예제 저장소(https://github.com/claude-code-expert/lecture)이며, 명세 주도 개발(SDD)의 참고 실물로 수록했습니다. 원본 4개 문서(PRD·TRD·REQUIREMENTS·ANALYSIS)는 CC BY-NC-ND 4.0(저작자표시-비영리-변경금지) 조건에 따라 한 글자도 수정하지 않은 원본 그대로이며, 비영리 교육 목적으로 출처를 표시하여 수록한 것입니다. 이 안내문(README)만 과목 자체 작성입니다.

## 이 과목의 문서 체계와의 관계

이 과목은 Charter(왜·무엇)와 Spec(어떻게 동작해야 하는가)의 2문서 체계를 씁니다. 이 예제는 같은 내용을 4문서로 더 잘게 나눈 확장형입니다.

| 예제 문서 | 담는 것 | 이 과목에서의 대응 |
|---|---|---|
| PRD.md | 왜 만들고 무엇을 만드는가 | Charter |
| REQUIREMENTS.md | 기능 명세, UI, 검증 | Spec의 요구사항·검증 방법 |
| TRD.md | 데이터·알고리즘·상수의 기술 정본 | Spec의 기술 상세(이 과목에서는 별도 문서로 요구하지 않음) |
| ANALYSIS.md | 확정 결정과 변경 이력 | 의도 기록·문서 변경 이력 |

## 읽기 연습 1개

REQUIREMENTS.md에서 요구사항 문장 3개를 골라 EARS 문형(조건과 행위의 분리)으로 다시 써 봅니다. 원문이 이미 조건을 분리하고 있는지, 검증 방법이 붙어 있는지 대조하면 자기 Spec의 품질 기준을 세울 수 있습니다.
