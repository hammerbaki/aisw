# 요구사항 명세서 · 학교 기준 맛집 목록 (근거: 네이버지도-구조분석.md · 네이버 지도 「경기광주역 맛집」 관찰)

## 개요

ICT폴리텍대학 근처 맛집을 명령줄에서 찾아보는 프로그램. 브라우저 AI가 네이버 지도를 조작하며 쓴 구조 분석서(검색 결과 목록 · 가게 상세 · 길찾기 · 즐겨찾기 화면)에서 기능을 뽑아 문장 명세로 옮겼다. 지도 표시 · 사진 · 리뷰 본문 · 예약 · 로그인 · 즐겨찾기는 범위 밖. 데이터는 맛집.csv(이름, 종류, 기준점, 도보분, 가격대, 한줄메모).

## 화면

- 메뉴 화면: 번호를 골라 기능으로 들어간다
- 가게 목록 화면: 가게를 한 줄씩 보여 준다 (구조 분석서 1-1의 「검색 결과 목록」)

## 요구사항

- [상시] REQ-01 시스템은 시작할 때 메뉴(가게 목록 · 종류로 찾기 · 종료)를 번호와 함께 표시해야 한다. (메뉴 화면)
- [사건] REQ-02 사용자가 「가게 목록」을 고르면, 시스템은 맛집.csv의 모든 가게를 이름 · 종류 · 기준점 · 도보분 · 가격대 순서로 한 줄씩 표시해야 한다. (가게 목록 화면)
- [사건] REQ-03 사용자가 종류를 입력하면, 시스템은 그 종류의 가게만 표시해야 한다. (가게 목록 화면 · 분석서 2-1 필터 조건)
- [상시] REQ-04 시스템은 가게마다 기준점(정문 · 경기광주역 · 경안중 정류장)과 도보분을 함께 표시해야 한다. (가게 목록 화면 · 분석서 4-9 「거리는 가게 속성이 아니다」를 내 프로그램에서는 속성으로)
- [원치 않는 동작] REQ-05 만약 사용자가 없는 번호나 없는 종류를 입력하면, 시스템은 오류로 끝나지 않고 안내 문구를 표시한 뒤 메뉴로 돌아가야 한다. (메뉴 화면)
- [원치 않는 동작] REQ-06 만약 맛집.csv가 없거나 비어 있으면, 시스템은 빈 목록 대신 "데이터 파일이 없습니다" 안내를 표시해야 한다. (가게 목록 화면)
- [선택] REQ-07 가게에 한줄메모가 있으면, 시스템은 목록의 그 줄 끝에 메모를 표시해야 한다. (가게 목록 화면 · 분석서 4-2 한 줄 요약 문구)
- [상시] REQ-08 시스템은 목록의 가게 개수를 목록 아래에 표시해야 한다. (가게 목록 화면) ← 고침 (분석서 3 "검색 반경 · 전체 결과 개수를 알 수 없다"를 내 프로그램에서는 보이게)

## EARS 라벨 보고

- 고친 문장: 2 (원문 "가게를 적절히 보여 준다" → REQ-02, "오류를 잘 처리한다" → REQ-05)
- 빈 문형: 상태 (분석서 2-1의 「영업 중」 실시간 판정은 csv에 영업시간이 없어 범위 밖으로 둠)
- [사건] REQ-09 사용자가 「도보 시간 순」을 고르면, 시스템은 도보분이 짧은 가게부터 보여야 한다. ← 추가 (분석서 4-9: 네이버 지도에는 거리가 가게 속성으로 붙어 있지 않아 길찾기를 열어야 알 수 있다. 사람 메모의 불편 「걸어서 몇 분인지 바로 안 보인다」와 같은 자리)
