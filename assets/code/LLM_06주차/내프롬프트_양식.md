# 내 프롬프트 · 6주차 (쓰는 파일: week06/내프롬프트.md)

실습 3 · 4에서 Claude Code에 코드 완성을 맡길 때 보내는 프롬프트 두 개입니다. 직접 타이핑해도 됩니다. 맡겼으면 서버 터미널에서 pytest를 직접 돌려 결과로 판정합니다. 이 파일을 `내프롬프트.md`로 복사해 쓰고, 고친 문장은 거기에 남깁니다.

    cp -n ~/week06/내프롬프트_양식.md ~/week06/내프롬프트.md

**전제** · Claude Code는 `~/week06`에서 `claude`로 엽니다(터미널 1). 명령 실행은 서버 터미널에서 합니다. 키트의 `CLAUDE.md`(테스트 수정 금지 · 키를 코드에 쓰지 않음 · 실행 명령)가 세션을 열 때 함께 읽힙니다.

---

## 1) 검색기 두 함수 (실습 3 · 2/7에서 보냅니다)

```
@embed_search.py 이 파일의 미구현 함수 두 개(cosine_similarity,
search)를 독스트링에 적힌 순서대로 완성하라.
다른 함수와 상수는 건드리지 말라
```

**확인할 것** · `/exit` 뒤 서버 터미널에서 `.venv/bin/python -m pytest -q`가 `3 failed, 3 passed`인가. 3 passed는 검색기 테스트이고, 3 failed는 실습 4에서 다룰 `rag_chat.py` 테스트라 지금은 정상입니다. Claude Code의 Update 표시에 `tests/` 파일이 없는가(테스트를 고쳐 통과시킨 것이 아닌가).

---

## 2) 증강 프롬프트 (실습 4 · 2/5에서 보냅니다)

```
@rag_chat.py 이 파일의 build_prompt를 독스트링의
①②③ 구성대로 완성하라. trim_history와 다른 함수는 건드리지 말라
```

**확인할 것** · `/exit` 뒤 서버 터미널에서 `.venv/bin/python -m pytest -q`가 `1 failed, 5 passed`이고 실패 이름이 `test_trim_history…`인가. 남은 1개는 이번 실습에서 채우지 않는 `trim_history`라 정상입니다. 근거 태그에 번호가 붙는가, 질문 태그가 있는가, 지시에 「근거만 · 없으면 「주어진 자료에서 찾을 수 없습니다」 · 번호 표기」 세 가지가 있는가.

---

## 왜 「다른 함수는 건드리지 말라」가 있는가

맡긴 범위 밖을 고치면 검증할 곳이 늘어납니다. 지시문 설계에서 배운 금지의 명시가 코드 완성 위임에서도 같은 원리로 동작합니다. 키트의 CLAUDE.md도 같은 금지를 매 세션 읽히게 해 둔 것입니다.
