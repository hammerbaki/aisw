[10주차] 발표와 마스터 검증

10주차

발표와 마스터 검증

마지막 회차는 한 학기 산출물의 발표와 검증입니다. 각자 배포된 URL로 개인 프로젝트를 라이브 시연하고, 청중은 발표자의 URL에 직접 접속해 크로스 테스트를 수행합니다. 발표 후에는 면접 질문 30선으로 자기 언어의 답을 만드는 모의 문답, 그리고 학기 동안의 신기능 적용 기록 회고를 진행합니다. 이 회차의 산출물이 그대로 취업 포트폴리오와 면접 준비 자료가 됩니다.

이 회차의 기술은 검증 가능한 발표입니다. 주장 대신 동작하는 URL과 검증 코드로 증명합니다.

graph LR
    P["<b>프롬프트 엔지니어링</b><br/>무엇을 말할까"] --> C["<b>컨텍스트 엔지니어링</b><br/>무엇을 보여줄까<br/><i>CLAUDE.md</i>"] --> H["<b>하네스 엔지니어링</b><br/>어떤 환경을 만들까<br/><i>MCP·Skill·Hook</i>"] --> L["<b>루프 엔지니어링</b><br/>어떻게 반복시킬까<br/><i>에이전트·자동화</i>"]
단계 이 회차 기술(검증 가능한 발표)의 역할
프롬프트 면접 답변도 완결된 지시문처럼 구성합니다. 예: 결론 한 문장, 근거, 실제로 해 본 것의 3단 구성으로 답을 설계
컨텍스트 발표는 청중이 가진 컨텍스트에 맞춰 줄인 요약입니다. 예: 세부 구현 대신 요구사항과 검증 결과를 먼저 보여 청중의 판단 근거를 채움
하네스 시연 전 배포 파이프라인이 발표 사고를 막는 안전장치입니다. 예: 발표 직전 점검 통과·배포로 URL이 최신 판임을 보장
루프 크로스 테스트의 발견이 다음 개선의 입력이 됩니다. 예: 청중이 찾은 비정상 입력 문제를 기말 제출 전 마지막 수정으로 반영

학습 목표

  • 배포 URL 라이브 시연과 검증 코드로 프로젝트를 발표할 수 있습니다.
    • 예시: 정상 시나리오, 경계 시나리오, 검증 결과의 3단 시연을 시간 안에 수행
    • 장점: “만들었다”가 아니라 “동작하는 주소와 검증 증빙이 있다”로 말하는 포트폴리오 발표 경험
  • 동료 산출물을 크로스 테스트로 검증하고 결과를 전달할 수 있습니다.
    • 예시: 발표자의 URL에 접속해 비정상 입력 시나리오를 시험하고 기록표를 전달
    • 장점: 코드 리뷰·QA(품질 보증) 협업의 기본 소통 방식 훈련
  • 면접 질문에 실습 경험을 근거로 자기 언어의 답을 만들 수 있습니다.
    • 예시: “환각은 왜 발생하는가”에 확률적 생성 원리와 검증 레이어 경험을 붙여 답변
    • 장점: 질문은행 30문이 그대로 기술 면접 대비 자료가 됨
  • 한 학기의 신기능 적용 기록을 진화 지도 위에서 회고할 수 있습니다.
    • 예시: 학기 중 조사한 신기능들이 지도의 어느 단계에 몰렸는지 정리하고 자기 프로젝트 적용분을 표시
    • 장점: 도구 변화를 스스로 따라잡는 방법을 가졌다는 것이 면접의 마지막 답변이 됨

1. 발표 형식과 평가 기준

발표는 1인 단위이며 시연 중심입니다. 구성은 3단입니다. ① 프로젝트 소개(1분): Charter의 한 줄 정의와 사용자, 핵심 기능. ② 라이브 시연(3분): 배포 URL에 직접 접속해 정상 시나리오 1개와 경계·비정상 시나리오 1개를 보입니다. 로컬 화면이 아니라 실제 URL로 시연합니다. ③ 검증 발표(2분): Spec의 요구사항 중 2개를 골라, 무엇으로 검증했는지(테스트 코드, 평가 기록, 배포 전 점검)를 증빙 화면으로 보입니다.

평가는 시연의 화려함이 아니라 검증 가능성을 봅니다. URL이 동작하는가, 요구사항과 검증 증빙이 연결되는가, 질문에 자기 언어로 답하는가입니다. 청중에게도 역할이 있습니다. 발표마다 지정된 2명이 발표자의 URL에 접속해 즉석 크로스 테스트를 수행하고 기록표를 남깁니다.

2. 실습 1: 발표 직전 점검

발표 시작 전 15분 동안 각자 수행합니다.

  1. 배포 파이프라인으로 최신 판을 배포합니다. 자동화 실습의 deploy.sh 절차대로 점검 통과와 배포를 확인하고, URL을 새 창에서 열어 동작을 확인합니다.
  2. 시연 시나리오 2개(정상 1, 경계·비정상 1)를 week10/발표시나리오.md에 세 줄씩 적고 한 번 리허설합니다. 입력할 값과 기대 동작을 그대로 적어, 시연 중 즉흥 입력으로 무너지지 않게 합니다.
  3. 검증 증빙 화면(테스트 실행 결과, 평가 기록, 점검 통과 출력) 중 보여줄 2개를 열어 둡니다.

[확인 1] 발표시나리오.md와 최신 배포 URL, 증빙 화면 2개가 준비되었다.

3. 발표와 크로스 테스트

발표 순서와 1인당 시간은 수업 서두에 공지됩니다. 발표자 외의 역할은 다음과 같습니다.

  1. 지정 테스터 2명: 발표자의 URL에 접속해 크로스 테스트 기록표(자동화 실습과 같은 양식)의 시나리오 3종(정상, 경계값, 비정상 입력)을 수행하고, 발표 종료 시 기록표를 전달합니다.
  2. 나머지 청중: 질문 1개 이상을 준비합니다. 질문은 “무엇으로 검증했는가”, “왜 그 부품(스킬, 훅, MCP(Model Context Protocol))을 골랐는가” 유형을 우선합니다.

발표자는 받은 기록표의 발견 사항을 week10/발표기록.md에 옮기고, 기말 제출 전에 반영할 항목을 표시합니다.

[확인 2] 자기 발표의 시연이 실제 URL로 수행되었고, 받은 크로스 테스트 기록표가 발표기록.md에 정리되었다.

[확인 3] 테스터로 참여한 발표에서 작성한 기록표가 상대에게 전달되었다.

4. 면접 질문 30선과 모의 문답

배포물 “면접 질문 30선”은 이 과목의 학습 순서로 정리한 질문은행입니다. 네 축(LLM 원리, Claude Code 운용, 애플리케이션 개발, 운영·보안·배포) 30문이며, 각 질문에는 답이 들어 있는 실습을 가리키는 실마리가 붙어 있습니다. 모든 질문은 원전 공식 문서와 이 과목의 실습 안에서 답할 수 있습니다.

답변의 표준 구성은 3단입니다. 결론 한 문장, 원리 근거, 그리고 실제로 해 본 것 한 가지. 마지막 단이 이 과목 수강생의 차별점입니다. 어떤 질문이든 붙일 실습 경험이 있기 때문입니다.

5. 실습 2: 자기 답 작성과 모의 문답

  1. 질문은행에서 축이 다른 질문 3개를 골라, 3단 구성의 답을 week10/면접답안.md에 자기 언어로 작성합니다. 실마리의 실습 기록을 다시 열어 “실제로 해 본 것”을 구체적으로 씁니다.
  2. 짝과 모의 문답을 진행합니다. 서로 2문항씩 묻고, 답이 끝나면 묻는 쪽이 후속 질문(“그건 왜 그렇게 됩니까”) 1개를 이어 던집니다. 후속 질문에서 막힌 지점을 각자 기록합니다.
  3. 막힌 지점의 답을 보완해 면접답안.md를 갱신합니다.

[확인 4] 3문항의 3단 구성 답과, 모의 문답에서 막힌 지점의 보완 기록이 면접답안.md에 있다.

6. 입사 후의 환경: 엔터프라이즈 AI 운영

입사하면 AI 도구는 개인 설정이 아니라 조직 관리형 정책으로 운영됩니다. 회사 단위로 설정·권한이 통제되고, 도입 심사에서는 코드·데이터가 어디로 가서 얼마나 보존되는지(데이터 사용 정책)가 핵심 항목이 됩니다. API 키 관리, 민감 파일 접근 차단, 로컬 모델 보완축처럼 이 과목에서 다룬 보안 요소들이 전부 그 심사의 세부 항목입니다. 면접 질문 30선의 운영·보안 축이 이 환경에 대한 대비입니다.

7. 신기능 적용 기록 회고

학기 동안의 신기능 탐지 기록을 모아 회고합니다.

  1. 자기 실습기록들에서 신기능 탐지 서식(기능, 변화, 적용 장면, 지도 위치)을 모아 week10/신기능회고.md에 목록으로 옮깁니다.
  2. 두 가지를 정리합니다. 조사한 기능들이 진화 지도의 어느 단계에 몰렸는가. 그중 자기 프로젝트에 실제로 적용한 것과 적용하지 못한 이유는 무엇인가.
  3. 마지막 한 문단으로 답합니다. “다음에 처음 보는 도구 변화를 만나면 나는 어떤 절차로 따라잡을 것인가.”

[확인 5] 신기능회고.md에 기록 목록, 지도 분포, 절차 한 문단이 작성되었다.

8. 당일 제출물

수업 종료 시점에 개인 폴더에 다음이 있어야 합니다.

  1. week10/발표시나리오.md와 week10/발표기록.md (받은 크로스 테스트 기록표 정리 포함)
  2. 테스터로 작성해 전달한 크로스 테스트 기록표 사본
  3. week10/면접답안.md (3문항, 보완 기록 포함)
  4. week10/신기능회고.md
  5. [확인 1]부터 [확인 5]까지 중 수업에서 지정한 항목의 답

제출은 개인 폴더의 상태로 갈음합니다.

9. 기말 제출물

기말 평가는 개인 프로젝트 폴더의 상태로 하며, 마감은 수업에서 공지하는 기말 제출 기한입니다. 다음이 갖춰져야 합니다.

  1. 동작하는 산출물: 최신 판이 배포된 URL (README 첫 줄에 명시)
  2. 방법론 산출물: Charter.md, Spec.md(요구사항과 검증 방법), 확장설계서.md, sync 점검 최종본
  3. 검증 산출물: 테스트 코드, 평가·점검 기록, 배포 파이프라인 스크립트와 통과 증빙
  4. 발표 반영: 크로스 테스트에서 받은 발견 사항 중 반영한 항목의 기록 (발표기록.md 갱신)

배점과 평가 항목은 오리엔테이션에서 안내한 평가 체계를 따릅니다.

마무리

이 과목은 프롬프트, 컨텍스트, 하네스, 루프의 진화 지도를 따라 왔습니다. LLM의 원리에서 시작해 API 연동, RAG, 도구 사용, 확장 기능, 에이전트, 평가, 자동화를 거쳐, 오늘 각자의 산출물이 실제 URL로 시연되고 서로에게 검증받았습니다. 과정 전체를 관통한 두 문장은 유지됩니다. AI가 만들고, 사람이 검증한다. 그리고 AI가 준 것을 절대 그대로 쓰지 않는다. 도구는 계속 바뀌지만, 변화를 읽고 검증하며 적용하는 절차는 여러분의 것입니다.
