# 맛집 · 명세서를 처음부터 다시 만드는 프롬프트

같은 폴더의 네이버지도-구조분석.md(브라우저 AI가 네이버 지도에서 「경기광주역 맛집」을 검색하고 결과 3곳을 직접 눌러 본 뒤 쓴 서비스 구조 분석서)를 근거로 다음 순서로 진행한다. 첫 프롬프트(구조 추정)는 브라우저 AI에 보낸 것이고, ②~④는 Claude Code에서 보낸다.

① (브라우저 AI) 지금 열린 지도 앱에서 「경기광주역 맛집」을 검색하고 결과 3곳을 직접 눌러 본 뒤, 이 서비스의 구조를 추정하라. 완료 조건: ① 화면(섹션) 목록과 이동 흐름 ② 화면 뒤에서 일어나는 처리의 추정 목록 ③ 써 보고도 알 수 없는 것의 목록. 직접 보지 못한 것은 추측이라고 표시하라.
② (Plan 모드) 네이버지도-구조분석.md를 근거로 이 서비스의 기능 목록을 만들어라. 완료 조건: 각 기능은 한 줄 설명과 관련 화면 이름을 포함하고, 화면 기능과 내부 처리 기능을 구분한다.
③ (Plan 해제) 위 기능 목록을 바탕으로 요구사항 명세서를 작성하라. 완료 조건: 각 요구사항은 어떤 조건에서 무엇을 해야 하는지가 드러나는 한 문장으로 쓰고, 고유 ID와 관련 파일(또는 화면)을 표기한다. 결과는 spec/요구사항명세서.md로 저장하고, 이 명세서를 처음부터 다시 만들 수 있는 프롬프트도 spec/프롬프트.md로 함께 저장하라.
④ spec/요구사항명세서.md의 각 요구사항을 EARS 다섯 문형(상시·사건·상태·원치 않는 동작·선택) 중 하나로 분류해 문장 앞에 문형 라벨을 붙이고, 조건이나 행위가 빠져 어느 문형에도 들어가지 않는 문장은 고쳐서 같은 파일에 다시 저장하라. 고친 문장과 분류하지 못한 문장은 목록으로 보고하라.

재생성 대상은 python3 하나로 실행되는 명령줄 프로그램이며 데이터는 맛집.csv(이름,종류,기준점,도보분,가격대,한줄메모)에서 읽는다. 지도 · 사진 · 리뷰 · 예약 · 로그인 · 즐겨찾기는 범위 밖이다.

#!/usr/bin/env python3
"""학교 기준 맛집 목록 · 명령줄 프로그램.

근거: 같은 폴더의 요구사항명세서.md (REQ-01 ~ REQ-09)
데이터: 같은 폴더의 맛집.csv (이름,종류,기준점,도보분,가격대,한줄메모)
"""
import csv
import os
import sys

HERE = os.path.dirname(os.path.abspath(__file__))
DATA = os.path.join(HERE, "맛집.csv")


def load():
    """REQ-06: 파일이 없거나 비어 있으면 안내하고 빈 목록을 돌려준다."""
    if not os.path.exists(DATA):
        print("데이터 파일이 없습니다: 맛집.csv")
        return []
    with open(DATA, encoding="utf-8", newline="") as f:
        rows = [r for r in csv.DictReader(f) if r.get("이름")]
    if not rows:
        print("데이터 파일이 없습니다: 맛집.csv (비어 있음)")
    return rows


def walk_min(row):
    try:
        return int(row.get("도보분", "") or 0)
    except ValueError:
        return 0


def show_list(rows, title="가게 목록"):
    """REQ-02 · REQ-04 · REQ-07 · REQ-08: 가게를 한 줄씩, 개수는 아래에."""
    print(f"\n[{title}]")
    for i, r in enumerate(rows, 1):
        memo = f" · {r['한줄메모']}" if r.get("한줄메모") else ""  # REQ-07
        print(f"{i:2d}) {r['이름']} | {r['종류']} | {r['기준점']}에서 도보 {r['도보분']}분 | {r['가격대']}{memo}")
    print(f"모두 {len(rows)}곳")  # REQ-08 ← 고침


def show_by_walk(rows):
    """REQ-09 ← 추가: 도보분이 짧은 가게부터."""
    show_list(sorted(rows, key=walk_min), "도보 시간 순")


def find_by_kind(rows):
    """REQ-03 · REQ-05: 종류로 거른다. 없는 종류면 안내."""
    kind = input("종류 (예: 분식, 한식, 카페): ").strip()
    hit = [r for r in rows if r["종류"] == kind]
    if not hit:
        print(f"'{kind}' 종류의 가게가 없습니다. 있는 종류: {', '.join(sorted({r['종류'] for r in rows}))}")
        return
    show_list(hit, f"{kind} 가게")


def main():
    rows = load()
    while True:
        print("\n1) 가게 목록  2) 도보 시간 순  3) 종류로 찾기  0) 종료")  # REQ-01
        choice = input("선택: ").strip()
        if choice == "0":
            print("종료합니다.")
            return
        if not rows:
            rows = load()
            if not rows:
                continue
        if choice == "1":
            show_list(rows)
        elif choice == "2":
            show_by_walk(rows)
        elif choice == "3":
            find_by_kind(rows)
        else:
            print("없는 번호입니다. 1 · 2 · 3 · 0 중에서 고르세요.")  # REQ-05


if __name__ == "__main__":
    try:
        main()
    except (KeyboardInterrupt, EOFError):
        print("\n종료합니다.")
        sys.exit(0)

# 요구사항 명세서 · 학교 기준 맛집 목록 (근거: 네이버지도-구조분석.md · 네이버 지도 「경기광주역 맛집」 관찰)

## 개요

ICT폴리텍대학 근처 맛집을 명령줄에서 찾아보는 프로그램. 브라우저 AI가 네이버 지도를 조작하며 쓴 구조 분석서(검색 결과 목록 · 가게 상세 · 길찾기 · 즐겨찾기 화면)에서 기능을 뽑아 문장 명세로 옮겼다. 지도 표시 · 사진 · 리뷰 본문 · 예약 · 로그인 · 즐겨찾기는 범위 밖. 데이터는 맛집.csv(이름, 종류, 기준점, 도보분, 가격대, 한줄메모).

## 화면

- 메뉴 화면: 번호를 골라 기능으로 들어간다
- 가게 목록 화면: 가게를 한 줄씩 보여 준다 (구조 분석서 1-1의 「검색 결과 목록」)

## 요구사항

- [상시] REQ-01 시스템은 시작할 때 메뉴(가게 목록 · 종류로 찾기 · 종료)를 번호와 함께 표시해야 한다. (메뉴 화면)
- [사건] REQ-02 사용자가 「가게 목록」을 고르면, 시스템은 맛집.csv의 모든 가게를 이름 · 종류 · 기준점 · 도보분 · 가격대 순서로 한 줄씩 표시해야 한다. (가게 목록 화면)
- [사건] REQ-03 사용자가 종류를 입력하면, 시스템은 그 종류의 가게만 표시해야 한다. (가게 목록 화면 · 분석서 2-1 필터 조건)
- [상시] REQ-04 시스템은 가게마다 기준점(정문 · 경기광주역 · 경안중 정류장)과 도보분을 함께 표시해야 한다. (가게 목록 화면 · 분석서 4-9 「거리는 가게 속성이 아니다」를 내 프로그램에서는 속성으로)
- [원치 않는 동작] REQ-05 만약 사용자가 없는 번호나 없는 종류를 입력하면, 시스템은 오류로 끝나지 않고 안내 문구를 표시한 뒤 메뉴로 돌아가야 한다. (메뉴 화면)
- [원치 않는 동작] REQ-06 만약 맛집.csv가 없거나 비어 있으면, 시스템은 빈 목록 대신 "데이터 파일이 없습니다" 안내를 표시해야 한다. (가게 목록 화면)
- [선택] REQ-07 가게에 한줄메모가 있으면, 시스템은 목록의 그 줄 끝에 메모를 표시해야 한다. (가게 목록 화면 · 분석서 4-2 한 줄 요약 문구)
- [상시] REQ-08 시스템은 목록의 가게 개수를 목록 아래에 표시해야 한다. (가게 목록 화면) ← 고침 (분석서 3 "검색 반경 · 전체 결과 개수를 알 수 없다"를 내 프로그램에서는 보이게)

## EARS 라벨 보고

- 고친 문장: 2 (원문 "가게를 적절히 보여 준다" → REQ-02, "오류를 잘 처리한다" → REQ-05)
- 빈 문형: 상태 (분석서 2-1의 「영업 중」 실시간 판정은 csv에 영업시간이 없어 범위 밖으로 둠)
- [사건] REQ-09 사용자가 「도보 시간 순」을 고르면, 시스템은 도보분이 짧은 가게부터 보여야 한다. ← 추가 (분석서 4-9: 네이버 지도에는 거리가 가게 속성으로 붙어 있지 않아 길찾기를 열어야 알 수 있다. 사람 메모의 불편 「걸어서 몇 분인지 바로 안 보인다」와 같은 자리)
