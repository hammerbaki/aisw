CLAUDE.md와 LLM 동작 원리

실습 자료 이 주차 키트 파일 보기 · 내려받기

프롬프트 · 컨텍스트 수업은 문제 하나를 남기고 끝났습니다. 대화를 요약하거나 비우면 말로 한 지시가 모델에 더 이상 전달되지 않으므로, 사라지면 안 되는 규칙은 대화가 아니라 파일에 두어야 한다는 것이었습니다. 이 수업에서는 그 파일을 직접 만듭니다. 세션을 열 때마다 자동으로 읽히는 규칙 파일, CLAUDE.md입니다.

규칙 파일을 만든 뒤에는 AI 내부를 봅니다. 우리는 그동안 AI에게 일을 시키고 결과를 검증해 왔지만, AI가 답을 어떻게 만들어 내는지는 다루지 않았습니다. 답이 매번 다른 이유, 그럴듯한 오답이 나오는 이유, 대화가 길어질수록 요금이 쌓이는 이유가 전부 AI가 답을 만드는 방식에 있습니다.

진행은 세 부분입니다. ① CLAUDE.md: 골격과 포트폴리오에 CLAUDE.md를 만들고(실습 1), 특정 경로에만 필요한 규칙을 rules 파일로 나눕니다(실습 2). ② 컨텍스트 윈도우와 메모리: 세 저장 위치의 유지 범위를 비교하고, 판정 질문 두 개로 정보를 둘 곳을 정합니다. ③ LLM 동작 원리와 환각: 다음 토큰의 확률 계산이라는 구조에서 응답이 흔들리는 이유와 환각의 원인을 보고, 토큰 수를 실측합니다(실습 3). 시작은 매주 같습니다. 환경 접속과 자료 받기(0장)입니다.

0. 시작하기: 환경 접속, 자료 받기, 프롬프트 · 컨텍스트 되짚기

수업은 수업마다 같은 순서로 시작합니다. 서버에 접속하고, 터미널 2개를 배치하고, Claude Code가 동작하는지 점검하고, week05 자료를 받습니다. 처음이거나 절차를 잊었어도 이 장만 따라오면 실습을 시작할 수 있습니다.

0-1. 실습 환경 접속

앞선 수업에서 갖춘 환경을 그대로 다시 엽니다. 처음이거나 절차를 잊었다면 아래 「처음 접속하거나 절차를 잊은 사람」부터.

  1. 서버 접속. PowerShell에서 ssh 아이디@서버주소(비밀번호는 쳐도 안 보임). 프롬프트가 [아이디@실습서버 ~]$로 바뀌면 성공. VS Code Remote-SSH를 쓰면 같은 프롬프트가 VS Code 터미널에 뜹니다. 이 창이 내 PC인지 서버인지는 프롬프트가 알려줍니다. PS C:\Users\이름> = 내 PC, 대괄호에 @실습서버가 보이면 서버(날짜 · 시각 · 폴더가 함께 나올 수 있습니다).

    처음 접속하거나 절차를 잊은 사람. 계정은 1주차에 나눠 준 아이디(이름 영문 약자+성, 예: 홍길동 → gdhong)이고 목록은 덱의 「접속 · 첫 접속」 장에 있습니다. 설치가 안 되어 있으면 「접속 · 설치」 장을 따릅니다. PowerShell을 열고(시작 검색 “Windows PowerShell” 또는 Win+X → 터미널) 아래를 칩니다. 첫 접속에만 continue connecting? (yes/no)? 질문이 나오고 yes를 칩니다. 비밀번호는 쳐도 화면에 안 보이는 것이 정상이고, 끊기면 다시 ssh부터입니다. 초기 비밀번호는 전원 공통이니 접속 뒤 passwd로 반드시 바꿉니다(현재 비밀번호 → 새 비밀번호 2번 → updated successfully). 아이디나 비밀번호를 모르면 손을 듭니다.

내 PC · PowerShell 
   ssh 아이디@서버주소
   ... continue connecting? (yes/no)? yes  # 첫 접속에만
   아이디@서버주소's password:  # 입력해도 안 보임
   [아이디@실습서버 ~]$  # 접속 성공!
서버 터미널 
   passwd
  • 확인 1 프롬프트에 @실습서버가 보이고, 초기 비밀번호였다면 passwd로 바꿨다.

VS Code Remote-SSH(권장). VS Code 설치(최초 1회) → 왼쪽 확장(Extensions) 아이콘 → “Remote - SSH” 검색 → Install(최초 1회) → F1 → Remote-SSH: Connect to Host... → 아이디@서버주소 입력(ssh는 붙이지 않습니다) → 처음이면 Linux 선택 → 비밀번호 → 왼쪽 아래에 SSH: 서버주소가 보이면 연결 완료 → File > Open Folder → /home/아이디. 탐색기에 서버 파일이 보이고, Ctrl+S 저장이 곧 서버에 쓰기입니다. 연결이 안 되면 PowerShell 창 2개로 각각 ssh 접속하면 그 두 창이 터미널 1 · 2를 대신합니다(파일은 cat으로 확인). 붙여넣기는 VS Code 터미널 Ctrl+V, PowerShell은 우클릭.

  • 확인 2 왼쪽 아래에 SSH: 서버주소가 보인다. 탐색기에 서버 파일이 보이고, 터미널 2개가 모두 서버에서 열려 있다.

  1. 터미널 2개 배치. 터미널 1 = Claude Code(지시하는 창), 터미널 2 = 서버 명령(직접 실행해 확인하는 창). 나란히 엽니다. VS Code에서는 Terminal > New Terminal, 분할 아이콘으로 하나 더. 이 터미널은 서버에서 열리므로 ssh를 다시 치지 않습니다. 강의안의 배지 [Claude Code 터미널] / [서버 터미널]가 이 구분이고, claude가 떠 있는 동안의 입력은 [Claude Code 안]입니다. 두 터미널의 현재 폴더는 각각 따로 바뀝니다. 한쪽에서 cd를 해도 다른 쪽은 움직이지 않습니다. Remote-SSH가 안 되면 PowerShell 창 2개로 진행합니다.

  2. 환경 점검. claude 버전 → API 키 → 모델 순서로 칩니다.

서버 터미널 
   claude --version
   echo ${ANTHROPIC_API_KEY:0:8}
   2.x.x  (버전 숫자는 달라도 됩니다)
   sk-ant-a  (빈 줄이면 키 없음 → 「접속 · 설치」 장)
Claude Code 안 
   > /status
     Model: haiku
   /exit

/status에 Model: haiku가 보이면 준비 완료입니다. Model이 haiku가 아니면 /model에서 다시 선택합니다. 이 모델은 Claude Code 대화의 모델입니다. 실습 3의 토큰 측정 스크립트가 부르는 API 모델은 프롬프트 수업의 채점기와 같이 COURSE_MODEL(없으면 수업 기본 모델)이며, 같은 ANTHROPIC_API_KEY를 씁니다. 비밀번호를 잊었으면 손을 들어 알립니다. claude: command not found면 터미널을 닫고 새로 엽니다. claude를 실행했을 때 로그인 방법을 고르는 화면이 나오면 키 등록이 빠진 것입니다. echo 줄이 빈 줄이어도 같은 상태입니다. 앞 8자 sk-ant-a는 모든 키가 같은 접두어라 비밀이 아니고, 그 뒤는 화면에 출력하지 않습니다.

아직 설치와 키 등록을 하지 않았다면(처음이거나 잊었다면). 배포 폴더 /home/공용계정/week01에 들어 있는 접속 가이드를 따라옵니다. 요약하면 curl -fsSL https://claude.ai/install.sh | bash → 터미널을 닫았다 새로 열기 → claude --version → cat ~/*.txt로 키 복사 → echo 'export ANTHROPIC_API_KEY=발급키' >> ~/.bashrc → source ~/.bashrc → claude 첫 실행 승인(Yes → Security notes에서 Enter → 폴더 신뢰 Yes) → /model에서 Haiku 선택(Opus 금지. 기본 모델은 계정 · 버전에 따라 다르며 Opus일 수 있습니다) → /status. 모두 최초 1회이고 재접속해도 유지됩니다. 설치 · 키 등록 · 모델 설정은 모두 서버 터미널에서 합니다. 내 PC PowerShell 창에서 치면 설치되지 않습니다. 명령을 치기 전에 프롬프트로 창을 확인합니다. 키 원문은 화면 공유나 채팅에 노출하지 않습니다.

[Claude Code 안] · 모델 설정

   > /model   → 목록에서 Haiku 선택 (Opus 금지)
   > /status
     Model: haiku
   > /exit

로그인 방법 선택 화면이 나오면 키 등록이 빠진 것입니다. Go back으로 나가 키 등록부터 다시 합니다.

0-3. 프롬프트 · 컨텍스트 되짚기

프롬프트 · 컨텍스트 수업은 세 부분이었습니다(덱 「RECAP · 프롬프트 · 컨텍스트」).

부분 무엇을 했나
① 프롬프트 엔지니어링 지시문은 맥락 · 요청 · 금지로 구성하고, 시스템 프롬프트 · XML 태그 · 예시로 전달하면 AI가 추측으로 채우는 부분이 줄어듭니다. 모델 · 문항 · 채점기를 고정하고 프롬프트만 바꿔 v0 ~ v3를 비교했습니다(통제된 비교). 정확도(v0 → v3)는 0% → 90% → 100% → 0%였습니다. 교수 실행 1회에서 v3 응답 20건 모두 JSON을 마크다운 코드 블록으로 감싸 JSON 검사를 통과하지 못했고, 다시 실행해도 0~3건만 통과했습니다. 형식은 지시만으로 보장되지 않습니다
② 컨텍스트 윈도우 /status는 세션 조건을, /context는 System prompt · System tools · Messages별 토큰 사용량을 보여 줍니다. 새 세션도 비어 있지 않아서, 대화를 시작하기 전에도 19.2k/200k가 사용 중입니다. /compact는 원문을 요약으로 대체하고 /clear는 대화를 비웁니다. 대화로만 전달한 규칙은 사라질 수 있습니다
③ 기록과 정리 v0 ~ v3는 prompts/에 파일로 두고 실행하며, 채점 결과는 results/에 버전별 폴더로 저장했습니다. prompts/ · results/ · 내소재.md를 함께 커밋하면 같은 조건으로 다시 측정할 수 있습니다. 점수 표로 채택 버전을 정하고, 계속 지킬 규칙을 기록했습니다

프롬프트 · 컨텍스트 수업에 남은 문제가 이 수업의 어디에서 풀리는지 정리하면 다음과 같습니다(덱 「RECAP · 이번 주로 이어지는 것」).

그 수업에서 본 장면 남은 문제 해결되는 곳
/compact 뒤 대화로 정한 규칙이 빠짐 규칙을 세션마다 다시 말해야 함 이번 주 · CLAUDE.md. 실습 1. 세션마다 자동으로 읽히는 규칙 파일
새 세션도 대화 전에 19.2k/200k 사용 규칙을 늘릴수록 매 세션 비용도 늘어남 이번 주 · 경로별 규칙. 실습 2. 특정 경로 규칙은 rules 파일로 분리
같은 v3가 실행마다 0~3건만 통과 답이 왜 흔들리는지 설명하지 못함 이번 주 · LLM 동작 원리. 실습 3. 형식 강제(구조화된 출력)는 API 회차
승인 · 금지를 지시문으로만 요구 지시만으로는 지켜진다는 보장이 없음 이후 · 하네스 회차. Hook 등 프로그램이 직접 막음

셋째 줄은 둘로 나뉩니다. 답이 흔들리는 이유는 이 수업의 LLM 동작 원리(샘플링)로 설명하고, 형식을 프로그램이 강제하는 구조화된 출력은 API 회차에서 직접 만듭니다.

프롬프트 수업의 방식은 코딩 밖에서도 그대로 쓰입니다. 프롬프트를 직접 쓰지 않고 AI에게 만들게 하는 것입니다(덱 「RECAP · 프롬프트 활용」).

활용 예 AI가 먼저 물어볼 것 내가 넣을 재료 받을 결과
이력서 지원 직무, 경력 · 프로젝트별 역할과 성과 수업 · 동아리 · 인턴 기록, 채용 공고 직무에 맞춘 이력서 작성 프롬프트
자기소개서 문항, 글자 수, 강조할 경험 두세 개 문항 원문, 경험 메모 문항별 초안 작성 프롬프트
포트폴리오 소개문 대상 독자, 프로젝트마다 문제 · 역할 · 결과 README, 커밋 기록, 결과 화면 프로젝트 소개문 프롬프트
발표 대본 발표 시간, 청중, 슬라이드별 핵심 슬라이드 제목 목록 슬라이드별 대본 프롬프트

직접 쓰면 내가 떠올린 조건만 프롬프트에 들어갑니다. 만들어 달라고 하면 AI가 빠진 조건을 먼저 질문하고, 답을 맥락 · 요청 · 금지 형식으로 정리합니다. 빠진 조건이 드러나고, 처음 쓰는 글도 형식을 갖추며, prompts/에 저장해 고쳐 쓸 수 있습니다. 한계도 있습니다. AI가 질문해도 결과의 질은 내가 넣은 재료의 질에 달려 있습니다. 예: “백엔드 인턴 이력서 작성 프롬프트를 만들어 줘. 먼저 필요한 정보를 하나씩 질문해.” 이 방식은 실습 1의 준비 2에서 다시 씁니다.

이번 주차에 배우는 네 가지

사라지면 안 되는 지시를 파일로 상주시키고, 답이 매번 다른 이유를 LLM의 동작 원리로 설명합니다. 목표는 매번 다시 말하던 지시를 파일로 상주시키고, “LLM은 어떻게 동작하는가”라는 면접 질문에 답할 수 있게 되는 것입니다. 흐름은 CLAUDE.md 작성 → 경로별 규칙 → 컨텍스트 윈도우와 메모리 → LLM 동작 원리 → 환각입니다.

  1. 규칙 파일 · CLAUDE.md로 상주시킨다. 요약 · 비우기 뒤에는 대화로 정한 지시가 모델에 전달되지 않을 수 있습니다. /init 초안에 없는 규칙을 후보 10개와 견주어 골라 넣고, 새 세션의 /context에서 Memory files로 읽혔는지 확인합니다.
  2. 경로별 규칙 · CLAUDE.md와 .claude/rules/. 어떤 작업에든 적용되면 CLAUDE.md, 특정 경로면 .claude/rules/입니다. rules 파일은 머리말의 paths 경로에 있는 파일을 읽을 때만 읽힙니다. 둘 다 아닌 후보는 보류로 규칙후보.md에 둡니다.
  3. 컨텍스트 윈도우와 메모리 · 얼마나 오래 남는가. 컨텍스트 윈도우는 이번 세션, 자동 메모리는 다음 세션에도, CLAUDE.md는 프로젝트가 계속되는 한 남습니다. 판정 질문 두 개로 항목별 저장 위치를 정하고, 항목마다 셋 중 어디에 둘지 구분 표를 채웁니다.
  4. LLM 동작 원리 · 확률을 계산하는 기계. 다음 토큰의 확률을 계산해 고르기를 반복해 답을 만듭니다. 토큰 수를 실측하고, 환각이 생기는 이유와 대책을 봅니다. 공개 모델을 필요 메모리와 장비 가격으로 가늠합니다.

LLM 동작 원리는 네 단계 중 어느 한 칸이 아니라 네 단계 모두의 공통 기반입니다. 어느 단계에서 무엇을 하든 답을 실제로 만들어 내는 것은 모델이고, 그 만드는 방식을 알아야 지시문을 명확하게 써야 했던 이유, 컨텍스트 윈도우에 한계가 있는 이유, 답을 검증해야 하는 이유가 설명됩니다. 한 문장으로 줄이면, 규칙을 파일로 상주시키고 답이 흔들리는 이유를 동작 원리로 설명하는 주차입니다.

1. CLAUDE.md 작성법

CLAUDE.md는 프로젝트 규칙을 적어 두면 Claude Code가 세션을 열 때마다 자동으로 읽는 파일입니다. 규칙 파일에 있는 내용은 대화 요약의 대상이 아니라 매번 새로 읽히는 원본이므로, 사라지면 안 되는 규칙은 이 파일에 기록합니다.

1-1. CLAUDE.md는 세션마다 전체가 로드되는 마크다운 파일

세션을 시작할 때 파일 전체가 컨텍스트에 로드됩니다. 형식은 네 가지만 알면 됩니다.

  • 제목과 목록. # 제목으로 절을 나누고 - 목록으로 지시를 적습니다. 절 구성은 다음 절에서 다룹니다.
  • @경로 가져오기. @명세서.md처럼 적으면 해당 파일이 함께 로드됩니다. 최대 4단계까지 중첩되고, 백틱 안의 @는 문자로 남습니다.
  • HTML 주석. 블록 단위 <!-- --> 주석은 Claude Code가 로드 전에 자동으로 제거합니다. 토큰을 쓰지 않는 관리자용 메모입니다.
  • 구체적으로 쓰기. “코드를 깔끔하게”가 아니라 “2칸 들여쓰기 사용”처럼 지켰는지 확인할 수 있게 씁니다.

명령 무엇을 보여 주나 언제 쓰나
/context 컨텍스트 창을 무엇이 얼마나 차지하는지 CLAUDE.md가 읽혔는지 볼 때 · 대화가 길어져 응답이 흐려질 때

/usage 이번 세션의 요금 · 토큰 · 코드 변경 줄 수 비용이 걱정될 때 (/cost도 같은 창)
/compact 앞 대화를 요약해 공간을 비움 같은 작업을 이어 가는데 창이 찼을 때

3. 경로별 규칙: 항상 적용인가, 특정 파일에서만인가

실습 1에서 CLAUDE.md에 넣은 「tests/test_page.py는 수정하지 않는다」는 테스트 파일을 다룰 때만 필요한데, CLAUDE.md에 있으면 매 세션 읽힙니다. 이런 규칙을 둘 곳을 따로 정합니다.

위치 읽히는 시점 적합한 규칙 비용 예
CLAUDE.md 매 세션 시작 시 항상 읽힘 어떤 작업에든 항상 적용할 규칙 항상 지불. 무관한 작업에서도 매 세션 토큰 비용을 냅니다. 그래서 짧게 유지합니다 「커밋 메시지는 한국어로 쓴다」
.claude/rules/ 폴더 지정한 경로의 파일을 읽을 때만 특정 폴더나 파일에만 해당하는 규칙 해당할 때만 지불. 테스트와 무관한 작업에서는 토큰을 내지 않습니다 「tests/ 아래에서는 기존 검사 항목을 지우지 않는다」

규칙 파일 머리에 적용 경로(paths)를 적으면, Claude가 그 경로의 파일을 읽을 때 규칙도 함께 읽힙니다. paths가 없으면 CLAUDE.md처럼 매 세션 읽힙니다.

어디에 둘지는 “이 규칙은 어떤 작업에든 적용되는가?”라는 질문에 “그렇다”면 CLAUDE.md, “아니다”면 rules입니다. 내 포트폴리오라면 「문서와 주석은 한국어로 쓴다」는 CLAUDE.md, 「index.html의 섹션 id를 바꾸지 않는다」는 rules(paths: index.html)입니다. 실습 2에서는 골격의 규칙후보.md로 이 분류를 해 봅니다.

언제 규칙을 추가할지의 실무 기준도 있습니다. 처음부터 모든 규칙을 예측해 적으려 하지 않고, 같은 실수를 두 번 이상 보면 그때 규칙으로 적습니다. 반복이 확인된 것만 올리는 방식이 유지 비용이 가장 낮습니다. 옮기지 못한 후보가 남아도 규칙후보.md는 지우지 않고 그대로 둡니다.

5-1. CLAUDE.md는 권고, 강제는 장치로

파일 위치는 프로젝트 폴더 기준으로 다음과 같습니다.

   CLAUDE.md
     → 매 세션 읽힘 · 권고
   .claude/rules/app-규칙.md
     → paths의 파일을 읽을 때 읽힘 · 권고
   .claude/skills/release-check/SKILL.md

5-2. 예시 1 · 강제 설정: permissions와 hook은 settings.json에 적는다

수업에서는 실행하지 않고 모양만 봅니다.

// .claude/settings.json
{
 "permissions": {
  "deny": [
   "Read(./.env)",
   "Edit(./tests/test_page.py)"
  ]
 },
 "hooks": {
  "PreToolUse": [{
   "matcher": "Edit|Write",
   "hooks": [{
    "type": "command",
    "command":
     "$CLAUDE_PROJECT_DIR/.claude/hooks/protect.sh"
   }]
  }]
 }
}
#!/bin/bash
# .claude/hooks/protect.sh · hook 스크립트
# matcher(Edit|Write) 호출 직전에 실행된다
# 호출 정보가 JSON으로 stdin에 들어온다
FILE=$(jq -r '.tool_input.file_path')
case "$FILE" in
  */tests/test_page.py|*/.env)
    echo "고정 파일 수정 금지: $FILE" >&2
    exit 2 ;;
esac
exit 0
# exit 2 → 호출을 막고, stderr를 Claude에게 전달
# exit 0 → 통과
# exit 1 → 오류로만 기록, 막지 않음
# 준비: chmod +x protect.sh, jq 설치

permissions는 도구 이름과 경로 목록으로 거절합니다. 설정 한 줄로 끝나서 조건이 단순할 때 씁니다. hook은 스크립트가 조건을 판정합니다. 목록으로 못 적는 조건도 막을 수 있고, 막을 때는 반드시 exit 2입니다. 출처: code.claude.com/docs/en/permissions · code.claude.com/docs/en/hooks.

3. git diff로 tests/가 바뀌지 않았는지 본다
4. 결과를 항목별 표로 보고한다

skill은 여러 단계의 절차를 담습니다. 평소에는 name · description만 읽히고, 부르거나 요청이 description과 맞으면 본문까지 읽힙니다. 그래서 평소에는 이름과 설명만큼의 컨텍스트를 씁니다. 폴더 이름 = name = 명령 이름입니다.

<!-- .claude/rules/app-규칙.md -->
---
paths:
  - "app/**/*.py"
---
# app 규칙
- 함수 이름은 동사로 시작한다
- 오류는 ValueError · KeyError만 쓴다

rules는 특정 경로에만 필요한 규칙을 담습니다. paths 패턴에서 **는 하위 폴더 전체, *는 한 폴더 안의 이름이고, 따옴표로 감싸고 경로마다 - 한 줄을 씁니다. 이 파일은 app/ 파일을 읽을 때만 불려 오고, 머리말이 없으면 CLAUDE.md와 같이 매 세션 읽힙니다. 실습 2의 tests-규칙.md도 이 모양입니다. skill과 rules는 모두 권고라서, 지켜졌는지는 결과로 확인합니다. 출처: code.claude.com/docs/en/skills · code.claude.com/docs/en/memory.

7. AI 시대의 개발자

여기부터는 도구의 원리를 다룹니다. 그 전에 왜 원리를 알아야 하는지 배경을 봅니다.

7-1. 프로그래밍의 역사는 추상화의 역사

추상화는 아래 단계의 세부 동작을 감추고, 더 높은 수준의 표현으로 지시하게 하는 것입니다. 단계가 올라갈 때마다 개발자는 실제 문제에 가까워졌고, 거센 반론이 있었습니다.

AI 쪽 사람의 일은 세 가지입니다. 기획은 ① 정확한 지시와 ② 정확한 위임(무엇을 맡기고 무엇을 직접 할지)이고, 검토는 ③ 사람의 판단(결과를 매번 확인한다)입니다. 실습 2에서 AI 분류 10개 중 6개를 다시 판정한 것이 ③입니다. 지금까지 배운 지시문 설계, 테스트 검증, 규칙 파일이 전부 이 세 가지를 위한 도구였습니다. 그 상대인 LLM이 어떤 기계인지가 다음 장의 내용입니다.

8. LLM 동작 원리

8-1. LLM: 다음 토큰의 확률을 계산하는 기계

LLM(Large Language Model, 거대언어모델)이 하는 일은 지금까지의 텍스트가 주어졌을 때 다음에 올 조각의 확률을 계산하는 것입니다. 조각의 단위가 토큰(token)이고, 이 계산을 하는 프로그램 덩어리를 모델(model)이라고 부릅니다. 지금까지 AI라고 불러 온 것의 내부 구조의 이름입니다. 후보 중 하나를 골라 출력하고, 그 결과까지 포함한 전체를 다시 읽어 그다음 조각을 계산합니다. 이 반복이 문장을 만듭니다.

   입력: 대한민국의 수도는
   다음 토큰 후보와 확률 (개념)
     서울   ████████░  매우 높음
     부산   █░░░░░░░░  낮음
     어디   █░░░░░░░░  낮음
   하나를 골라 출력 → 전체를 다시 읽고 반복
graph LR
    T["입력 텍스트"] --> TK["토큰 분해"] --> M["모델<br/>다음 토큰의<br/>확률 계산"] --> S["후보 중 하나 선택<br/>(샘플링)"] --> O["출력 토큰"]
    O -->|"출력을 입력에 붙여 반복"| M

“서울”은 찾아본 결과가 아니라 확률 계산의 결과입니다. 이 구조에서 알 수 있는 것이 두 가지입니다. ① 뜻을 이해해서가 아니라 확률을 계산해서 답한다. ② 고르는 선택 단계가 있으므로 같은 입력에서도 다른 출력이 나온다. 테스트로 검증해야 했던 비결정성의 원리적 근거가 이것입니다. 요약하면 토큰 분해 → 확률 계산 → 선택(샘플링) → 출력을 입력에 붙여 반복입니다.

8-2. 사례: 계산과 글자 세기가 서툰 이유

글자 세기. “strawberry에 r이 몇 개인가”라는 질문에 당시 최고 성능 모델이던 GPT-4o와 Claude까지 r을 2개라고 답해 유명해진 사례입니다(AI에게 물었더니…’Strawberry’에 ’r’이 2개?, 애플경제). 정답은 3개입니다. 원인은 구조에 있습니다. 모델은 글자가 아니라 토큰을 봅니다. strawberry는 “str” · “aw” · “berry”처럼 몇 개의 토큰(GPT-4o 기준), 곧 사전 번호 몇 개로 들어가고, 그 번호 안에 글자 정보가 없습니다. 사람 눈에는 s · t · r · a · w · b · e · r · r · y 열 글자가 보이지만, 모델 입력에는 번호 몇 개만 있습니다. 셀 대상이 없으니 패턴으로 개수를 추측합니다.

여러 자리 곱셈. 자주 틀립니다. 계산기라면 있을 수 없는 일입니다. 구구단을 외운 사람이 계산 절차 없이 외운 패턴으로 답을 말하는 것과 비슷합니다. 모델은 계산 절차를 실행하는 것이 아니라 숫자 텍스트의 패턴으로 예측하므로, 학습하지 않은 조합에서 그럴듯한 오답이 생성됩니다.

최근 모델은 맞히기도 한다. 구조가 바뀌어서가 아니라, 유명해진 질문과 답이 학습 데이터에 포함된 결과에 가깝습니다. 이렇게 평가 문제의 답이 학습 자료에 섞여 드는 것을 데이터 오염(data contamination)이라고 부릅니다. 기출 문제의 답을 외워 맞힌 셈입니다.

그래서 실무에서는 계산을 계산기 · 코드 실행 같은 도구에 맡깁니다.

9. 실습 3: 토큰 이해와 실측

같은 뜻도 토큰 수가 다르고, 모델은 글자를 보지 않는다는 것을 숫자로 확인합니다. 측정 스크립트 스크립트/token_count.py는 0장에서 받은 week05에 있습니다. 프롬프트 수업의 채점기와 같은 방식으로 파이썬 표준 라이브러리만 써서 API의 토큰 계산 기능(count_tokens)에 문장을 보내고 토큰 수를 받아 오므로, 설치할 패키지가 없습니다. 인증은 0장에서 확인한 ANTHROPIC_API_KEY입니다. 실행 위치는 ~/week05입니다.

서버 터미널 
   cd ~/week05
   python3 스크립트/token_count.py "a"
   python3 스크립트/token_count.py "안녕하세요, 만나서 반갑습니다."
   python3 스크립트/token_count.py "Hello, nice to meet you."
   python3 스크립트/token_count.py "strawberry"
   [교수 화면 실측 결과 · 문장: 줄은 생략]
   토큰 수: 8   ← 고정 7 + "a" 1
   토큰 수: 27  → 문장 20
   토큰 수: 14  → 문장 7
   토큰 수: 9   → 단어 2

숫자 읽는 법: 측정값 = 고정 7토큰 + 문장 토큰. 비교할 때는 고정분을 빼고 봅니다. 네 숫자는 내소재.md 5)에 적습니다. 측정 결과는 파일로 남지 않으므로 이 숫자가 기록입니다.

  1. 같은 뜻, 약 3배의 토큰. 측정값마다 요청 형식의 고정 7토큰이 붙습니다(“a” 한 글자가 8). 이를 빼면 한국어 인사는 20토큰, 영어는 7토큰입니다. 같은 내용이라도 요금과 컨텍스트 사용량이 약 3배입니다.
  2. strawberry는 10글자, 2토큰. 측정값 9에서 고정 7을 빼면 2토큰입니다. 10글자가 두 조각으로 들어갑니다. 어디서 자르는지는 공개되지 않아 API는 개수만 알려 줍니다.
  3. 그래서 r의 개수는 추측이 된다. 모델 입력은 s · t · r · a · w · b · e · r · r · y가 아니라 조각 번호 몇 개입니다. 번호 안에는 글자 정보가 없어, r의 개수는 학습한 패턴으로 추측합니다. 2개라고 답할 수 있고, 맞혀도 질문을 학습해서입니다(8-2).
   모델에 들어가는 모양 · 개념도
     사람이 보는 것:  s t r a w b e r r y   (10글자)
     모델이 받는 것:  [고정 7토큰] [조각] [조각]
     질문: strawberry에 r은 몇 개?
     → "2개"(오답) 또는 "3개"(정답)
     → 확실한 답은 코드로: 'strawberry'.count('r')

요금 · 컨텍스트 한도 · 글자 세기 오류가 모두 토큰 단위에서 나옵니다.

막히면 python3 스크립트/token_count.py --check로 모델 이름과 키 설정 여부를 봅니다(API_KEY_SET=True). KEY_NOT_SET이 나오면 「접속 · 설치」 장의 키 등록을 먼저 합니다. HTTP 429는 요청이 몰린 것이므로 잠시 뒤 다시 실행하고, 네트워크 오류가 반복되면 손을 듭니다. 통신이 막혀 실측이 안 되면 위 교수 화면 숫자를 「참고」로 표시해 적습니다. 숫자는 모델에 따라 조금 다를 수 있습니다.

10. 컨텍스트 윈도우가 유한한 이유

모델은 다음 토큰을 계산할 때마다 입력 전체의 토큰 사이 관계를 계산합니다. 토큰 수가 2배면 계산량은 약 4배이므로, 한 번에 처리할 토큰 수에 상한을 둡니다. 이 상한이 컨텍스트 윈도우입니다. 앞서 /context로 본 것이 이 한도 안의 사용량입니다.

한도의 크기와 구성. 수업 모델은 20만 토큰 안팎으로, 장편 소설 한 권 분량입니다. 100만 토큰급 모델도 여럿 있습니다(Opus 5, GPT-5.5, Gemini 3.1 Pro). 한도 안에는 시스템 프롬프트 · CLAUDE.md · rules · 대화 기록 · 읽은 파일 · 도구 결과 · 모델의 답변이 합산됩니다.

창이 커져도 남는 제약. 한도를 넘은 입력은 처리되지 않습니다. 넘는 부분은 잘리거나 요약되어, 모델이 원문을 참조할 수 없습니다. 입력이 길수록 비용과 오류가 늘어납니다. 토큰 단위로 과금되고, 긴 입력의 중간 내용을 놓치는 정확도 저하가 측정되어 있습니다.

회사에서 생기는 문제. 긴 계약서 · 로그 · 저장소를 통째로 넣으면 한도를 넘거나 요금이 커집니다. 긴 대화에서는 앞의 지시가 요약되며 빠져, 규칙을 어기는 결과가 나옵니다. 그래서 필요한 부분만 검색해 넣는 구조를 씁니다.

이번 주 실습에서 쓴 대응. /context로 한도 안의 사용량을 확인했습니다(실습 1). /compact로 대화를 요약해 공간을 비우고, 규칙은 CLAUDE.md에서 다시 읽혔습니다(실습 1). paths로 필요한 경로에서만 규칙을 읽어 토큰을 아꼈습니다(실습 2).

컨텍스트가 커질수록 토큰이 녹는다. 우리 수업의 실측입니다. 한 달 수업 4회, 가장 싼 Haiku 4.5만 썼는데 API 비용이 부가세 포함 약 $110(화면은 세전 $99.23), 학생 한 명이 $43이었습니다. 한 학기(약 4개월)면 약 $440입니다. 그래서 공개 모델을 직접 돌리고 싶어집니다. 맥미니를 AI 에이전트를 상시 돌리는 장비로 쓰는 수요가 늘어 값이 올랐다는 기사도 나왔습니다(「맥 미니가 ‘AI 에이전트 호스트’로… 클로드 수요에 애플 인상·품귀 사태」, AI매터스 2026-05-12, https://aimatters.co.kr/news-report/41929/ · 「’AI 에이전트용’ 애플 맥미니 200달러 올라」, https://chosundaily.com/bbs/board.php?bo_table=hotclick&wr_id=32922&page=38&device=pc).

11-2. “우리 장비에서 돌아가는가, 얼마가 드는가”

수업 API 비용(월 약 15만 원)을 보면 공개 모델을 직접 돌리고 싶어집니다. 회사에서 공개 모델을 쓰기로 해도 첫 질문은 같습니다. 필요한 메모리, 장비 가격, API와 비교한 경제성으로 답합니다.

  • 파라미터 수. 이름 뒤의 8B, 70B입니다. 파라미터(parameter)는 모델이 학습으로 얻은 수치 값이고, B는 10억 개입니다. 숫자가 클수록 성능이 높지만 메모리를 더 차지합니다. 이 수들을 전부 메모리에 올려야 모델이 돌아갑니다.
  • 필요 메모리. 압축판(Q4) 기준 대략 파라미터 수(B) × 0.5GB + 실행 여유분이 필요합니다. 8B급 약 6GB · 27~32B급 16~24GB · 70B급 약 40GB. Q4는 원래 16비트(2바이트)로 저장하던 수를 4비트(0.5바이트)로 줄이는 양자화(quantization)입니다. 정밀도를 조금 잃는 대신 메모리가 4분의 1로 줄어, 작은 장비에서도 실행할 수 있게 됩니다. 실행 여유분은 대화가 길어질수록 토큰마다 계산해 둔 중간값을 담는 공간과 실행 프로그램이 차지하는 자리입니다.
  • 장비 가격. 맥미니 M6 16GB 약 150만 원(8B급) · 32GB 약 218만 원(27~32B급). 70B급은 64GB 이상이 필요해 맥 스튜디오 약 600만 원부터입니다.

맥미니가 경제적인가. 맥미니 32GB(약 218만 원)는 Haiku API 약 9억 토큰어치입니다. 2년 안에 본전을 뽑으려면 API를 월 약 9만 원(약 3,700만 토큰) 이상 꾸준히 써야 합니다. 우리 수업 전체(월 약 15만 원)면 약 15개월, 학생 한 명(월 약 6만 원)이면 약 3년이 걸립니다. Pro 구독(월 2.7만 원)으로 치면 약 7년치입니다. 로컬 32B급은 Claude보다 성능이 낮고 느립니다.

회사용 참고: 70B급을 클라우드 GPU(H100 80GB 1장)로 24시간 돌리면 시간당 약 3,400원, 월 약 245만 원입니다. 수업 API 비용(월 약 15만 원)의 16배입니다. 면접에서 “모델을 고를 때 무엇을 보는가”라는 질문이 나오면 파라미터 수, 양자화, 필요 메모리, 그리고 이 경제성 계산을 포함해 답하면 좋습니다.

12. 샘플링과 temperature: 일정한 답이 맞는 답은 아니다

8-1에서 본 선택 단계(샘플링)는 조절이 가능합니다. 대표 설정이 temperature(온도), 0부터 1까지의 값입니다. 값이 낮으면 확률이 가장 높은 후보를 거의 항상 고르고, 높으면 낮은 후보도 뽑힙니다. 창작에는 높은 값, 정답이 정해진 업무(코딩, 분류)에는 낮은 값을 씁니다.

temperature는 채팅 화면이나 Claude Code가 아니라 API 요청에서 지정하는 값입니다. 그래서 실습 결과가 사람마다 달랐습니다. 여기서는 코드와 결과만 확인하고, 다음 주제(API 연동)에서 직접 실행합니다.

   import anthropic

   client = anthropic.Anthropic()   # API 키는 환경 변수에서 읽는다

   client.messages.create(model=…, max_tokens=…,
     temperature=0.0, messages=…)  # 선택 단계 조절: 0.0(일정)부터 1.0(다양)까지

코드 첫 줄의 import anthropic은 라이브러리를 불러오는 문장입니다. 라이브러리(library)는 다른 개발자가 만들어 배포한 기능 묶음입니다. 서버와의 통신 세부를 라이브러리가 대신하므로 우리 코드는 모델 이름과 질문만 적으면 됩니다. 불러온 기능은 anthropic.Anthropic()처럼 라이브러리 이름 뒤에 점을 찍어 씁니다.

같은 요청을 temperature 값만 바꿔 세 번씩 보내면 결과의 형태가 다음처럼 달라집니다.

   temperature=0.0  세 번 모두 거의 같은 답
   temperature=1.0  매번 다른 답
   # 확률 1위 후보가 오답이면
   temperature=0.0  같은 오답을 매번 반복
   temperature=1.0  답이 흔들리고 오답이 섞임

temperature는 답이 얼마나 일정한지를 정할 뿐, 사실 여부는 확인하지 않습니다. 0이어도 환각은 남습니다. 다음 장의 사례에서 확인합니다. 확인의 기준은 “같은 답이 나오는가”가 아니라 “기준(테스트)을 통과하는가”입니다.

13. 환각

13-1. 과거의 환각과 현재

초기 대화형 AI에 「조선왕조실록에 기록된 세종대왕의 맥북프로 던짐 사건에 대해 알려줘」라고 물으면, 없는 사건을 실록의 일화처럼 유창하게 설명했습니다. 같은 질문에 이후 모델(GPT-4)은 세종대왕은 15세기 조선의 왕이고 맥북 프로는 21세기의 노트북이라 문맥이 맞지 않는다고 답했습니다.

  • 왜 이젠 맞히나. ① 모르면 모른다고 답하는 훈련 ② 웹 검색으로 근거 확인 ③ 이 사건이 밈으로 퍼져 학습 데이터에 들어감.
  • 그래도 남는다. 유명한 사례는 외워서 맞히지만, 덜 알려진 질문에는 지금도 그럴듯한 오답이 나옵니다.

13-2. 왜 그럴듯한 오답이 나오는가

유창한 오답의 이름이 환각(hallucination)입니다. Claude가 없는 대상에 대한 질문을 거절했다면, 환각이 없어서가 아니라 “모르면 모른다고 답하라”는 별도 훈련이 작동한 것이고, 이 장치도 완전하지 않습니다.

구조의 원인. 모델은 “모른다”가 아니라 “다음에 올 법한 토큰”을 계산합니다. 본 적 없는 대상에도 그럴듯한 나열은 언제나 존재합니다. 성능 부족이 아니라 구조상 피할 수 없는 결과입니다.

훈련의 원인. 시험에서 모르는 문제를 빈칸으로 두면 0점이지만, 찍으면 맞을 가능성이 남습니다. AI의 훈련도 비슷해서, “모르겠다”보다 그럴듯한 추측이 좋은 점수를 받아 왔습니다. OpenAI가 논문으로 정리한 설명입니다(Why Language Models Hallucinate).

아부(sycophancy). 질문자가 만족한 답에 보상을 받아 와서, 틀렸다고 우기면 입장을 바꿉니다. 미국 텍사스A&M대와 신시내티대 연구진이 2026년 9월 8일 공개한 결과, 명백하게 틀린 주장을 최대 25차례 반복하자 일부 최신 모델은 100개 문제 중 97개에서 한 번 이상 사용자의 잘못된 주장에 동조했고, 감정적 호소로 입장을 바꾼 비율은 44.3%였습니다(AI에 ‘네가 틀렸어’ 25번 우기자, 97%가 “당신 말이 맞아요”, 조선일보 2026-09-16). 동의는 사실 확인이 아닙니다. 근거를 확인합니다. TDD에서 본 「무리하게 시키면 AI가 테스트를 고친다」와 같은 성질이며, 답도 같습니다. 판정은 사람의 말이 아니라 사람이 미리 써 둔 기준이 합니다.

정렬 위장(Alignment Faking). 지금까지의 환각은 모델이 몰라서 틀리는 오류입니다. 성격이 다른 유형도 있습니다. Anthropic과 Redwood Research의 실험(2024)에서 훈련 조건에 대한 정보를 받은 모델은, 지금이 「훈련(테스트) 상황」이라고 판단하면 겉으로는 새로운 훈련 목표에 따르는 척하면서 속으로는 원래의 성향을 숨기고 지키는 행동을 보였습니다. 이 수업의 검증 장치가 겨냥하는 것은 첫째 유형(환각)이지만, 둘째 유형의 존재는 “AI의 답을 그대로 믿지 않는다”는 이 과목의 규칙이 왜 원칙이어야 하는지를 다시 보여 줍니다.

결론. 환각은 원리적으로 없앨 수 없으므로, 개발자의 일은 환각이 있다는 전제로 설계하는 것입니다. ① 근거 문서를 붙이고 ② 출력을 검증하는 장치를 둡니다. 포트폴리오 실습에서는 ① CLAUDE.md의 「연락처는 프로필.md에 있는 것만」 규칙이 근거 문서이고, ② 지어낸 연락처를 잡는 test_page.py가 검증 장치입니다.

한 세션 안에서는 규칙을 말로 해도 파일에 써도 결과가 같습니다. 차이는 세션이 바뀔 때 드러납니다. 세션이 누적되면 차이가 커집니다. 한 학기 동안 세션 수십 개, 요약 수십 번, 같은 폴더를 여러 사람이 여는 회사 프로젝트에서는 “지난번에 말했는데”가 통하지 않습니다. 말로만 한 규칙은 요약에서 빠지면 이후 세션에 전달되지 않고, 새 사람은 무엇을 지켜야 하는지 대화 기록을 찾아봐야 합니다. 파일에 둔 규칙은 세션을 열 때마다 새로 읽히고, 위반하면 즉시 확인되며, 반복이 확인된 것만 올려 짧게 유지됩니다.
