생각: (다음에 무엇을 할지 한 문장)
행동: (vat_calc 또는 discount_calc 또는 finish 중 하나)
입력: (행동에 넘길 값. vat_calc는 공급가액 숫자, discount_calc는 "원가,할인율" 형식, finish는 사용자에게 줄 최종 답)

# ---------- 도구 (도구 사용 실습의 원칙 그대로: 인자 검증, 오류는 문자열로) ----------

def vat_calc(raw):
    try:
        amount = float(str(raw).replace(",", "").replace("원", "").strip())
    except (TypeError, ValueError):
        return "오류: 숫자가 필요합니다"
    if amount < 0:
        return "오류: 금액은 0 이상이어야 합니다"
    vat = round(amount * 0.1)
    return f"공급가액 {amount:,.0f}원, 부가세 {vat:,}원, 합계 {amount + vat:,.0f}원"


def discount_calc(raw):
    try:
        price_s, rate_s = str(raw).split(",")
        price, rate = float(price_s), float(rate_s)
    except (TypeError, ValueError):
        return "오류: '원가,할인율' 형식이 필요합니다 (예: 50000,20)"
    if not (0 <= rate <= 100):
        return "오류: 할인율은 0~100 사이여야 합니다"
    sale = round(price * (1 - rate / 100))
    return f"원가 {price:,.0f}원, {rate:g}% 할인 적용가 {sale:,}원"


TOOLS = {"vat_calc": vat_calc, "discount_calc": discount_calc}

            model=self.model, max_tokens=400, system=system,
            messages=[{"role": "user", "content": prompt}],
        )
        return "".join(b.text for b in r.content if b.type == "text")

"""같은 에이전트의 Claude Agent SDK 재구현판 (week10 실습용, 완성되어 있음).

react_agent.py에서 직접 만들던 것(서식 프롬프트, 파싱, 루프, 재주입, 단계 상한)을
SDK가 대신합니다. 우리가 쓰는 코드는 도구 정의와 질문뿐입니다.
Claude Code를 움직이는 것과 같은 인프라입니다.

사용법:
    python sdk_agent.py "100만원 노트북, 부가세 포함가에서 20% 할인하면?"

전제: pip install claude-agent-sdk (ASO Lab에는 설치되어 있음),
      Claude Code 설치 환경, 환경변수 ANTHROPIC_API_KEY, COURSE_MODEL
"""
import asyncio
import os
import sys

from claude_agent_sdk import (
    ClaudeAgentOptions,
    create_sdk_mcp_server,
    query,
    tool,
)


# ---------- 도구: react_agent.py와 같은 계산, 같은 검증 원칙 ----------

@tool("vat_calc", "공급가액(원)을 받아 부가세 10%와 합계 금액을 계산한다.", {"amount": float})
async def vat_calc(args):
    try:
        amount = float(args.get("amount"))
    except (TypeError, ValueError):
        return {"content": [{"type": "text", "text": "오류: amount는 숫자여야 합니다"}]}
    if amount < 0:
        return {"content": [{"type": "text", "text": "오류: 금액은 0 이상이어야 합니다"}]}
    vat = round(amount * 0.1)
    text = f"공급가액 {amount:,.0f}원, 부가세 {vat:,}원, 합계 {amount + vat:,.0f}원"
    return {"content": [{"type": "text", "text": text}]}


@tool("discount_calc", "원가(원)와 할인율(%)을 받아 할인 적용가를 계산한다.", {"price": float, "rate": float})
async def discount_calc(args):
    try:
        price, rate = float(args.get("price")), float(args.get("rate"))
    except (TypeError, ValueError):
        return {"content": [{"type": "text", "text": "오류: price와 rate는 숫자여야 합니다"}]}
    if not (0 <= rate <= 100):
        return {"content": [{"type": "text", "text": "오류: 할인율은 0~100 사이여야 합니다"}]}
    sale = round(price * (1 - rate / 100))
    text = f"원가 {price:,.0f}원, {rate:g}% 할인 적용가 {sale:,}원"
    return {"content": [{"type": "text", "text": text}]}


async def main(question):
    calc = create_sdk_mcp_server(name="calc", tools=[vat_calc, discount_calc])
    options = ClaudeAgentOptions(
        model=os.environ.get("COURSE_MODEL", "claude-haiku-4-5"),
        mcp_servers={"calc": calc},
        allowed_tools=["mcp__calc__vat_calc", "mcp__calc__discount_calc"],
        system_prompt="너는 계산 상담원이다. 계산은 직접 하지 말고 반드시 도구로 한다. 한국어로 답한다.",
        max_turns=6,  # react_agent.py의 MAX_STEPS에 해당하는 안전장치
    )
    async for message in query(prompt=question, options=options):
        # 메시지 종류를 그대로 출력해 SDK 루프의 진행(도구 호출·결과·최종 답)을 관찰한다
        print(f"[{type(message).__name__}] {message}")


if __name__ == "__main__":
    if len(sys.argv) != 2:
        print(__doc__)
        sys.exit(1)
    asyncio.run(main(sys.argv[1]))

# Requirement Spec

프로젝트의 요구사항 명세입니다. 요구사항 문장은 EARS(Easy Approach to Requirements Syntax, 정형 요구사항 문형) 형식으로 씁니다. 리버스 엔지니어링에서 연습한 문형의 재사용입니다.

## EARS 문형 참조

| 패턴 | 문형 | 예 |
|---|---|---|
| 상시 | 시스템은 (행위)해야 한다 | 시스템은 모든 응답에 근거 번호를 표시해야 한다 |
| 이벤트 | (사건)이 발생하면, 시스템은 (행위)해야 한다 | 검색 유사도가 문턱 미만이면, 시스템은 답변을 거절해야 한다 |
| 상태 | (상태)인 동안, 시스템은 (행위)해야 한다 | 세션이 유지되는 동안, 시스템은 대화 이력을 보존해야 한다 |
| 선택 기능 | (조건)인 경우, 시스템은 (행위)해야 한다 | 관리자 모드인 경우, 시스템은 사용 로그를 표시해야 한다 |

# PRD: Lucky Draw 2단계 추첨 사이트

> **작업 범위**: 단일 HTML 파일(`lucky-draw.html`)에 HTML + CSS + JavaScript를 모두 포함한 정적 럭키 드로우 사이트를 구현합니다.

## 1. 제품 개요

### 1.1 한 줄 정의
인원 번호를 **랜덤으로 즉시 추첨**해 당첨자를 정한 뒤, **경품 원판을 돌려** 그 사람이 받을 상품을 정하는 **2단계 럭키 드로우** 단일 페이지.

### 1.2 배경
오프라인 행사·온라인 세미나·팀 회식에서 즉석으로 경품을 추첨할 때, 종이 제비뽑기·엑셀 random·외부 추첨 사이트는 신뢰성·재미·접근성이 부족하다. 회전 원판은 **돌아가는 과정 자체가 콘텐츠**이고, 멈추는 위치를 눈으로 따라가며 검증할 수 있어 신뢰감을 준다. 여기에 **"누가 받을지(번호) → 무엇을 받을지(경품)"** 2단계를 더해 행사 진행의 긴장감을 만든다.

### 1.3 목표
- 첫 방문자가 **30초 안에** 인원·경품을 입력하고 첫 추첨을 완료한다.
- 한 화면에서 **입력 → 번호 추첨 → 경품 원판 → 결과 → 다음 추첨**이 끊김 없이 돈다.
- 결과가 **눈으로 검증 가능**(원판이 멈춘 칸 = 당첨 경품)하여 신뢰감을 준다.

## 3. 핵심 사용 시나리오 (2단계 플로우)

### 시나리오 A: 즉석 추첨 (가장 빈번)
1. 진행자가 URL을 열거나 HTML 파일을 더블클릭한다.
2. **인원수**(예: 10)를 입력한다 → 추첨 대상 번호는 1~10이 된다.
3. **경품**을 등록한다(예: 키보드 2, 마우스 3, 스타벅스 만원·3만원·5만원 각 1) → 원판에 경품 슬라이스 + **꽝 1칸**이 만들어진다.
4. 중앙의 **SPIN** 버튼을 누른다.
   - 먼저 **당첨 번호**가 0.8초 만에 랜덤으로 공개된다(예: "당첨 번호 3번").
   - 이어서 **경품 원판**이 5~6초간 회전 후 멈춘다.
5. 멈춘 칸의 경품(또는 꽝)이 결과 패널·모달·기록에 동시에 표시된다.
6. 진행자가 3번 참가자에게 경품을 전달한 뒤, 다시 SPIN을 눌러 **다음 번호**를 추첨한다.

### 시나리오 B: 빠른 체험 (첫 방문)
1. 처음 방문한 사용자가 **예시** 버튼을 눌러 인원 10·경품 4종을 즉시 채운다.
2. SPIN을 눌러 번호 추첨 → 원판 회전 동작을 확인한다.

### 시나리오 C: 다회 연속 추첨 + 재고 재배정
1. 인원 10, 경품을 여러 종 등록하고 SPIN을 연속으로 누른다.
2. **같은 번호는 다시 뽑히지 않는다**(1인 1회). 매 회 당첨된 경품의 갯수가 1씩 차감된다.
3. 갯수가 0이 된 경품의 원판 칸은 **사라지지 않고**, 재고가 남은 다른 경품으로 **재배정**된다(원판 칸 수는 항상 일정).
4. 모든 경품이 소진되면 남은 칸은 **꽝**으로 채워지고, 남은 인원은 꽝으로 추첨된다.
5. 모든 번호(N명)를 다 뽑으면 SPIN이 비활성화된다.

## 2. 사용자 스토리 + 수용 기준

### F1. 인원수 입력
- [ ] `1~999` 정수만, 999 초과 시 999로 제한.
- [ ] 통계 "남은 인원"이 `인원수 − 뽑은 번호 수`로 실시간 갱신.

### F2~F4. 경품 추가/삭제/병합
- [ ] 상품명이 비어있으면 추가 안 됨 + 상품명 입력란 shake.
- [ ] 갯수가 1 미만/빈값/비정수면 추가 안 됨 + 갯수 입력란 shake.
- [ ] 갯수 999 초과 시 999로 제한. 상품명 1~20자(`maxlength="20"`).
- [ ] 추가 성공 시 입력란 초기화 + 상품명 포커스. 상품명·갯수 input에서 **Enter = 추가**.
- [ ] 같은 이름 재추가 → 리스트 한 줄, 갯수만 증가.
- [ ] × 버튼으로 즉시 삭제(확인 없음), 삭제 후 원판·통계 즉시 갱신.
- [ ] `count`가 0인 경품도 리스트에는 **회색으로 표시**.

### F5. 원판 자동 렌더 (TRD §5.1·§5.2)
- [ ] 경품 0개 → 원판 중앙 "경품을 추가해주세요".
- [ ] 경품 등록 → **경품 갯수 합 + 꽝 1칸**의 고정 섹션이 2색 교차(흑/백)로 렌더, 꽝은 회색.
- [ ] 슬라이스 안 텍스트 라벨(색맹 대응). `S≥12`면 truncate, 각도 10° 미만이면 라벨 생략.

### F6. 번호 추첨 (TRD §5.3)
- [ ] SPIN 시 `1~N` 미추첨 번호 중 균등 랜덤 1개를 ~0.8초 만에 공개("당첨 번호 N번").
- [ ] **같은 번호는 다시 뽑히지 않는다(1인 1회).** 모든 번호 소진 시 더 추첨되지 않음.

### F7. 경품 원판 회전 (TRD §5.4) ⭐
- [ ] 번호 공개 **후** 원판이 5.5초간 회전(최소 6바퀴, ease-out, 관성 느낌).
- [ ] 회전 중 SPIN·입력·추가·삭제·초기화·예시 비활성(중복 방지).
- [ ] **멈춘 슬라이스 = 결과** (12시 포인터 아래). 슬라이스 한가운데서 약간 어긋남(±35% jitter).

### F8. 결과 3중 표시
- [ ] 결과 패널(`#번호 → 상품명`) · 모달(번호 + 상품명, 당첨 시 이모지 1개) · 기록에 **동시 표시**.
- [ ] 모달은 닫기 버튼 · 배경 클릭 · Esc로 닫힘.

### F9. 컨페티 (TRD §5.6)
- [ ] 당첨(경품) 시에만 발사, 꽝은 미발사. 중앙 + 0.2/0.4초 좌·우. 화면 밖 자동 제거. `prefers-reduced-motion`이면 생략.

### F10. 재고 차감 + 재배정 (TRD §5.5)
- [ ] 당첨된 경품 `count` 1 감소. 0이 되면 그 칸을 **재고 최다 경품**으로 재배정, 없으면 꽝.
- [ ] 재배정 후에도 **섹션 수는 변하지 않는다.**

### F11. 당첨 기록
- [ ] 매 추첨 후 `{번호, 상품명, 시간(HH:MM:SS)}` 추가, `#일련번호`, **최신이 위**.

### F12. 통계
- [ ] 남은 경품 = 모든 `count` 합, 추첨 = 뽑은 번호 수, 남은 인원 = `N − 추첨`. 실시간 갱신.

### F13. 전체 초기화
- [ ] `confirm()` 확인 → 경품·기록·번호·인원·회전 모두 리셋. 원판은 **회전 없이 즉시 0도**, 결과 "READY TO SPIN".

### F14. 예시 불러오기
- [ ] 경품이 이미 있으면 확인 다이얼로그. 예시: **스타벅스 쿠폰 1 · 치킨 기프티콘 2 · 편의점 5천원 3 · 문상 1만원 2 + 인원 10**. (꽝은 자동 1칸이므로 경품 항목에 넣지 않는다.)

### 4.2 권장
- **색**: 흑/백 + **단일 액센트(빨강)**. 보조색 없음(회색 명도로 계층). 액센트는 **포인터·SPIN에만**.
- **원판**: 짝/홀 인덱스 검정/백색 2색 교차, **꽝은 중립 회색**. 식별은 슬라이스 라벨 텍스트로.
- **타이포**: 시스템 sans 하나, 굵기 400/700/800.
- **모서리·그림자**: `border-radius:6px`(원형 제외) 한 값, 카드 분리는 1px 테두리(그림자 미사용).
- **애니메이션**: 원판 회전(5.5s)·모달(0.3s fade+scale)·컨페티만. 그 외 장식 애니메이션 금지.
- **이모지**: 모달 당첨 표시 1개만(헤더 0).

### 4.3 레이아웃
- 데스크톱(≥920px): `grid 1fr 360px` (원판 카드 | 사이드).
- 모바일(<920px): 1열(원판 → 사이드). 원판 `aspect-ratio 1/1`로 잘리지 않음.


### 3.2 불변 규칙
- **동일 이름 경품**은 새 항목을 만들지 않고 기존 `count`만 증가(색·id 유지).
- `sections`는 **추첨 세션 동안 길이 고정**. 셋업 단계(`drawnNumbers.size === 0 && !isSpinning`)에서만 `prizes`로부터 재구성하고, 추첨 중에는 **재배정(라벨 교체)만** 한다. 삭제·길이 변경은 금지.
- `count`가 0이 된 경품도 **리스트에는 회색으로 남긴다**(원판에서는 재배정으로 제외).
- `currentRotation`은 항상 누적, 리셋 시에만 0.
- 회전 중에는 `prizes`·`sections`·`participantCount` 변경 금지(입력 잠금).

```javascript
const SPIN_DURATION_MS = 5500;   // 원판 회전 시간(=CSS transition)
const REDUCED_SPIN_MS  = 1000;   // prefers-reduced-motion 시 회전 시간
const NUMBER_REVEAL_MS = 800;    // 번호 공개 시간
```

## 5. 핵심 알고리즘

### 5.1 섹션 구성 (가중치 + 꽝)
경품을 `count`만큼 펼쳐 units를 만들고 **꽝 1칸**을 더한다. 갯수가 많을수록 칸이 많아 자연스러운 가중치가 된다.

```javascript
const units = [];
prizes.forEach(p => { for (let i = 0; i < p.count; i++) units.push(p.id); });
sections = units.length ? units.concat([BLANK]) : [];   // 경품 0개면 빈 휠(자리표시)
// 예: 키보드2+마우스3+스벅3 = units 8 → S = 9 (꽝 포함)
```

### 5.2 SVG 슬라이스 path
0도=오른쪽(+X), 시계방향, 12시=-90도. 슬라이스 i: `[i*anglePer-90, (i+1)*anglePer-90]`.

```javascript
function polar(cx, cy, r, deg) {
  const rad = deg * Math.PI / 180;
  return { x: cx + r * Math.cos(rad), y: cy + r * Math.sin(rad) };
}
function describeSlice(cx, cy, r, s, e) {
  const a = polar(cx, cy, r, s), b = polar(cx, cy, r, e);
  const large = e - s > 180 ? 1 : 0;
  return `M ${cx} ${cy} L ${a.x} ${a.y} A ${r} ${r} 0 ${large} 1 ${b.x} ${b.y} Z`;
}
```

**색·라벨 규칙**:
- 짝수 인덱스 = 검정(`--wheel-a`, 글자 흰색), 홀수 = 백색(`--wheel-b`, 글자 검정).
- **꽝 칸 = 중립 회색 `#D4D4D4`**(글자 검정). 액센트(빨강)는 슬라이스에 쓰지 않는다.
- 라벨 텍스트 = 경품명(또는 "꽝"). `각도 < 10°`(S>36)면 라벨 생략. `S ≥ 12`면 `max(2, floor(anglePer/3))`자로 truncate(`…`). 폰트 크기 `S>18 ? 5 : 6.5`. 라벨 위치 = 반지름 0.62r, 중심각으로 회전하되 90°<각<270°면 +180°(뒤집힘 방지).
- 중심 허브 원 r=10.

### 5.3 번호 추첨 (균등 · 중복 없음)

```javascript
function drawNumber() {
  const pool = [];
  for (let n = 1; n <= participantCount; n++) if (!drawnNumbers.has(n)) pool.push(n);
  if (pool.length === 0) return null;            // 모든 번호 소진
  const picked = pool[Math.floor(Math.random() * pool.length)];
  drawnNumbers.add(picked); currentNumber = picked;
  return picked;
}
```
공개: `NUMBER_REVEAL_MS` 동안 숫자 플리커(setInterval 60ms) 후 확정. `prefers-reduced-motion`이면 즉시 공개. (이 setInterval은 숫자 표시용이며 §5.4의 원판 회전과 무관.)

### 5.4 회전 정지 각도 (가장 중요, 변경 금지)

**불변식 ⭐**: 회전이 멈췄을 때 12시 포인터 아래 슬라이스(`winIdx`) = 결과. 검증 완료(S=2·5·9·18·37, 각 5000회 편차 ≤ 슬라이스 반각).

```javascript
function spin(number) {
  const S = sections.length, anglePer = 360 / S;
  const winIdx = Math.floor(Math.random() * S);
  const sliceCenter = winIdx * anglePer + anglePer / 2 - 90;
  let targetAngle = -90 - sliceCenter;
  targetAngle += (Math.random() - 0.5) * anglePer * 0.7;     // ±35% jitter
  const baseSpins = MIN_SPINS + Math.floor(Math.random() * MAX_EXTRA_SPINS);
  const currentMod = currentRotation % 360;
  const deltaToTarget = ((targetAngle - currentMod) + 720) % 360;
  currentRotation += baseSpins * 360 + deltaToTarget;
  wheelEl.style.transform = `rotate(${currentRotation}deg)`;
  const dur = prefersReducedMotion() ? REDUCED_SPIN_MS : SPIN_DURATION_MS;
  setTimeout(() => onSpinEnd(winIdx, number), dur);
}
```

CSS transition(원판 회전, JS setInterval 금지):
```css
.wheel-svg { transform-origin: 50% 50%;
             transition: transform 5.5s cubic-bezier(0.17, 0.67, 0.12, 0.99); }
@media (prefers-reduced-motion: reduce) { .wheel-svg { transition: transform 1s ease-out !important; } }
```

### 5.5 재고 차감 + 재배정 (섹션 수 불변)
당첨(경품) 시 `count--`. 0이 되면 그 경품의 모든 섹션을 **재고 최다 경품(동률은 등록순)**으로 교체, 재고 있는 경품이 없으면 **꽝**으로. 꽝 당첨은 차감 없음.

```javascript
function reassignDepleted(depletedId) {
  let target = null;
  for (const p of prizes) if (p.count > 0 && (target === null || p.count > target.count)) target = p;
  const fill = target ? target.id : BLANK;
  sections = sections.map(s => (s === depletedId ? fill : s));   // 길이 불변
}
```
> 트레이드오프: 섹션 수 고정으로 **확률이 잔여 재고와 정확히 비례하지 않는다**(소진 시 자기보정). 시각 안정성·단순성 우선의 의도된 선택.

### 5.6 컨페티 (Canvas 2D, 당첨만)
중력 시뮬레이션. 중앙 `PARTICLE_COUNT`개 + 0.2초 후 좌(`w*0.2`)·0.4초 후 우(`w*0.8`) 80개씩, **총 360개 이하**. 매 프레임 `vy+=g; x+=vx; y+=vy; rot+=vr`, 화면 밖 파티클 제거, 모두 사라지면 `requestAnimationFrame` 중단. 팔레트 = **`['#111111','#404040','#737373','#DC2626']`**(흑·회색·빨강, 무지개 금지). `prefers-reduced-motion`이면 생략. 꽝은 발사 안 함.
