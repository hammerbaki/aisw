학사 3주차 · 교재 02 · 2부 데이터 분석 기획 · ADsP 2과목 데이터분석 기획 > 데이터분석 기획의 이해

분석 기획은 분석을 실행하기 전에 무엇을, 왜, 어떤 순서로 할지를 정하는 일이다. 이 장은 ADsP 2과목의 첫 주요 항목인 ’데이터분석 기획의 이해’를 다룬다. 분석 주제의 유형, 분석 방법론의 단계, 분석 과제를 찾는 두 접근, 분석 프로젝트의 관리 영역이 그 내용이다. 2과목은 50문항 가운데 10문항이며, 1과목과 마찬가지로 10문항 가운데 4문항 이상을 맞히지 못하면 과락이다.

2과목의 문항은 계산을 요구하지 않는다. 용어의 짝과 단계의 순서를 묻거나, 사례를 주고 어느 유형과 어느 단계에 해당하는지를 묻는다. 그러므로 이 장은 비교표와 단계표를 중심으로 하고, 절마다 사례를 판별하는 따라 하기를 둔다. 사례는 교재 01의 중심 실습에서 읽은 거래 내역 표를 가진 가상의 온라인 상점(이하 ‘상점’)으로 통일한다. 이 장에는 코드가 없다. 중심 실습에서 쓰는 분석 과제 정의서는 3부(교재 04~12)에서 같은 자료를 실제로 분석할 때 다시 쓴다.

학습 목표

  1. 분석 대상과 분석 방법을 아는지에 따라 분석 주제의 네 유형을 구분하고, 목표 시점에 따른 두 기획 방식을 비교한다.
  2. KDD, CRISP-DM, 빅데이터 분석 방법론의 단계를 순서대로 말하고, 단계마다 하는 일을 짝짓는다.
  3. 사례를 보고 하향식 접근과 상향식 접근 가운데 어느 것인지 판단하고, 하향식 접근의 네 단계를 설명한다.
  4. 분석 과제의 다섯 관리 영역과 프로젝트 관리의 열 가지 주제 그룹을 구분한다.
  5. 학기 공통 자료로 풀 분석 과제 하나를 CRISP-DM의 단계에 맞춘 정의서로 작성한다.

1. 분석 기획의 방향

1.1 분석 기획

분석 기획은 실제 분석을 수행하기 전에 분석 과제를 정의하고, 의도한 결과를 얻을 수 있도록 관리 방안을 미리 계획하는 작업이다. 어떤 과제를(What), 왜(Why), 어떤 방법으로(How) 수행할지를 정한다.

분석을 기획하는 사람에게는 세 영역의 역량이 고루 필요하다. 교재 01의 4절에서 본 데이터 사이언스의 세 영역(분석, IT, 비즈니스 분석)과 이어지는 내용이다.

영역 내용
수학과 통계학의 지식 분석 기법을 이해하고 결과를 해석하는 바탕
정보 기술 데이터를 다루는 프로그래밍과 시스템의 기술
해당 업무에 대한 이해 분석 주제가 속한 업무 영역의 지식과 전문성

기획은 세 영역 가운데 한쪽으로 치우치지 않아야 한다. 기법만 알고 업무를 모르면 쓸모없는 과제를 정하게 되고, 업무만 알고 기법을 모르면 실행할 수 없는 과제를 정하게 된다. ### 1.2 분석 주제의 유형

분석 주제는 두 물음으로 나눈다. 무엇을 분석할지(분석 대상, What)를 아는가, 어떻게 분석할지(분석 방법, How)를 아는가이다. 두 물음의 답에 따라 네 유형이 나온다.

분석 방법을 안다 분석 방법을 모른다
분석 대상을 안다 최적화(Optimization) 솔루션(Solution)
분석 대상을 모른다 통찰(Insight) 발견(Discovery)

솔루션은 ’해결’로 옮기기도 한다. 상점의 사례로 옮기면 다음과 같다.

유형 상황 하는 일
최적화 품목군별 재고가 모자라거나 남는다는 문제를 알고, 지난 거래량으로 발주량을 계산하는 방법도 안다 알고 있는 방법을 적용하여 결과를 더 좋게 만든다
솔루션 반품이 늘어난 것이 문제라는 것은 알지만, 어떤 분석으로 원인을 찾을지 모른다 문제에 맞는 분석 방법(해법)을 찾는다
통찰 고객을 묶는 군집 분석은 할 줄 알지만, 무엇을 알아낼지는 정해 두지 않았다 아는 방법으로 자료를 살펴 새로운 분석 대상을 얻는다
발견 무엇을 분석할지도, 어떻게 분석할지도 정해지지 않았다 자료를 탐색하여 분석 대상 자체를 새로 찾는다

네 유형은 고정된 것이 아니다. 발견으로 시작한 과제가 분석 대상이 정해지면 솔루션이나 최적화로 옮겨 간다. 유형은 과제에 붙은 이름이 아니라 그 시점에 무엇을 알고 있는가를 나타낸다.

표를 외울 때에는 가로와 세로를 따로 기억한다. 분석 대상을 알면 윗줄(최적화, 솔루션)이고, 모르면 아랫줄(통찰, 발견)이다. 분석 방법을 알면 왼쪽 열(최적화, 통찰)이고, 모르면 오른쪽 열(솔루션, 발견)이다.

1.3 목표 시점에 따른 기획 방식

분석 기획은 목표로 삼는 시점에 따라 둘로 나눈다. 당면한 과제를 빠르게 해결하려는 과제 중심적 접근과, 분석을 조직에 지속적으로 내재화하려는 장기적 마스터 플랜 접근이다.

구분 과제 중심적 접근 장기적 마스터 플랜 접근
목표 시점 단기 중장기
1차 목표 속도와 시험(Speed & Test) 정확도와 전개(Accuracy & Deploy)
과제의 유형 빠른 성과(Quick-Win) 장기적 관점(Long Term View)
접근 방식 문제 해결(Problem Solving) 문제 정의(Problem Definition)
상점의 예 다음 달 할인 행사의 대상 품목군을 2주 안에 정한다 3년에 걸쳐 고객 자료를 정비하고 분석 과제의 순서를 정한다

두 방식은 어느 하나를 고르는 관계가 아니다. 과제 중심적 접근으로 이해관계자가 분석의 가치를 빠르게 확인하게 하고, 장기적 마스터 플랜 접근으로 과제들을 일관된 방향에 놓는다. 둘을 함께 쓰는 것이 바람직하다. 마스터 플랜은 교재 03에서 다룬다.

1.4 분석 기획에서 고려할 것

분석을 기획할 때에는 다음 세 가지를 미리 살핀다.

고려할 것 내용 상점의 예
가용 데이터(Available Data) 분석에 쓸 데이터가 있는지를 먼저 확인한다. 데이터의 유형(정형, 반정형, 비정형)에 따라 쓸 수 있는 분석 방법과 도구가 달라진다 거래 내역과 고객 표(정형)는 있다. 방문 기록(반정형)과 상품 후기(비정형)는 모아 두지 않았다
적절한 활용 사례(Proper Use Case) 비슷한 분석이 이미 잘 구현되어 쓰이는 시나리오와 해법이 있으면 그것을 최대한 활용한다 고객 세분화는 다른 유통 업종에 널리 쓰이는 사례가 있다
장애 요소에 대한 사전 계획(Low Barrier of Execution) 분석을 수행하고 결과를 쓰는 과정에서 걸림돌이 될 것을 미리 찾아 대비한다. 비용, 결과의 이해 가능성, 운영 환경에서의 성능, 조직에 정착시키기 위한 교육과 변화 관리가 여기에 든다 분석 결과를 판촉 담당자가 이해하지 못하면 쓰이지 않는다. 설명할 수 있는 수준의 방법을 고른다

일회성 분석으로 끝내지 않고 조직의 역량으로 남기려면 계속적인 교육과 활용 방안 같은 변화 관리를 기획 단계에서 함께 계획한다.

1.5 혼동하기 쉬운 용어

짝 구분
솔루션과 통찰 솔루션은 대상을 알고 방법을 모른다. 통찰은 방법을 알고 대상을 모른다. 표의 대각선에 놓인 둘을 바꾸어 놓은 보기에 유의한다
최적화와 발견 둘 다 아는 것이 최적화, 둘 다 모르는 것이 발견이다
과제 중심적 접근과 장기적 마스터 플랜 접근 과제 중심은 속도와 시험, 빠른 성과, 문제 해결이다. 마스터 플랜은 정확도와 전개, 장기적 관점, 문제 정의다. 문제 해결과 문제 정의를 서로 바꾸어 놓은 보기에 유의한다

따라 하기

상점에서 나온 여섯 가지 상황을 분석 주제의 유형으로 판별한다. 표를 공책에 옮기고 칸을 채운다. 두 물음의 답을 먼저 적고, 유형은 1.2절의 표에서 찾는다.

사례 상황 분석 대상을 아는가 분석 방법을 아는가 유형
가 품목군별 월 매출 합계를 매달 그룹별 집계로 내어 보고한다
나 가입한 뒤 첫 구매까지 걸리는 기간이 길어졌다. 이를 줄이고 싶으나 어떤 분석을 써야 할지 정하지 못했다
다 군집 분석을 다룰 줄 아는 담당자가 고객 표를 이리저리 묶어 보며 쓸 만한 집단이 있는지 살핀다
라 새로 생긴 부서가 상점의 자료로 무엇을 할 수 있을지 아무것도 정하지 않았다
마 간편결제와 카드의 건당 금액 평균을 t-검정으로 견주기로 하였다
바 할인 문자를 보낸 뒤 매출이 늘었는지 알고 싶으나 무엇을 어떻게 재야 할지 정하지 못했다
  • 확인 1 여섯 사례마다 두 물음의 답(안다, 모른다)을 적고 유형을 하나씩 정하였다.
  • 확인 2 네 유형이 모두 한 번 이상 나왔고, 대상을 아는 사례(가, 나, 마, 바)는 모두 윗줄의 유형(최적화, 솔루션)에 놓였다.

이어서 다음 두 과제가 과제 중심적 접근과 장기적 마스터 플랜 접근 가운데 어느 쪽에 가까운지 판별한다. (ㄱ) 다음 주 행사에 쓸 할인 쿠폰의 금액을 이번 주 안에 정한다. (ㄴ) 앞으로 세 해 동안 어떤 자료를 새로 모으고 어떤 분석을 차례로 도입할지 정한다.

  • 확인 3 (ㄱ)과 (ㄴ)을 두 접근에 하나씩 놓고, 각각의 1차 목표(속도와 시험, 정확도와 전개)를 함께 적었다.

2. 분석 방법론

2.1 방법론의 필요성과 구성

자료에 근거한 의사결정을 가로막는 요소로 다음 셋을 든다.

장애 요소 뜻
고정 관념(Stereotype) 이미 굳어진 생각에 따라 판단한다
편향된 생각(Bias) 한쪽으로 치우친 경험이나 선호에 따라 판단한다
프레이밍 효과(Framing Effect) 같은 사실이라도 제시하는 틀에 따라 판단이 달라진다

분석 방법론은 분석을 개인의 감각에 맡기지 않고, 누가 하더라도 일정한 품질로 되풀이할 수 있게 하는 절차의 체계다. 방법론은 다음 네 가지로 구성된다.

구성 요소 내용
절차(Procedures) 무엇을 어떤 순서로 하는가
방법(Methods) 각 절차를 어떻게 수행하는가
도구와 기법(Tools & Techniques) 수행에 쓰는 도구와 기법
템플릿과 산출물(Templates & Outputs) 채워 넣는 양식과 그 결과로 남는 문서

방법론은 개인의 경험에서 만들어지고 다시 개인의 역량으로 돌아간다. 교재 01의 1절에서 본 암묵지와 형식지가 여기서 다시 쓰인다.

과정 변화 내용
형식화 암묵지 → 형식지 개인의 머릿속에 있던 경험을 문서로 적는다
체계화 형식지 → 방법론 문서를 절차, 방법, 도구로 정리하여 방법론으로 만든다
내재화 방법론 → 암묵지 방법론을 익혀 개인의 역량으로 만든다

2.2 방법론의 모델

방법론이 단계를 진행하는 방식은 소프트웨어 개발의 생명 주기 모델에서 빌려 온 세 모델로 설명한다.

모델 진행 방식 특징
폭포수 모델(Waterfall Model) 단계를 순차적으로 진행한다. 앞 단계의 결과를 확인해야 다음 단계로 간다 하향식으로 진행한다. 문제가 발견되면 앞 단계로 되돌아가는 피드백을 둔다. 요구 사항이 바뀌면 대응하기 어렵다
프로토타입 모델(Prototype Model) 일부분을 먼저 만들어 사용자에게 보이고, 써 본 결과를 반영하여 고친다 사용자의 요구를 처음부터 분명히 알기 어려울 때 쓴다. 폭포수 모델의 단점을 보완한다
나선형 모델(Spiral Model) 같은 과정을 여러 번 반복하며 점증적으로 개발한다 반복마다 위험을 분석한다. 처음 시도하는 프로젝트에 적용하기 쉽다. 반복을 관리하는 체계가 없으면 복잡도가 커진다

2.3 KDD 분석 방법론

KDD(Knowledge Discovery in Databases)는 데이터베이스에서 의미 있는 지식을 찾아내는 절차를 다섯 단계로 정리한 방법론이다. 1996년에 페이야드(Fayyad) 등이 제시하였다. 데이터 마이닝은 KDD 전체 과정 가운데 한 단계의 이름이다.

순서 단계 하는 일 상점의 예
1 데이터 선택(Selection) 업무 영역을 이해하고 분석 목표를 정한 뒤, 분석에 쓸 목표 데이터를 고른다 2026년의 거래 내역과 고객 표를 분석 대상으로 고른다
2 전처리(Preprocessing) 잡음, 이상값, 결측값을 찾아 없애거나 다시 처리하여 일관된 데이터를 얻는다 금액이 0원인 거래, 고객 번호가 빈 거래가 있는지 살핀다
3 변환(Transformation) 분석 목적에 맞게 변수를 만들거나 고르고, 차원을 줄인다. 훈련용 자료와 검증용 자료로 나눈다 고객별 거래 횟수와 금액 합계를 만들고, 고객을 두 묶음으로 나눈다
4 데이터 마이닝(Data Mining) 분석 목적에 맞는 기법과 알고리즘을 골라 적용하여 패턴을 찾는다 의사결정나무로 가전 구매 고객을 분류한다
5 해석과 평가(Interpretation/Evaluation) 찾은 패턴을 해석하고 분석 목표에 맞는지 평가한다. 얻은 지식을 업무에 활용한다 분류 결과가 안내 문자 발송에 쓸 만한지 판단한다

전처리 단계에서 데이터가 더 필요하다고 드러나면 데이터 선택 단계를 다시 수행한다. 다른 단계에서도 필요하면 앞 단계로 되돌아간다.

2.4 CRISP-DM 분석 방법론

CRISP-DM(Cross Industry Standard Process for Data Mining)은 업종에 관계없이 쓸 수 있도록 만든 데이터 마이닝의 표준 절차다. 1990년대 후반에 여러 기업이 모인 컨소시엄이 만들었고, 2000년에 1.0판 안내서가 나왔다. 네 수준의 계층과 여섯 단계로 구성된다.

네 수준

수준 이름 내용
1 단계(Phases) 가장 위의 수준. 여섯 단계다
2 일반화 태스크(Generic Tasks) 단계를 구성하는 일의 단위. 예: 데이터 정제
3 세분화 태스크(Specialized Tasks) 일반화 태스크를 구체적인 상황에 맞게 나눈 것. 예: 수치형 열의 정제, 범주형 열의 정제
4 프로세스 실행(Process Instances) 실제 분석에서 수행한 구체적인 실행

여섯 단계

순서 단계 하는 일 주요 태스크
1 업무 이해(Business Understanding) 업무의 관점에서 프로젝트의 목적과 요구 사항을 이해하고, 이를 분석의 목표로 바꾼다 업무 목적 파악, 상황 파악, 데이터 마이닝 목표 설정, 프로젝트 계획 수립
2 데이터 이해(Data Understanding) 데이터를 모으고 속성을 파악하며 품질의 문제를 찾는다 초기 데이터 수집, 데이터 기술 분석, 데이터 탐색, 데이터 품질 확인
3 데이터 준비(Data Preparation) 분석 기법에 맞는 분석용 데이터 세트를 만든다 분석용 데이터 세트 선택, 데이터 정제, 분석용 데이터 세트 편성, 데이터 통합, 데이터 포맷팅
4 모델링(Modeling) 기법과 알고리즘을 골라 모형을 만들고 기술적으로 평가한다 모델링 기법 선택, 모델 테스트 계획 설계, 모델 작성, 모델 평가
5 평가(Evaluation) 모형이 처음에 정한 업무 목적에 맞는지 평가하고, 결과를 받아들일지 판단한다 분석 결과 평가, 모델링 과정 평가, 모델 적용성 평가
6 전개(Deployment) 모형을 실제 업무에 적용할 계획을 세우고 프로젝트를 마무리한다 전개 계획 수립, 모니터링과 유지보수 계획 수립, 프로젝트 종료 보고서 작성, 프로젝트 리뷰

데이터 준비는 시간이 가장 많이 드는 단계다. CRISP-DM의 안내서 가운데 하나는 데이터 준비에 프로젝트 시간과 노력의 50~70%가 드는 것으로 추정한다. 단계 사이의 되돌아감

CRISP-DM의 단계는 한 방향으로만 흐르지 않는다. 단계의 순서는 엄격하지 않으며, 대부분의 프로젝트는 필요에 따라 단계 사이를 오간다. 폭포수 모델처럼 차례로 끝내는 것이 아니라, 앞 단계로 되돌아가며 완성도를 높인다.

되돌아가는 자리 까닭
업무 이해 ↔︎ 데이터 이해 데이터를 살펴보면 업무의 목적을 다시 잡아야 할 때가 있다
데이터 준비 ↔︎ 모델링 모형을 만들다 보면 변수를 더 만들거나 데이터를 다시 정제해야 할 때가 있다
평가 → 업무 이해 평가에서 결과가 업무 목적에 맞지 않으면 처음으로 돌아가 목적과 과제를 다시 정한다

전개가 끝난 뒤에도 운영에서 얻은 경험으로 다음 분석을 시작하므로, 여섯 단계 전체가 하나의 순환을 이룬다.

KDD와의 대응

두 방법론은 단계의 수와 이름이 다르지만 하는 일은 겹친다. KDD의 다섯 단계에는 CRISP-DM의 업무 이해와 전개에 해당하는 독립된 단계가 없다. KDD의 데이터 선택 단계가 업무 영역의 이해와 목표 설정을 언급하지만, CRISP-DM은 이를 업무 이해라는 첫 단계로 따로 둔다.

KDD CRISP-DM
(대응하는 단계가 없다) 업무 이해
데이터 선택, 전처리 데이터 이해
변환 데이터 준비
데이터 마이닝 모델링
해석과 평가 평가
(대응하는 단계가 없다) 전개

2.5 빅데이터 분석 방법론

빅데이터 분석 방법론은 세 계층과 다섯 단계로 구성된다.

세 계층

계층 내용
단계(Phase) 가장 위의 계층. 단계마다 산출물이 만들어진다. 산출물은 기준선(Baseline)으로 설정하여 관리하고 버전 관리로 통제한다
태스크(Task) 단계를 구성하는 단위 활동. 물리적 또는 논리적 단위로 품질을 검토하는 대상이다
스텝(Step) 태스크를 구성하는 가장 작은 단위. 작업 분할 구조도(WBS)의 워크 패키지에 해당한다. 입력 자료, 처리와 도구, 출력 자료로 구성된 단위 프로세스다

다섯 단계와 주요 태스크

순서 단계 하는 일 주요 태스크 주요 산출물
1 분석 기획(Planning) 업무를 이해하고 프로젝트의 범위, 계획, 위험 대응을 정한다 비즈니스 이해 및 범위 설정, 프로젝트 정의 및 계획 수립, 프로젝트 위험 계획 수립 프로젝트 범위 정의서, 수행 계획서
2 데이터 준비(Preparing) 필요한 데이터를 정의하고, 저장할 곳을 설계하고, 수집하여 정합성을 점검한다 필요 데이터 정의, 데이터 스토어 설계, 데이터 수집 및 정합성 점검 데이터 정의서, 데이터 스토어
3 데이터 분석(Analyzing) 분석용 데이터를 만들어 탐색하고, 모형을 만들어 평가하고 검증한다 분석용 데이터 준비, 텍스트 분석, 탐색적 분석, 모델링, 모델 평가 및 검증 분석용 데이터 세트, 모델 평가 보고서
4 시스템 구현(Developing) 분석 결과를 운영 중인 시스템에 적용하거나 시험용 시스템을 만든다 설계 및 구현, 시스템 테스트 및 운영 시스템 설계서, 운영 지침서
5 평가 및 전개(Deploying) 프로젝트의 성과를 평가하고 모형의 발전 계획을 세운 뒤 마무리한다 모델 발전 계획 수립, 프로젝트 평가 및 보고 모델 발전 계획서, 최종 보고서

데이터 분석 단계에서 데이터가 모자라다고 드러나면 데이터 준비 단계로 되돌아간다. 두 단계는 필요한 만큼 반복한다.

분석 기획 단계에서는 프로젝트 범위 정의서(SOW, Statement of Work), 작업 분할 구조도(WBS)가 든 수행 계획서, 위험 관리 계획서를 만든다. 위험에 대응하는 방법은 회피(Avoid), 전이(Transfer), 완화(Mitigate), 수용(Accept)의 넷이다.

2.6 혼동하기 쉬운 용어

짝 구분
단계의 수 KDD는 다섯, CRISP-DM은 여섯, 빅데이터 분석 방법론은 다섯이다
계층 CRISP-DM은 네 수준(단계, 일반화 태스크, 세분화 태스크, 프로세스 실행)이다. 빅데이터 분석 방법론은 세 계층(단계, 태스크, 스텝)이다
KDD의 전처리와 변환 전처리는 잡음, 이상값, 결측값을 처리한다. 변환은 변수를 만들고 고르며 차원을 줄이고, 훈련용과 검증용으로 나눈다
CRISP-DM의 데이터 이해와 데이터 준비 데이터 이해는 수집, 기술 분석, 탐색, 품질 확인이다. 데이터 준비는 선택, 정제, 편성, 통합, 포맷팅이다. 품질 확인은 데이터 이해에, 정제와 통합은 데이터 준비에 속한다

따라 하기

상점이 ‘재구매 고객 예측’ 과제를 진행하며 한 활동 여섯 개가 순서 없이 놓여 있다. 활동마다 CRISP-DM의 단계를 적고, 단계의 순서대로 기호를 늘어놓는다.

기호 활동 CRISP-DM의 단계
ㄱ 고객별 거래 횟수와 금액 합계를 새 열로 만들고 두 표를 고객ID로 합친다
ㄴ “재구매율을 높인다”는 상점의 목적을 “다음 분기에 다시 살 고객을 맞힌다”는 물음으로 바꾸어 적는다
ㄷ 고른 모형의 결과를 판촉 문자 발송 절차에 넣고, 달마다 결과를 점검할 계획을 세운다
ㄹ 두 표의 열과 건수를 살피고 빈칸과 이상한 값이 있는지 확인한다
ㅁ 의사결정나무와 로지스틱 회귀를 만들어 검증용 자료에서 맞힌 비율을 견준다
ㅂ 고른 모형이 재구매율 향상이라는 처음 목적에 쓸 만한지 판촉 담당자와 검토한다
  • 확인 4 여섯 활동에 단계를 하나씩 적었고, 여섯 단계가 모두 한 번씩 쓰였다.
  • 확인 5 단계의 순서대로 늘어놓은 결과가 ㄴ, ㄹ, ㄱ, ㅁ, ㅂ, ㄷ이다.
  • 확인 6 ㅁ과 ㅂ을 서로 다른 단계에 놓은 까닭을 ’기술적 평가’와 ’업무 목적’이라는 말을 넣어 한 줄로 적었다.

이어서 빅데이터 분석 방법론의 태스크 다섯 개(데이터 스토어 설계, 탐색적 분석, 프로젝트 위험 계획 수립, 시스템 테스트 및 운영, 모델 발전 계획 수립)를 다섯 단계에 하나씩 놓는다. 마지막으로 KDD의 다섯 단계를 2.4절의 대응표 없이 CRISP-DM의 단계 옆에 적어 본다.

  • 확인 7 다섯 태스크가 다섯 단계에 하나씩 놓였고, KDD에 대응하는 단계가 없는 CRISP-DM의 단계로 업무 이해와 전개를 적었다.

3. 분석 과제 발굴

3.1 하향식 접근과 상향식 접근

분석 과제를 찾는 길은 둘이다. 문제에서 출발하는 하향식 접근(Top-Down Approach)과 데이터에서 출발하는 상향식 접근(Bottom-Up Approach)이다.

구분 하향식 접근 상향식 접근
출발점 풀어야 할 문제 가지고 있는 데이터
쓰는 때 문제가 분명히 주어져 있을 때 문제를 정의하기 어려울 때
물음의 관점 왜(Why) 그런 일이 생기는가 무엇이(What) 데이터에 있는가
진행 문제 탐색 → 문제 정의 → 해결 방안 탐색 → 타당성 검토 데이터를 먼저 살피고, 결과를 보며 문제를 찾아 고쳐 나간다
주로 쓰는 분석 정의한 문제에 맞추어 해결 방안 탐색에서 고른 분석 목표 값이 없는 분석. 비지도 학습이 대표적이다
어울리는 분석 주제의 유형 분석 대상이 정해진 경우(최적화, 솔루션) 분석 대상 자체를 찾는 경우(통찰, 발견)

실제 과제 발굴에서는 두 접근을 섞어 쓴다. 가능한 방안을 넓게 찾는 발산(Diverge)의 단계는 상향식 접근에 해당하고, 그 가운데 고르고 검증하는 수렴(Converge)의 단계는 하향식 접근에 해당한다. 디자인 싱킹(Design Thinking)은 발산과 수렴을 되풀이하여 과제를 찾는 방법이다.

3.2 하향식 접근의 네 단계

순서 단계 하는 일
1 문제 탐색(Problem Discovery) 업무 전체를 빠짐없이 훑어 풀어야 할 문제를 찾아낸다. 해법보다 문제를 놓치지 않는 것이 중요하다
2 문제 정의(Problem Definition) 찾아낸 업무의 문제를 데이터의 문제로 바꾸어 정의한다
3 해결 방안 탐색(Solution Search) 정의한 문제를 풀 분석 기법과 시스템, 역량을 찾는다
4 타당성 검토(Feasibility Study) 경제적 타당성과 데이터·기술적 타당성을 검토하여 과제로 확정할지 정한다

3.3 문제 탐색

문제 탐색은 세 가지 방법으로 한다.

비즈니스 모델 기반 문제 탐색. 기업의 비즈니스 모델을 단순화하여 업무, 제품, 고객의 세 단위로 문제를 찾고, 이를 관리하는 두 영역인 규제와 감사, 지원 인프라를 더한다. 모두 다섯 영역이다.

영역 살피는 것 상점의 과제 예
업무(Operation) 제품과 서비스를 만들고 제공하기 위한 내부 프로세스와 주요 자원 품목군별 재고량의 최적화
제품(Product) 생산하고 제공하는 제품과 서비스의 개선 품목군별 판매 현황의 점검
고객(Customer) 제품과 서비스를 받는 고객, 그리고 고객에게 닿는 채널 결제수단별 이용 고객의 특성 파악
규제와 감사(Regulation & Audit) 제품의 생산과 전달 과정에서 생기는 규제와 보안 부정 결제의 탐지, 개인정보 처리 기록의 점검
지원 인프라(IT & Human Resource) 분석을 수행하는 시스템과 이를 운영하는 인력 주문이 몰리는 시기의 서버 증설 시점 예측, 상담 인력의 배치

지금의 사업 방식에서 벗어나 새로운 문제를 찾으려면 탐색의 범위를 넓힌다. 관점은 넷이다.

관점 살피는 것
거시적 관점 사회, 기술, 경제, 환경, 정치의 변화(STEEP)
경쟁자 확대 관점 대체재, 경쟁자, 신규 진입자
시장의 요구 탐색 관점 고객, 채널, 영향자
역량의 재해석 관점 내부 역량, 협력사와 네트워크

외부 참조 모델 기반 문제 탐색. 같은 업종이나 비슷한 업종의 분석 사례를 견주어 보고(벤치마킹), 자기 회사에 적용할 과제를 빠르게 찾는다. 분석 유스케이스 정의. 찾아낸 문제를 문제의 상황, 해결했을 때의 효과와 함께 적어 둔다. 이것이 다음 단계인 문제 정의의 입력이 된다.

3.4 문제 정의, 해결 방안 탐색, 타당성 검토

문제 정의. 업무의 문제를 데이터의 문제로 바꾼다. 필요한 데이터와 기법을 정하려면 문제가 데이터의 말로 적혀 있어야 한다.

업무의 문제 데이터의 문제
한 번 사고 다시 오지 않는 고객이 많다 고객별 거래 횟수와 마지막 거래일을 구하고, 재구매 여부에 영향을 주는 변수를 찾는다
간편결제 할인을 계속할지 정해야 한다 간편결제 거래와 카드 거래의 건당 금액 평균이 다른지 검정한다

해결 방안 탐색. 지금의 시스템으로 분석할 수 있는가, 분석 역량을 가지고 있는가의 두 물음에 따라 방안이 넷으로 갈린다.

분석 역량이 있다 분석 역량이 없다
기존 시스템으로 가능하다 기존 시스템을 개선하여 활용한다 교육과 채용으로 역량을 확보한다
새 기법과 시스템이 필요하다 시스템을 고도화한다 전문 업체에 맡긴다

타당성 검토. 다음 두 가지를 검토한다.

타당성 검토하는 것
경제적 타당성 비용 대비 편익. 데이터, 시스템, 인력, 유지보수에 드는 비용과 분석 결과로 얻는 경제적 가치를 견준다
데이터 및 기술적 타당성 데이터가 있는가, 분석 시스템의 환경이 갖추어져 있는가, 분석 역량이 있는가

3.5 상향식 접근

문제가 분명하지 않으면 하향식 접근의 첫 단계인 문제 탐색부터 막힌다. 상향식 접근은 가지고 있는 데이터를 먼저 분석하고, 그 결과에서 문제를 찾아 계속 고쳐 나간다.

  • 비지도 학습. 상향식 접근의 분석은 주로 비지도 학습으로 한다. 목표 값을 정하지 않고 데이터 자체의 결합, 연관성, 유사성을 살피는 방법이다. 군집 분석, 연관 분석이 여기에 든다. 정해진 목표 값을 맞히도록 학습하는 지도 학습(분류, 회귀)과 구분한다.
  • 상관 관계의 분석. 원인을 따져 묻는 대신 함께 나타나는 것을 먼저 찾는다. 교재 01의 3절에서 본 “인과 관계에서 상관 관계로”의 변화와 이어진다.
  • 프로토타이핑 접근법. 일단 분석을 시도해 보고, 결과를 확인하면서 반복하여 고쳐 나가는 방법이다. 완전하지 않더라도 신속하게 모형을 만들어 보이고, 사용자가 그것을 보며 문제를 더 분명히 알게 한다.

프로토타이핑이 필요한 까닭은 셋이다.

까닭 내용
문제에 대한 인식 수준 문제를 정확히 알지 못하거나 새로운 문제일 때, 시험용 모형으로 문제를 이해하고 구체화한다
필요 데이터 존재 여부의 불확실성 필요한 데이터가 있는지 불확실할 때, 대체할 데이터를 사용자와 반복하여 협의한다
데이터 사용 목적의 가변성 데이터의 가치는 처음 정한 목적에 고정되지 않는다. 쓰임이 바뀌거나 넓어질 수 있다

프로토타이핑은 다음 순서를 되풀이한다.

가설의 생성 → 디자인에 대한 실험 → 실제 환경에서의 테스트 → 테스트 결과에서 통찰 도출과 가설 확인

3.6 분석 과제 정의서

하향식 접근이나 상향식 접근으로 찾은 과제는 분석 과제 정의서로 정리한다. 정의서는 과제의 내용을 한곳에 적은 문서이며, 프로젝트를 수행하는 계획의 입력으로 쓰인다. 다음 항목을 적는다.

항목 내용
소스 데이터 분석에 쓰는 데이터와 그 출처
분석 방법 적용할 분석 기법
데이터 입수와 분석의 난이도 데이터를 구하기 쉬운가, 분석이 어려운가
분석 수행 주기 한 번 하는 분석인가, 주기적으로 되풀이하는가
분석 결과의 검증 책임 결과가 맞는지를 누가 확인하는가(검증 오너십)
상세 분석 과정 분석을 진행하는 구체적인 절차

5절의 중심 실습에서 이 정의서를 CRISP-DM의 단계에 맞춘 양식으로 작성한다.

4. 분석 프로젝트 관리

4.1 분석 과제의 관리 영역

분석 프로젝트는 범위, 일정, 품질, 위험, 의사소통 같은 일반적인 관리 항목에 더하여 다음 다섯 영역을 관리한다. 분석 과제에만 있는 특성이다.

영역 관리하는 것 상점의 예
데이터 크기(Data Size) 분석할 데이터의 양. 양에 따라 저장과 처리의 방식이 달라진다 거래 428건은 한 대의 PC로 다룬다. 방문 기록 수억 건은 그럴 수 없다
데이터 복잡도(Data Complexity) 데이터의 유형과 출처의 다양함. 정형 데이터만 쓰는가, 비정형 데이터와 여러 시스템의 데이터를 합치는가 거래 내역(정형)에 상품 후기(비정형)를 더하면 복잡도가 커진다
속도(Speed) 분석 결과가 필요한 시점. 하루나 주 단위로 모아 처리해도 되는가, 실시간으로 처리해야 하는가 월 매출 보고는 모아서 처리한다. 부정 결제의 탐지는 결제 순간에 판단해야 한다
분석 복잡도(Analytic Complexity) 모형의 복잡함. 모형이 복잡할수록 정확도는 오르지만 해석하기 어려워진다 판촉 담당자가 이해할 수 있는 모형과 가장 잘 맞히는 모형 사이에서 기준점을 정한다
정확도와 정밀도(Accuracy & Precision) 정확도는 모형의 결과와 실제 값의 차이가 작은 정도다. 정밀도는 모형을 되풀이해 썼을 때 결과가 흩어지는 정도가 작은 것, 곧 일관성이다 다음 달 매출 예측이 실제와 가까우면 정확하다. 자료를 바꾸어 다시 예측해도 값이 비슷하면 정밀하다

분석 복잡도와 정확도는 한쪽을 올리면 다른 쪽을 내주어야 하는 관계(상충 관계)에 있다. 해석할 수 있으면서 정확도가 충분한 모형을 찾는 것이 관리의 목표다. 정확도와 정밀도 사이에도 상충 관계가 있는 경우가 많으므로, 모형을 쓰는 목적에 맞추어 어느 쪽을 앞세울지 정한다. 분석 결과를 활용하는 측면에서는 정확도가 중요하고, 모형의 안정성 측면에서는 정밀도가 중요하다.

4.2 분석 프로젝트의 특성

  • 분석가는 데이터의 영역과 업무의 영역 사이에서 둘을 잇는 조정자의 역할을 한다. 분석 기법만이 아니라 프로젝트 관리의 역량도 필요하다.
  • 분석 프로젝트는 처음에 의도한 결과가 한 번에 나오지 않는다. 데이터와 모형을 바꾸어 가며 반복하므로 범위와 일정이 처음 계획에서 자주 벗어난다.

4.3 프로젝트 관리의 주제 그룹

프로젝트 관리의 국제 표준인 ISO 21500은 관리할 주제를 열 개의 주제 그룹으로 나누고, 관리의 진행을 착수, 기획, 실행, 통제, 종료의 다섯 프로세스 그룹으로 나눈다. 분석 프로젝트에서는 주제 그룹마다 유의할 점이 있다.

주제 그룹 분석 프로젝트에서 유의할 점
통합(Integration) 프로젝트 관리의 여러 프로세스를 하나로 묶어 운영한다
이해관계자(Stakeholder) 데이터 전문가, 업무 전문가, 분석 전문가, 시스템 전문가처럼 다양한 전문가가 참여하므로 이해관계자를 식별하고 관리한다
범위(Scope) 분석을 진행하면서 데이터의 형태와 양, 적용하는 알고리즘에 따라 범위가 자주 바뀐다. 결과물이 보고서인지 시스템인지를 미리 정해 둔다
자원(Resource) 분석 전문가가 부족하므로 인력의 확보 방안을 미리 검토한다
시간(Time) 의도한 결과가 한 번에 나오지 않아 반복이 많다. 기간을 정해 두고 그 안에서 할 일을 조정하는 타임 박싱(Time Boxing) 기법으로 일정을 관리한다
원가(Cost) 외부 데이터를 사 오거나 상용 도구를 쓰면 비용이 크게 든다. 사전에 조사한다
리스크(Risk) 데이터를 확보하지 못하거나 데이터와 알고리즘의 한계로 결과가 나오지 않을 위험을 미리 식별하고 대응한다
품질(Quality) 품질 목표를 정하고 품질 통제와 품질 보증으로 나누어 수행한다
조달(Procurement) 목적에 맞는 외부 자원을 적절히 쓴다. 시험적인 분석에는 장비를 사기보다 빌려 쓰는 방식을 검토한다
의사소통(Communication) 전문적인 분석 결과를 이해관계자 모두가 이해할 수 있는 형태로 공유하도록 의사소통 체계를 마련한다

4.4 혼동하기 쉬운 용어

짝 구분
데이터 크기와 데이터 복잡도 크기는 양이고, 복잡도는 유형과 출처의 다양함이다
관리 영역과 주제 그룹 관리 영역은 다섯(데이터 크기, 데이터 복잡도, 속도, 분석 복잡도, 정확도와 정밀도)이다. 주제 그룹은 열(통합, 이해관계자, 범위, 자원, 시간, 원가, 리스크, 품질, 조달, 의사소통)이다
주제 그룹과 프로세스 그룹 범위, 시간, 원가는 주제 그룹이다. 통제는 프로세스 그룹이며 주제 그룹이 아니다
범위와 시간 데이터와 알고리즘에 따라 할 일의 경계가 바뀌는 것은 범위, 반복 때문에 일정이 늘어나는 것은 시간이다

6. 자주 하는 실수와 오해

증상 또는 오해 원인 바로잡기
솔루션과 통찰을 바꾸어 고른다 이름의 느낌으로 고르고, 대상과 방법 가운데 무엇을 아는지를 따지지 않는다 먼저 “대상을 아는가”로 줄을 정한다. 대상을 알면 윗줄(최적화, 솔루션)이다
’평가’라는 말이 든 활동을 모두 평가 단계에 놓는다 모델링 단계의 ‘모델 평가’ 태스크와 평가 단계를 구분하지 않는다 모형의 성능을 재는 것은 모델링, 업무 목적에 맞는지를 보는 것은 평가 단계다
데이터 품질 확인을 데이터 준비 단계에 놓는다 품질을 확인하는 일과 고치는 일을 하나로 본다 확인은 데이터 이해, 정제는 데이터 준비다
빅데이터 분석 방법론의 데이터 준비를 분석용 데이터 세트를 만드는 단계로 안다 CRISP-DM의 데이터 준비와 이름이 같다 빅데이터 분석 방법론의 데이터 준비는 필요 데이터의 정의와 수집이다. 분석용 데이터 세트는 데이터 분석 단계에서 만든다
KDD에도 업무 이해와 전개 단계가 있다고 답한다 두 방법론의 단계를 일대일로 맞추려 한다 KDD는 다섯 단계이며 업무 이해와 전개에 대응하는 단계가 없다
데이터를 쓰기만 하면 상향식이라고 판단한다 하향식 접근도 데이터를 쓴다는 점을 놓친다 출발점이 문제인지 데이터인지를 본다. 문제가 먼저 주어졌으면 하향식이다
경쟁자를 비즈니스 모델의 다섯 영역에 넣는다 범위 확장의 관점과 비즈니스 모델의 영역을 섞는다 다섯 영역은 업무, 제품, 고객, 규제와 감사, 지원 인프라다. 경쟁자는 범위를 넓힐 때의 관점이다
관리 영역의 정밀도를 분류 모형의 정밀도로 읽는다 이름이 같다 이 장의 정밀도는 반복했을 때의 일관성이다. 교재 11의 정밀도는 양성으로 예측한 것 가운데 실제 양성의 비율이다
정의서의 분석 목표를 “매출을 늘린다”처럼 쓴다 업무의 말과 데이터의 말을 구분하지 않는다 열 이름과 방법(합계, 비교, 분류)이 들어간 물음으로 바꾸어 쓴다

7. 정리

주제 기억할 것
분석 주제의 유형 대상과 방법을 모두 알면 최적화, 대상만 알면 솔루션, 방법만 알면 통찰, 둘 다 모르면 발견
목표 시점에 따른 기획 과제 중심적 접근은 속도와 시험, 빠른 성과, 문제 해결. 장기적 마스터 플랜 접근은 정확도와 전개, 장기적 관점, 문제 정의
기획에서 고려할 것 가용 데이터, 적절한 활용 사례, 장애 요소에 대한 사전 계획
방법론의 구성과 모델 절차, 방법, 도구와 기법, 템플릿과 산출물. 폭포수(순차), 프로토타입(먼저 만들고 고침), 나선형(반복과 점증)
KDD 데이터 선택 → 전처리 → 변환 → 데이터 마이닝 → 해석과 평가. 업무 이해와 전개에 대응하는 단계가 없다
CRISP-DM 업무 이해 → 데이터 이해 → 데이터 준비 → 모델링 → 평가 → 전개. 네 수준. 단계 사이를 오간다. 데이터 준비에 시간이 가장 많이 든다
빅데이터 분석 방법론 단계, 태스크, 스텝의 세 계층. 분석 기획 → 데이터 준비 → 데이터 분석 → 시스템 구현 → 평가 및 전개
하향식 접근 문제 탐색 → 문제 정의 → 해결 방안 탐색 → 타당성 검토. 문제 탐색의 다섯 영역은 업무, 제품, 고객, 규제와 감사, 지원 인프라
상향식 접근 데이터에서 출발. 비지도 학습, 프로토타이핑, 디자인 싱킹의 발산
분석 과제 정의서 소스 데이터, 분석 방법, 난이도, 수행 주기, 검증 책임, 상세 분석 과정
분석 과제의 관리 영역 데이터 크기, 데이터 복잡도, 속도, 분석 복잡도, 정확도와 정밀도
프로젝트 관리의 주제 그룹 통합, 이해관계자, 범위, 자원, 시간, 원가, 리스크, 품질, 조달, 의사소통

  7. ②. CRISP-DM은 단계 사이를 오가며, 평가에서 업무 이해로 돌아가는 길이 있다. ①은 그 반대다. ③은 KDD의 단계다. ④는 빅데이터 분석 방법론의 계층이며, CRISP-DM은 네 수준(단계, 일반화 태스크, 세분화 태스크, 프로세스 실행)이다. (2.4절)
