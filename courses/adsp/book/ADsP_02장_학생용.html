분석 기획은 분석을 실행하기 전에 무엇을, 왜, 어떤 순서로 할지를 정하는 일이다. 이 장은 ADsP 2과목의 첫 주요 항목인 ’데이터분석 기획의 이해’를 다룬다. 분석 주제의 유형, 분석 방법론의 단계, 분석 과제를 찾는 두 접근, 분석 프로젝트의 관리 영역이 그 내용이다. 2과목은 50문항 가운데 10문항이며, 4문항 이상을 맞히지 못하면 과락이다.

2과목의 문항은 용어의 짝과 단계의 순서, 사례의 유형과 단계를 묻는다. 이 장은 비교표와 단계표를 중심으로 하고, 사례는 교재 01의 거래 내역 표를 가진 가상의 온라인 상점(이하 ‘상점’)으로 통일한다. 코드는 없다.

학습 목표

  1. 분석 대상과 분석 방법을 아는지에 따라 분석 주제의 네 유형을 구분하고, 목표 시점에 따른 두 기획 방식을 비교한다.
  2. KDD, CRISP-DM, 빅데이터 분석 방법론의 단계를 순서대로 말하고, 단계마다 하는 일을 짝짓는다.
  3. 사례를 보고 하향식 접근과 상향식 접근 가운데 어느 것인지 판단하고, 하향식 접근의 네 단계를 설명한다.
  4. 분석 과제의 다섯 관리 영역과 프로젝트 관리의 열 가지 주제 그룹을 구분한다.
  5. 학기 공통 자료로 풀 분석 과제 하나를 CRISP-DM의 단계에 맞춘 정의서로 작성한다.

1. 분석 기획의 방향

배경과 쓰임

「인공지능 및 데이터 기반 행정 활성화에 관한 법률」(2026년 2월 27일에 「데이터기반행정 활성화에 관한 법률」에서 이름이 바뀌었고 2026년 8월 28일부터 시행)은 데이터를 수집, 저장, 가공, 분석, 표현하는 방법으로 정책 수립과 의사결정을 객관적이고 과학적으로 수행하는 행정을 ’데이터기반행정’이라 정의한다. 같은 법은 공공기관에 분석센터를 두고 그 업무를 총괄하는 책임관을 임명하게 한다.

[최신 자료 자리: 인공지능 및 데이터 기반 행정 활성화에 관한 법률의 이름과 시행일] 2026-11-16에 국가법령정보센터(https://www.law.go.kr)에서 확인한 값은 2026년 2월 27일 공포, 2026년 8월 28일 시행이며, 2027년 2월 28일에 시행할 개정이 따로 예정되어 있다. 수업 전에 법령 이름과 조문 번호(제2조 정의, 제19조 책임관, 제20조 분석센터)를 다시 확인한다.

1.1 분석 기획

분석 기획은 실제 분석을 수행하기 전에 분석 과제를 정의하고, 의도한 결과를 얻을 수 있도록 관리 방안을 미리 계획하는 작업이다. 기획하는 사람에게는 수학과 통계학의 지식(기법의 이해와 결과의 해석), 정보 기술(데이터를 다루는 프로그래밍과 시스템), 해당 업무에 대한 이해(업무 영역의 지식과 전문성)의 세 영역이 고루 필요하다. 교재 01의 4절에서 본 데이터 사이언스의 세 영역과 이어진다.

1.2 분석 주제의 유형

분석 주제는 무엇을 분석할지(분석 대상, What)를 아는가, 어떻게 분석할지(분석 방법, How)를 아는가의 두 물음으로 나눈다.

분석 방법을 안다 분석 방법을 모른다
분석 대상을 안다 최적화(Optimization) 솔루션(Solution)
분석 대상을 모른다 통찰(Insight) 발견(Discovery)

최적화는 알고 있는 방법을 적용하여 결과를 더 좋게 만들고, 솔루션(’해결’로도 옮긴다)은 문제에 맞는 분석 방법을 찾는다. 통찰은 아는 방법으로 자료를 살펴 새로운 분석 대상을 얻고, 발견은 분석 대상 자체를 새로 찾는다. 유형은 과제에 붙은 고정된 이름이 아니라 그 시점에 무엇을 알고 있는가를 나타내므로, 발견으로 시작한 과제가 대상이 정해지면 솔루션이나 최적화로 옮겨 간다. 분석 대상을 알면 윗줄, 분석 방법을 알면 왼쪽 열이다.

1.3 목표 시점에 따른 기획 방식

분석 기획은 목표 시점에 따라 당면한 과제를 빠르게 해결하려는 과제 중심적 접근과, 분석을 조직에 지속적으로 내재화하려는 장기적 마스터 플랜 접근으로 나눈다.

구분 과제 중심적 접근 장기적 마스터 플랜 접근
목표 시점 단기 중장기
1차 목표 속도와 시험(Speed & Test) 정확도와 전개(Accuracy & Deploy)
과제의 유형 빠른 성과(Quick-Win) 장기적 관점(Long Term View)
접근 방식 문제 해결(Problem Solving) 문제 정의(Problem Definition)

두 방식은 어느 하나를 고르는 관계가 아니라 함께 쓰는 것이 바람직하다. 과제 중심적 접근으로 분석의 가치를 빠르게 보이고, 마스터 플랜으로 과제들을 일관된 방향에 놓는다. 마스터 플랜은 교재 03에서 다룬다.

1.4 분석 기획에서 고려할 것

고려할 것 내용
가용 데이터(Available Data) 분석에 쓸 데이터가 있는지 먼저 확인한다. 데이터의 유형(정형, 반정형, 비정형)에 따라 쓸 수 있는 분석 방법과 도구가 달라진다
적절한 활용 사례(Proper Use Case) 비슷한 분석이 이미 잘 구현되어 쓰이는 시나리오와 해법이 있으면 최대한 활용한다
장애 요소에 대한 사전 계획(Low Barrier of Execution) 비용, 결과의 이해 가능성, 운영 환경에서의 성능, 조직에 정착시키기 위한 교육과 변화 관리처럼 걸림돌이 될 것을 미리 찾아 대비한다

상점의 경우 거래 내역과 고객 표(정형)는 있으나 방문 기록(반정형)과 상품 후기(비정형)는 없다. 없는 기록은 곧 장애 요소의 목록이 되며, 중심 실습의 정의서 11번에 옮겨 적는다.

  • 확인 2 네 사례가 최적화, 솔루션, 통찰, 발견에 하나씩 놓였고, 대상을 아는 두 사례(가, 나)가 윗줄의 유형에 놓였다.
  • 확인 3 (ㄱ)과 (ㄴ)을 두 접근에 하나씩 놓고 각각의 1차 목표(속도와 시험, 정확도와 전개)를 적었다.

해석. “어떤 분석을 써야 할지 정하지 못했다”는 방법을 모른다는 단서이고, “무엇을 할 수 있을지 정하지 않았다”, “쓸 만한 집단이 있는지 살핀다”는 대상을 모른다는 단서다. 다는 방법(군집 분석)을 알고 대상을 모르므로 통찰, 나는 대상(첫 구매까지의 기간)을 알고 방법을 모르므로 솔루션이다.

2. 분석 방법론

배경과 쓰임

CRISP-DM 1.0판 안내서(Chapman 외, 2000)의 머리말에 따르면, 1996년 말에 데이터 마이닝을 일찍 도입한 세 회사(당시의 Daimler-Benz, ISL, NCR)가 회사나 도구에 묶이지 않은 표준 절차를 만들기로 하고, 컨소시엄을 꾸려 유럽 위원회의 지원을 받아 2000년에 1.0판을 냈다. 공공 부문에서도 「인공지능 및 데이터 기반 행정 활성화에 관한 법률」 제17조가 “데이터 분석등의 절차 및 방법”의 표준을 정하도록 한다.

2.1 방법론의 필요성과 구성

자료에 근거한 의사결정을 가로막는 요소로 고정 관념(Stereotype), 편향된 생각(Bias), 프레이밍 효과(Framing Effect, 같은 사실이라도 제시하는 틀에 따라 판단이 달라진다)를 든다. 분석 방법론은 분석을 개인의 감각에 맡기지 않고 누가 하더라도 일정한 품질로 되풀이할 수 있게 하는 절차의 체계이며, 절차(Procedures), 방법(Methods), 도구와 기법(Tools & Techniques), 템플릿과 산출물(Templates & Outputs)의 네 가지로 구성된다.

방법론은 개인의 경험에서 만들어지고 다시 개인의 역량으로 돌아간다(교재 01의 1절, 암묵지와 형식지).

과정 변화 내용
형식화 암묵지 → 형식지 개인의 머릿속에 있던 경험을 문서로 적는다
체계화 형식지 → 방법론 문서를 절차, 방법, 도구로 정리하여 방법론으로 만든다
내재화 방법론 → 암묵지 방법론을 익혀 개인의 역량으로 만든다

2.2 방법론의 모델

모델 진행 방식 특징
폭포수 모델(Waterfall Model) 단계를 순차적으로 진행한다. 앞 단계의 결과를 확인해야 다음 단계로 간다 하향식으로 진행한다. 문제가 발견되면 앞 단계로 되돌아가는 피드백을 둔다. 요구 사항이 바뀌면 대응하기 어렵다
프로토타입 모델(Prototype Model) 일부분을 먼저 만들어 사용자에게 보이고, 써 본 결과를 반영하여 고친다 사용자의 요구를 처음부터 분명히 알기 어려울 때 쓴다. 폭포수 모델의 단점을 보완한다
나선형 모델(Spiral Model) 같은 과정을 여러 번 반복하며 점증적으로 개발한다 반복마다 위험을 분석한다. 처음 시도하는 프로젝트에 적용하기 쉽다. 반복을 관리하는 체계가 없으면 복잡도가 커진다

2.3 KDD 분석 방법론

KDD(Knowledge Discovery in Databases)는 데이터베이스에서 의미 있는 지식을 찾아내는 절차를 다섯 단계로 정리한 방법론으로, 1996년에 페이야드(Fayyad) 등이 제시하였다. 데이터 마이닝은 KDD 전체 과정 가운데 한 단계의 이름이다.

순서 단계 하는 일
1 데이터 선택(Selection) 업무 영역을 이해하고 분석 목표를 정한 뒤, 분석에 쓸 목표 데이터를 고른다
2 전처리(Preprocessing) 잡음, 이상값, 결측값을 찾아 없애거나 다시 처리하여 일관된 데이터를 얻는다
3 변환(Transformation) 분석 목적에 맞게 변수를 만들거나 고르고, 차원을 줄인다. 훈련용 자료와 검증용 자료로 나눈다
4 데이터 마이닝(Data Mining) 분석 목적에 맞는 기법과 알고리즘을 골라 적용하여 패턴을 찾는다
5 해석과 평가(Interpretation/Evaluation) 찾은 패턴을 해석하고 분석 목표에 맞는지 평가한다. 얻은 지식을 업무에 활용한다

전처리에서 데이터가 더 필요하다고 드러나면 데이터 선택을 다시 수행하는 것처럼, 필요하면 앞 단계로 되돌아간다.

2.4 CRISP-DM 분석 방법론

CRISP-DM(Cross Industry Standard Process for Data Mining)은 업종, 도구, 적용 분야에 묶이지 않도록 만든 데이터 마이닝의 표준 절차로서, 네 수준의 계층과 여섯 단계로 구성된다.

수준 이름 내용
1 단계(Phases) 가장 위의 수준. 여섯 단계다
2 일반화 태스크(Generic Tasks) 단계를 구성하는 일의 단위. 예: 데이터 정제
3 세분화 태스크(Specialized Tasks) 일반화 태스크를 구체적인 상황에 맞게 나눈 것. 예: 수치형 열의 정제, 범주형 열의 정제
4 프로세스 실행(Process Instances) 실제 분석에서 수행한 구체적인 실행의 기록

[그림 자리: CRISP-DM의 네 수준] 위에서 아래로 좁아지는 네 층(단계, 일반화 태스크, 세분화 태스크, 프로세스 실행)을 그리고, 위의 두 층에 “일반(generic)”, 아래의 두 층에 “상황에 맞춘 것(specialized)”이라고 표시한다. 층마다 이 교재의 예(데이터 준비 → 데이터 정제 → 수치형 열의 정제 → 상점의 2026년 금액 열 점검 기록)를 한 줄씩 적는다. 안내서 2장의 그림 1을 참고하여 새로 그린다.

순서 단계 하는 일 주요 태스크
1 업무 이해(Business Understanding) 업무의 관점에서 프로젝트의 목적과 요구 사항을 이해하고, 이를 분석의 목표로 바꾼다 업무 목적 파악, 상황 파악, 데이터 마이닝 목표 설정, 프로젝트 계획 수립
2 데이터 이해(Data Understanding) 데이터를 모으고 속성을 파악하며 품질의 문제를 찾는다 초기 데이터 수집, 데이터 기술 분석, 데이터 탐색, 데이터 품질 확인
3 데이터 준비(Data Preparation) 분석 기법에 맞는 분석용 데이터 세트를 만든다 분석용 데이터 세트 선택, 데이터 정제, 분석용 데이터 세트 편성, 데이터 통합, 데이터 포맷팅
4 모델링(Modeling) 기법과 알고리즘을 골라 모형을 만들고 기술적으로 평가한다 모델링 기법 선택, 모델 테스트 계획 설계, 모델 작성, 모델 평가
5 평가(Evaluation) 모형이 처음에 정한 업무 목적에 맞는지 평가하고, 결과를 받아들일지 판단한다 분석 결과 평가, 모델링 과정 평가, 모델 적용성 평가
6 전개(Deployment) 모형을 실제 업무에 적용할 계획을 세우고 프로젝트를 마무리한다 전개 계획 수립, 모니터링과 유지보수 계획 수립, 프로젝트 종료 보고서 작성, 프로젝트 리뷰

데이터 준비는 시간이 가장 많이 드는 단계로, CRISP-DM의 안내서 가운데 하나는 프로젝트 시간과 노력의 50~70%가 든다고 추정한다. 단계의 순서는 엄격하지 않으며, 다음 자리에서 앞 단계로 되돌아가며 완성도를 높인다.

되돌아가는 자리 까닭
업무 이해 ↔︎ 데이터 이해 데이터를 살펴보면 업무의 목적을 다시 잡아야 할 때가 있다
데이터 준비 ↔︎ 모델링 모형을 만들다 보면 변수를 더 만들거나 데이터를 다시 정제해야 할 때가 있다
평가 → 업무 이해 평가에서 결과가 업무 목적에 맞지 않으면 처음으로 돌아가 목적과 과제를 다시 정한다

전개에서 얻은 경험이 다음 분석을 시작하므로 여섯 단계 전체가 하나의 순환을 이룬다.

[그림 자리: CRISP-DM의 여섯 단계와 순환] 가운데에 ’데이터’를 두고 둘레에 여섯 단계를 시계 방향으로 놓는다. 업무 이해와 데이터 이해 사이, 데이터 준비와 모델링 사이에 양쪽 화살표를, 평가에서 업무 이해로 되돌아가는 화살표를 그리고, 여섯 단계를 감싸는 바깥 원에 “다음 분석으로 이어짐”이라고 적는다. 안내서 2장의 그림 2를 참고하여 새로 그린다.

KDD의 다섯 단계에는 CRISP-DM의 업무 이해와 전개에 해당하는 독립된 단계가 없다.

KDD CRISP-DM

변환 데이터 준비
데이터 마이닝 모델링
해석과 평가 평가

2.5 빅데이터 분석 방법론

빅데이터 분석 방법론은 세 계층과 다섯 단계로 구성된다.

계층 내용
단계(Phase) 가장 위의 계층. 단계마다 산출물이 만들어진다. 산출물은 기준선(Baseline)으로 설정하여 관리하고 버전 관리로 통제한다
태스크(Task) 단계를 구성하는 단위 활동. 물리적 또는 논리적 단위로 품질을 검토하는 대상이다
스텝(Step) 태스크를 구성하는 가장 작은 단위. 작업 분할 구조도(WBS)의 워크 패키지에 해당한다. 입력 자료, 처리와 도구, 출력 자료로 구성된 단위 프로세스다

[그림 자리: 빅데이터 분석 방법론의 세 계층] 맨 위에 다섯 단계를 가로로 늘어놓고, 그 가운데 ‘데이터 분석’ 단계 하나를 골라 아래로 다섯 태스크를 펼친 뒤, 태스크 하나(‘모델링’)를 다시 스텝으로 펼친다. 스텝 상자 하나에는 “입력 자료 → 처리와 도구 → 출력 자료”의 세 칸을 그린다. 단계 상자 옆에 “산출물은 기준선으로 관리”, 태스크 상자 옆에 “품질 검토의 단위”, 스텝 상자 옆에 “WBS의 워크 패키지”라고 적는다.

순서 단계 주요 태스크 주요 산출물
1 분석 기획(Planning) 비즈니스 이해 및 범위 설정, 프로젝트 정의 및 계획 수립, 프로젝트 위험 계획 수립 프로젝트 범위 정의서, 수행 계획서
2 데이터 준비(Preparing) 필요 데이터 정의, 데이터 스토어 설계, 데이터 수집 및 정합성 점검 데이터 정의서, 데이터 스토어
3 데이터 분석(Analyzing) 분석용 데이터 준비, 텍스트 분석, 탐색적 분석, 모델링, 모델 평가 및 검증 분석용 데이터 세트, 모델 평가 보고서
4 시스템 구현(Developing) 설계 및 구현, 시스템 테스트 및 운영 시스템 설계서, 운영 지침서
5 평가 및 전개(Deploying) 모델 발전 계획 수립, 프로젝트 평가 및 보고 모델 발전 계획서, 최종 보고서

데이터 분석 단계에서 데이터가 모자라면 데이터 준비 단계로 되돌아가 필요한 만큼 반복한다. 분석 기획 단계에서는 프로젝트 범위 정의서(SOW, Statement of Work), 작업 분할 구조도(WBS)가 든 수행 계획서, 위험 관리 계획서를 만들며, 위험에 대응하는 방법은 회피(Avoid), 전이(Transfer), 완화(Mitigate), 수용(Accept)의 넷이다.

2.6 단계별 산출물의 예

방법론의 네 구성 요소 가운데 마지막이 템플릿과 산출물이며, 단계는 산출물이 남았을 때 끝난다. CRISP-DM 1.0판 안내서는 일반화 태스크마다 남길 산출물을 정해 두었다. 영문 이름은 안내서의 것이고 한국어 이름은 이 교재가 옮긴 것이다.

단계 주요 산출물(안내서의 이름)
업무 이해 배경(Background), 업무 목적(Business Objectives), 업무 성공 기준(Business Success Criteria), 자원 목록, 위험과 대응책, 데이터 마이닝 목표, 데이터 마이닝 성공 기준(Data Mining Success Criteria), 프로젝트 계획
데이터 이해 초기 데이터 수집 보고서, 데이터 기술 보고서(Data Description Report), 데이터 탐색 보고서, 데이터 품질 보고서(Data Quality Report)
데이터 준비 포함과 제외의 근거(Rationale for Inclusion/Exclusion), 데이터 정제 보고서, 파생 속성(Derived Attributes), 통합된 데이터(Merged Data), 데이터 세트 설명(Dataset Description)
모델링 모델링 기법, 테스트 설계(Test Design), 매개변수 설정과 모형, 모형 평가
평가 업무 성공 기준에 비춘 결과의 평가, 승인된 모형(Approved Models), 과정의 검토(Review of Process), 결정(Decision)
전개 전개 계획(Deployment Plan), 모니터링과 유지보수 계획, 최종 보고서, 경험의 기록(Experience Documentation)

표에서 세 가지를 본다. 첫째, 업무 이해 단계의 업무 성공 기준은 업무의 말(예: 안내를 받은 고객의 구매 비율)이고 데이터 마이닝 성공 기준은 데이터의 말(예: 검증용 자료에서 찾아낸 비율)이다. 평가 단계는 앞의 것으로, 모델링 단계의 모델 평가는 뒤의 것으로 판단한다. 둘째, 데이터 품질 보고서는 데이터 이해의 산출물이고, 그 보고서를 받아 고치는 일은 데이터 준비의 데이터 정제다. 셋째, 전개의 경험의 기록은 다음 프로젝트의 업무 이해로 넘어가 순환을 이룬다.

따라 하기

예상. 아래 활동 가운데 ’평가’나 ’견준다’는 말이 든 ㅁ과 ㅂ이 같은 단계에 놓일지 다른 단계에 놓일지 먼저 적는다.

실행. 상점이 ‘재구매 고객 예측’ 과제를 진행하며 한 여섯 활동에 CRISP-DM의 단계를 적고, 단계의 순서대로 늘어놓는다.

기호 활동
ㄱ 고객별 거래 횟수와 금액 합계를 새 열로 만들고 두 표를 고객ID로 합친다
ㄴ “재구매율을 높인다”는 상점의 목적을 “다음 분기에 다시 살 고객을 맞힌다”는 물음으로 바꾸어 적는다
ㄷ 고른 모형의 결과를 판촉 문자 발송 절차에 넣고, 달마다 결과를 점검할 계획을 세운다
ㄹ 두 표의 열과 건수를 살피고 빈칸과 이상한 값이 있는지 확인한다
ㅁ 의사결정나무와 로지스틱 회귀를 만들어 검증용 자료에서 맞힌 비율을 견준다
ㅂ 고른 모형이 재구매율 향상이라는 처음 목적에 쓸 만한지 판촉 담당자와 검토한다

이어서 빅데이터 분석 방법론의 태스크 다섯 개(데이터 스토어 설계, 탐색적 분석, 프로젝트 위험 계획 수립, 시스템 테스트 및 운영, 모델 발전 계획 수립)를 다섯 단계에 하나씩 놓는다.

  • 확인 4 여섯 활동에 여섯 단계가 한 번씩 쓰였고, 단계의 순서대로 늘어놓은 결과가 ㄴ, ㄹ, ㄱ, ㅁ, ㅂ, ㄷ이다.
  • 확인 5 다섯 태스크가 빅데이터 분석 방법론의 다섯 단계에 하나씩 놓였다.

해석. ㅁ은 검증용 자료에서 맞힌 비율이라는 데이터의 기준으로 모형을 견주므로 모델링 단계의 모델 평가이고, ㅂ은 업무 목적에 쓸 만한지를 판단하므로 평가 단계다. 단계는 활동의 이름에 든 낱말이 아니라 무엇을 기준으로 판단하고 무엇을 남기는가로 정한다.

3. 분석 과제 발굴

배경과 쓰임

「인공지능 및 데이터 기반 행정 활성화에 관한 법률」 제20조의 분석센터가 받는 과제는 대개 “이 정책을 계속할 것인가”처럼 문제가 먼저 정해진 채로 들어온다. 한편 CRISP-DM 안내서는 데이터 이해 단계의 일에 “숨은 정보에 관한 가설을 세울 만한 흥미로운 부분 집합을 찾는 것”을 넣는다. 과제는 위에서 내려오기도 하고 데이터에서 올라오기도 한다.

3.1 하향식 접근과 상향식 접근

구분 하향식 접근(Top-Down Approach) 상향식 접근(Bottom-Up Approach)
출발점 풀어야 할 문제 가지고 있는 데이터
쓰는 때 문제가 분명히 주어져 있을 때 문제를 정의하기 어려울 때
물음의 관점 왜(Why) 그런 일이 생기는가 무엇이(What) 데이터에 있는가
진행 문제 탐색 → 문제 정의 → 해결 방안 탐색 → 타당성 검토 데이터를 먼저 살피고, 결과를 보며 문제를 찾아 고쳐 나간다
주로 쓰는 분석 정의한 문제에 맞추어 해결 방안 탐색에서 고른 분석 목표 값이 없는 분석. 비지도 학습이 대표적이다
어울리는 분석 주제의 유형 분석 대상이 정해진 경우(최적화, 솔루션) 분석 대상 자체를 찾는 경우(통찰, 발견)

실제 과제 발굴에서는 두 접근을 섞어 쓴다. 가능한 방안을 넓게 찾는 발산(Diverge)의 단계는 상향식, 그 가운데 고르고 검증하는 수렴(Converge)의 단계는 하향식에 해당하며, 디자인 싱킹(Design Thinking)은 발산과 수렴을 되풀이하여 과제를 찾는다.

3.2 하향식 접근의 네 단계

순서 단계 하는 일
1 문제 탐색(Problem Discovery) 업무 전체를 빠짐없이 훑어 풀어야 할 문제를 찾아낸다. 해법보다 문제를 놓치지 않는 것이 중요하다
2 문제 정의(Problem Definition) 찾아낸 업무의 문제를 데이터의 문제로 바꾸어 정의한다
3 해결 방안 탐색(Solution Search) 정의한 문제를 풀 분석 기법과 시스템, 역량을 찾는다
4 타당성 검토(Feasibility Study) 경제적 타당성과 데이터·기술적 타당성을 검토하여 과제로 확정할지 정한다

3.3 문제 탐색

비즈니스 모델 기반 문제 탐색. 비즈니스 모델을 업무, 제품, 고객의 세 단위로 단순화하고, 이를 관리하는 규제와 감사, 지원 인프라를 더한 다섯 영역에서 문제를 찾는다.

영역 살피는 것
업무(Operation) 제품과 서비스를 만들고 제공하기 위한 내부 프로세스와 주요 자원
제품(Product) 생산하고 제공하는 제품과 서비스의 개선
고객(Customer) 제품과 서비스를 받는 고객, 그리고 고객에게 닿는 채널
규제와 감사(Regulation & Audit) 제품의 생산과 전달 과정에서 생기는 규제와 보안
지원 인프라(IT & Human Resource) 분석을 수행하는 시스템과 이를 운영하는 인력

새로운 문제를 찾으려면 탐색의 범위를 거시적 관점(사회, 기술, 경제, 환경, 정치의 변화, STEEP), 경쟁자 확대 관점(대체재, 경쟁자, 신규 진입자), 시장의 요구 탐색 관점(고객, 채널, 영향자), 역량의 재해석 관점(내부 역량, 협력사와 네트워크)으로 넓힌다.

외부 참조 모델 기반 문제 탐색. 같은 업종이나 비슷한 업종의 분석 사례를 견주어(벤치마킹) 자기 회사에 적용할 과제를 빠르게 찾는다. 분석 유스케이스 정의. 찾아낸 문제를 문제의 상황, 해결했을 때의 효과와 함께 적어 문제 정의의 입력으로 삼는다.

3.4 문제 정의, 해결 방안 탐색, 타당성 검토

문제 정의. 업무의 문제를 데이터의 문제로 바꾼다. 예를 들어 “간편결제 할인을 계속할지 정해야 한다”는 업무의 문제는 “간편결제 거래와 카드 거래의 건당 금액 평균이 다른지 검정한다”는 데이터의 문제가 된다.

해결 방안 탐색. 지금의 시스템으로 분석할 수 있는가, 분석 역량을 가지고 있는가에 따라 방안이 넷으로 갈린다.

분석 역량이 있다 분석 역량이 없다
기존 시스템으로 가능하다 기존 시스템을 개선하여 활용한다 교육과 채용으로 역량을 확보한다
새 기법과 시스템이 필요하다 시스템을 고도화한다 전문 업체에 맡긴다

타당성 검토. 경제적 타당성(비용 대비 편익)과 데이터 및 기술적 타당성(데이터, 분석 시스템의 환경, 분석 역량)을 검토하고, 결과를 해석할 때의 한계도 적는다. 예컨대 결제수단마다 사는 품목군이 다르면 금액의 차이를 결제수단의 탓으로 돌릴 수 없다.

3.5 상향식 접근

문제가 분명하지 않으면 하향식 접근의 문제 탐색부터 막힌다. 상향식 접근은 가지고 있는 데이터를 먼저 분석하고 그 결과에서 문제를 찾아 고쳐 나간다. 분석은 주로 목표 값을 정하지 않고 데이터의 결합, 연관성, 유사성을 살피는 비지도 학습(군집 분석, 연관 분석)으로 하며, 목표 값을 맞히는 지도 학습(분류, 회귀)과 구분한다. 원인을 따지기 전에 함께 나타나는 것을 먼저 찾는다는 점에서 교재 01의 3절에서 본 “인과 관계에서 상관 관계로”와 이어진다.

프로토타이핑 접근법은 일단 분석을 시도하고 결과를 확인하며 반복하여 고쳐 나가는 방법으로, 완전하지 않더라도 신속하게 모형을 만들어 보여 사용자가 문제를 더 분명히 알게 한다. 필요한 까닭은 셋이다.

까닭 내용
문제에 대한 인식 수준 문제를 정확히 알지 못하거나 새로운 문제일 때, 시험용 모형으로 문제를 이해하고 구체화한다
필요 데이터 존재 여부의 불확실성 필요한 데이터가 있는지 불확실할 때, 대체할 데이터를 사용자와 반복하여 협의한다
데이터 사용 목적의 가변성 데이터의 가치는 처음 정한 목적에 고정되지 않는다. 쓰임이 바뀌거나 넓어질 수 있다

프로토타이핑은 가설의 생성 → 디자인에 대한 실험 → 실제 환경에서의 테스트 → 테스트 결과에서 통찰 도출과 가설 확인의 순서를 되풀이한다.

3.6 분석 과제 정의서

찾은 과제는 분석 과제 정의서로 정리한다. 정의서는 과제의 내용을 한곳에 적은 문서이며 프로젝트 수행 계획의 입력으로 쓰인다.

항목 내용
소스 데이터 분석에 쓰는 데이터와 그 출처
분석 방법 적용할 분석 기법
데이터 입수와 분석의 난이도 데이터를 구하기 쉬운가, 분석이 어려운가
분석 수행 주기 한 번 하는 분석인가, 주기적으로 되풀이하는가
분석 결과의 검증 책임 결과가 맞는지를 누가 확인하는가(검증 오너십)
상세 분석 과정 분석을 진행하는 구체적인 절차

따라 하기

예상. 아래 사례 가운데 분석 방법의 이름(연관 분석, 군집 분석)이 든 나와 라를 방법의 이름만으로 상향식이라고 할 수 있을지 먼저 적는다.

실행. 사례마다 “문제가 먼저 주어졌는가”에 답하여 접근을 정하고, 하향식이면 비즈니스 모델의 다섯 영역 가운데 어디인지 적는다.

사례 상황
가 경영 회의에서 “가전의 반품률을 낮추라”는 지시가 내려와, 반품의 원인이 될 만한 것을 목록으로 만든다
나 쌓인 거래 내역을 연관 분석으로 살피다가, 도서와 식품이 같은 날 함께 팔리는 경우가 많은 것을 보고 묶음 판촉을 과제로 삼는다
다 주문이 몰린 달에 서버가 멈춘 일이 있어, 접속량을 예측하여 증설 시점을 정하는 과제를 세운다
라 정해 둔 과제 없이 고객 표와 거래 내역을 군집 분석으로 묶어 보며 집단마다 특징을 적는다
  • 확인 6 네 사례가 하향식 둘(가, 다), 상향식 둘(나, 라)로 나뉘었고, 사례마다 “문제가 먼저 주어졌는가”의 답을 적었다.
  • 확인 7 하향식의 두 사례에 다섯 영역 가운데 하나씩(제품, 지원 인프라)을 붙였다.

해석. 사례 나는 연관 분석을 쓰지만 과제가 분석의 결과에서 나왔으므로 상향식이다. 하향식도 문제를 정의한 뒤에는 데이터를 분석하므로, 접근을 가르는 것은 방법의 이름이 아니라 출발점이다.

4. 분석 프로젝트 관리

배경과 쓰임

분석 프로젝트는 결과가 데이터에 달려 있어 시작할 때 결과를 장담할 수 없다. CRISP-DM 안내서가 상황 파악의 산출물에 ’위험과 대응책’을 넣고, 빅데이터 분석 방법론이 분석 기획 단계에 ’프로젝트 위험 계획 수립’을 둔 것도 이 때문이다.

4.1 분석 과제의 관리 영역

분석 프로젝트는 범위, 일정, 품질, 위험, 의사소통 같은 일반적인 관리 항목에 더하여 분석 과제에만 있는 다섯 영역을 관리한다.

영역 관리하는 것
데이터 크기(Data Size) 분석할 데이터의 양. 양에 따라 저장과 처리의 방식이 달라진다
데이터 복잡도(Data Complexity) 데이터의 유형과 출처의 다양함. 정형 데이터만 쓰는가, 비정형 데이터와 여러 시스템의 데이터를 합치는가
속도(Speed) 분석 결과가 필요한 시점. 모아서 처리해도 되는가, 실시간으로 처리해야 하는가
분석 복잡도(Analytic Complexity) 모형의 복잡함. 모형이 복잡할수록 정확도는 오르지만 해석하기 어려워진다
정확도와 정밀도(Accuracy & Precision) 정확도는 모형의 결과와 실제 값의 차이가 작은 정도다. 정밀도는 모형을 되풀이해 썼을 때 결과가 흩어지는 정도가 작은 것, 곧 일관성이다

분석 복잡도와 정확도는 상충 관계에 있으므로 해석할 수 있으면서 정확도가 충분한 모형을 찾는다. 정확도와 정밀도도 상충하는 경우가 많으며, 분석 결과를 활용하는 측면에서는 정확도가, 모형의 안정성 측면에서는 정밀도가 중요하다.

4.3 프로젝트 관리의 주제 그룹

프로젝트 관리의 국제 표준인 ISO 21500은 관리할 주제를 열 개의 주제 그룹으로 나누고, 관리의 진행을 착수, 기획, 실행, 통제, 종료의 다섯 프로세스 그룹으로 나눈다.

주제 그룹 분석 프로젝트에서 유의할 점
통합(Integration) 여러 관리 프로세스를 하나로 묶어 운영한다
이해관계자(Stakeholder) 데이터, 업무, 분석, 시스템의 전문가가 참여하므로 식별하고 관리한다
범위(Scope) 데이터의 형태와 양, 적용하는 알고리즘에 따라 범위가 자주 바뀐다. 결과물이 보고서인지 시스템인지를 미리 정해 둔다
자원(Resource) 분석 전문가가 부족하므로 인력의 확보 방안을 미리 검토한다
시간(Time) 의도한 결과가 한 번에 나오지 않아 반복이 많다. 기간을 정해 두고 그 안에서 할 일을 조정하는 타임 박싱(Time Boxing)으로 관리한다
원가(Cost) 외부 데이터를 사 오거나 상용 도구를 쓰면 비용이 크게 든다. 사전에 조사한다
리스크(Risk) 데이터를 확보하지 못하거나 알고리즘의 한계로 결과가 나오지 않을 위험에 대응한다
품질(Quality) 품질 목표를 정하고 품질 통제와 품질 보증으로 나누어 수행한다
조달(Procurement) 외부 자원을 적절히 쓴다. 시험적인 분석에는 장비를 사기보다 빌려 쓰는 방식을 검토한다
의사소통(Communication) 분석 결과를 이해관계자 모두가 이해할 수 있는 형태로 공유한다

통제는 프로세스 그룹이며 주제 그룹이 아니다.

절차

단계 1. 과제의 선택과 업무 이해 칸

  1. 과제 후보 하나를 고르고 1번(과제 이름)과 2번(배경과 업무 목적)을 쓴다.

  3. 분석 대상과 분석 방법을 각각 아는지 판단하여 4번에 유형과 근거를 쓴다.
  • 확인 9 3번이 데이터의 말(열 이름이나 집계, 비교, 분류 같은 방법의 말)로 적혔고, 4번의 유형과 두 물음의 답이 1.2절의 표와 맞는다.

단계 2. 데이터 이해와 데이터 준비 칸

  1. 3번의 물음에 답하는 데 필요한 열을 「준비」의 두 표에서 골라 5번에 쓴다.
  2. 6번에 자료의 건수와 기간, 품질에서 살필 점을 하나 이상 쓴다.
  3. 7번에 분석용 표의 한 줄이 무엇인지와 새로 만들 변수를 쓴다. 고객 단위로 하면 거래가 없는 고객 넷을 뺄지(56줄) 거래 횟수 0으로 둘지(60줄)를 함께 적는다.

단계 3. 모델링, 평가, 전개 칸

  1. 8번에 분석 방법을 배우는 장과 함께 쓴다.
  2. 9번에 업무 성공 기준(업무의 말)과 데이터 마이닝 성공 기준(데이터의 말)을 한 줄씩 쓰고 확인할 사람을 적는다(2.6절).
  3. 10번에 결과를 쓰는 곳과 다시 분석하는 주기를 쓴다.
  4. 11번에 이 자료로는 알 수 없는 것을 하나 이상 쓴다.
  • 확인 11 8번의 방법이 3번의 물음과 맞고, 9번에 두 성공 기준이 한 줄씩 구분되어 적혔다.
  • 확인 12 11번에 「준비」에 적힌 ‘이 자료에 없는 기록’ 가운데 하나 이상이 장애 요소로 적혔다.

  1. 옆 사람과 정의서를 바꾸어, 3번의 분석 목표가 5번의 열로 답할 수 있는 물음인지, 9번과 11번이 채워졌는지 확인한다.

빅데이터 분석 방법론의 데이터 준비를 분석용 데이터 세트를 만드는 단계로 안다 CRISP-DM의 데이터 준비와 이름이 같다 빅데이터 분석 방법론의 데이터 준비는 필요 데이터의 정의와 수집이다. 분석용 데이터 세트는 데이터 분석 단계에서 만든다
데이터를 쓰기만 하면 상향식이라고 판단한다 하향식 접근도 데이터를 쓴다는 점을 놓친다 출발점이 문제인지 데이터인지를 본다
관리 영역의 정밀도를 분류 모형의 정밀도로 읽는다 이름이 같다 이 장의 정밀도는 반복했을 때의 일관성이다. 교재 11의 정밀도는 양성으로 예측한 것 가운데 실제 양성의 비율이다

7. 연습 문제

서술형이다. 판단의 근거를 이 장의 절 번호와 함께 적는다. 정답과 채점 기준은 수업에서 확인한다.

연습 1. 상점의 판촉 담당자가 “계좌이체로 사는 고객이 적은데, 이 고객들을 위한 행사를 해야 할지 모르겠다”고 말하였다. (1) 이 말을 분석 과제 정의서의 3번(분석 목표)으로 쓸 수 있도록 학기 공통 자료의 열 이름이 들어간 물음 한 문장으로 바꾸어 쓴다. (2) 그 물음에 대하여 업무 성공 기준과 데이터 마이닝 성공 기준을 한 줄씩 쓴다. (3) 분석 주제의 유형을 정하고 두 물음의 답을 근거로 적는다.

연습 2. 경영 회의에서 “의류의 매출이 줄었다는데 원인을 찾으라”는 지시가 내려왔다. 하향식 접근의 네 단계(문제 탐색, 문제 정의, 해결 방안 탐색, 타당성 검토)에 따라 이 과제를 한 줄씩 전개한다. 타당성 검토의 줄에는 학기 공통 자료로 할 수 있는 것과 할 수 없는 것을 하나씩 적는다.
