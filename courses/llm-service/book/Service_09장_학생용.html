LLM 기능의 설계와 API 연동

2027학년도 「LLM 서비스 개발」의 준비 중인 교재입니다. 편집 상태를 검토하기 위해 미리 공개한 것으로, 수업 전에 내용과 순서가 바뀔 수 있습니다.

학사 11주차 · 교재 09 · 서비스 4: 문서 요약과 질의응답 (1/2)

개편 초안 2판(2026-11-18). 이 장은 옛 10장을 줄인 것이다. 키트는 새 장 번호의 Service_09장이고 작업 폴더는 ~/llm-service-lab/ch09/이다. 앞 장의 산출물 없이 시작한다. 이 장의 명령과 출력은 모두 2026-11-18에 Windows 11의 Git Bash와 Python 3.13.7에서 모의 모드(LLM_FAKE=1)로 실행해 얻은 것이다. 실제 모델의 호출(키가 필요한 것)은 실행하지 않았고 「실행 결과 자리」로 남겼다. 자료는 옛 구성의 가상 채용 공고 10건을 그대로 쓴다.

[최신 자료 자리: 서비스 4의 자료] 이 단원의 자료를 공개 API로 받은 문서(후보: 고용24 직업정보의 직업정보 상세와 직업사전)로 바꿀지 정하지 않았다. 개발명세서의 응답 항목을 확인한 뒤 정한다(plan/개편안.md 9절의 26, U9). 2026-11-18에는 가상 채용 공고를 쓴다.

8장에서 서버가 규칙을 판정하는 API를 만들었다. 이 장부터 두 주 동안 서버에 LLM을 붙인다. 서비스 4는 문서 요약과 질의응답이다. 이 장에서는 문서를 정해진 형식으로 요약하는 API를 만들고, 10장에서는 문서에 근거해 답하는 질의응답을 만든다. 이 장의 문서는 가상의 채용 공고이다. 긴 공고에서 핵심 업무, 자격 요건, 마감일, 주의점을 뽑아 정해진 형식으로 돌려준다.

LLM 기능을 서비스에 넣는 일은 채팅 창에 질문을 넣는 일과 성격이 다르다. 사용자가 버튼을 누를 때마다 우리 프로그램이 모델을 부르고, 호출마다 요금이 나가며, 모델의 답이 화면에 그대로 들어간다. 그래서 이 장은 구조(키는 어디에 있어야 하는가), 비용과 품질(월 비용의 계산과 환각을 막는 장치), 프롬프트의 관리(판본을 매기고 평가로 고르기)를 함께 다룬다.

이 장에서 만드는 것은 프롬프트 판본 세 개를 평가 문항 10개로 비교해 하나를 채택한 기록(ch09/docs/프롬프트비교.md)이다. 키가 저장소에 없다는 것은 검사 스크립트로 확인한다. 해결하는 문제는 점수만으로는 보이지 않는 오답의 원인을 응답 원문에서 찾는 것이다.

모든 실습은 모의 모드(LLM_FAKE=1)로 키 없이 끝까지 돌아간다. Claude Console에서 각자 키를 발급한 학생은 요청 한 번(tools/first_call.py)을 실제로 보내 볼 수 있다. 판본 비교처럼 호출을 수십 번 되풀이하는 측정은 교수가 시연하고 그 실행 기록을 배포한다. 키는 선택이다.

학습 목표

  • LLM 호출의 구조를 설명한다. 브라우저, 우리 API 서버, Claude API의 세 층에서 키가 서버에만 있어야 하는 까닭을 설명한다.
    • 예시: 키를 브라우저 코드에 넣으면 개발자 도구로 누구나 복사해 쓸 수 있고, 요금은 키 주인에게 청구된다.
    • 활용: 프로젝트실습에서 LLM 기능을 붙일 때 서버의 환경 변수에만 키를 둔다.
  • 비용과 품질을 숫자로 다룬다. 입력·출력 토큰 단가로 기능 하나의 월 비용을 추정하고, 환각을 줄이는 장치(근거 제한, 모르면 null, 형식 강제와 검증)를 고른다.
    • 예시: 사용자 300명이 하루 네 번 요약하면 월 3만 6천 호출이고, 판본에 따라 월 4.89달러와 6.23달러로 갈린다.
    • 활용: 기능을 제안할 때 월 비용의 어림을 함께 적는다.
  • 프롬프트를 판본으로 관리하고 평가로 고른다. 프롬프트를 파일로 두고 한 번에 한 가지씩 바꾼 판본을 만든 뒤, 규칙 기반 채점으로 비교해 채택한다.
    • 예시: v2에 예시 두 건만 더한 v3가 마감일 항목을 7/10에서 10/10으로 올렸다.
    • 활용: 프롬프트를 고칠 때마다 같은 문항으로 다시 재어 회귀를 막는다.
  • LLM 기능을 서버에 안전하게 둔다. FastAPI로 요약 API를 띄우고, 모델 출력을 신뢰하지 않는 입력으로 다루며, 키가 저장소에 없음을 검사한다.
    • 예시: 모델이 옮긴 문장에 <img onerror=…>가 섞여도 textContent로 넣으면 실행되지 않는다.
    • 활용: 커밋 전에 check_secrets.py를 돌리는 습관을 들인다.

1. LLM 호출의 구조

1-1. 세 층: 브라우저, 우리 서버, Claude API

2026년 2학기판에서는 학생이 실행한 파이썬 스크립트가 Claude API를 직접 불렀다. 프로그램을 실행하는 사람과 키를 가진 사람이 같았으므로 문제가 없었다. 웹 서비스에서는 다르다. 「요약 보기」 버튼을 누르는 사람은 불특정 다수이고, 그 사람의 브라우저에서 도는 자바스크립트는 누구나 열어 볼 수 있다. 그래서 LLM 기능은 세 층으로 나뉜다.

graph LR
    B["브라우저<br/>(키 없음)"] -->|"POST /api/summary<br/>{text: 공고 본문}"| S["우리 API 서버<br/>ch09/api (FastAPI)<br/>키: .env의 ANTHROPIC_API_KEY"]
    S -->|"Messages API 요청<br/>헤더에 키"| C["Claude API<br/>api.anthropic.com"]
    C -->|"content, usage,<br/>stop_reason"| S
    S -->|"검사한 요약 JSON"| B
층 하는 일 갖고 있는 비밀 사용자가 볼 수 있는가
브라우저 버튼, 상태 표시, 결과 그리기 없음 모두 볼 수 있다(개발자 도구로 코드와 요청을 연다)
우리 API 서버 입력 검사, 프롬프트 조립, 모델 호출, 출력 검사, 요청 제한, 캐시 API 키, 프롬프트 원문 볼 수 없다
Claude API 모델 실행, 토큰 계산, 요금 청구 모델 볼 수 없다

키가 브라우저 코드에 들어가면 누구나 개발자 도구에서 그 키를 복사할 수 있고, 그 키로 보낸 요청의 요금은 키 주인에게 청구된다. 서버가 가운데에 있으면 키는 서버의 환경 변수에만 있고, 브라우저는 우리 서버의 주소(/api/summary)만 안다. 길이 제한, 요청 횟수 제한, 형식 검사도 브라우저에 두면 사용자가 지워 버릴 수 있으므로 서버에 둔다. 이 장은 서버까지 만들고, 화면은 curl로 대신한다.

1-2. 모의 모드의 설계

이 장의 모든 코드는 api/llm.py의 complete() 함수 하나로만 모델을 부른다. 요약 API도, 판본 비교 실행기도, 요청 구조 보기 도구도 이 함수를 거친다. 그래서 모의 모드를 한 곳에서 켜고 끌 수 있다.

[파일: ch09/api/llm.py] (발췌)

def is_fake() -> bool:
    return os.environ.get("LLM_FAKE", "") == "1"

def complete(system, user, *, max_tokens=1024, json_schema=None, fake_text=None):
    request = build_request(system, user, max_tokens=max_tokens, json_schema=json_schema)
    if is_fake():
        if fake_text is None:
            from api.fake import fake_summary          # 공고의 칸을 규칙으로 옮겨 적는다
            fake_text = json.dumps(fake_summary(user), ensure_ascii=False)
        return LLMResult(text=fake_text, input_tokens=estimate_tokens(system + user),
                         output_tokens=estimate_tokens(fake_text), stop_reason="end_turn",
                         model=request["model"] + " (모의)", fake=True, request=request)
    return _call_real(request)

모의 모드에는 두 종류가 있다. 요약 API는 fake.py가 공고의 [주요 업무], [자격 요건], [접수 기간], [유의 사항] 칸을 규칙으로 옮겨 적은 요약을 낸다. 판본 비교 실행기는 eval/모의응답/에 미리 적어 둔 응답을 재생한다. 두 경우 모두 응답은 실제 모델의 출력이 아니다.

모의 모드로 확인할 수 있는 것은 코드의 흐름(요청의 모양, 오류 처리, 채점기의 동작)이다. 모델이 실제로 무엇을 내놓는가, 판본 사이의 실제 점수 차, 실제 토큰 수와 요금은 실제 호출로만 알 수 있다. 모의 모드의 토큰 수는 글자 수에 0.8을 곱한 어림값이다.

2. Messages API

2-1. 요청 하나, 응답 하나

Claude API에서 모델을 부르는 모든 기능은 하나의 주소 POST /v1/messages, 곧 Messages API를 거친다[A1]. 요약, 분류, 추출, 질의응답이 모두 이 주소로 가고, 다른 점은 요청에 무엇을 담는가뿐이다. 파이썬에서는 SDK의 client.messages.create(...)가 이 요청을 보낸다.

필수 항목 뜻 이 장의 값
model 어느 모델이 답할지 환경 변수 LLM_MODEL(기본 claude-haiku-5-5, 2026-11 기준)
max_tokens 출력 토큰의 상한. 답이 여기에 닿으면 중간에 끊긴다 1024
messages 대화의 목록. 각 칸은 role(user 또는 assistant)과 content 공고 본문이 든 user 한 칸

[최신 자료 자리: 기본 모델의 이름과 성질] LLM_MODEL의 기본값 claude-haiku-5-5, 이 모델의 사고 방식(적응형)과 기본 effort. 확인할 곳 https://platform.claude.com/docs/en/about-claude/models/overview. 2026-11-16의 값은 claude-haiku-5-5, 적응형 사고, 기본 effort medium이다.

선택 항목 가운데 이 장에서 쓰는 것은 둘이다. system은 모든 호출에 같이 적용할 지시(역할, 규칙, 출력 형식)이며 messages 밖의 별도 항목이므로, 공고 본문 안의 지시 같은 문장과 서비스의 규칙이 구분된다. output_config는 effort(생각의 깊이, 이 장은 low)와 format(구조화 출력의 스키마, 5절)을 담는다. 키트가 쓰는 API 버전 2026-10-21에서는 temperature, top_p, top_k 같은 샘플링 값을 보낼 수 없다[A9]. 그래서 같은 입력에 같은 답을 기대하는 일관성은 샘플링 값이 아니라 구조화 출력, 명확한 지시와 예시, 캐시, 평가로 설계한다.

응답에서 읽는 항목은 셋이다[A1]. content는 응답 블록의 목록이고 글 답은 type이 text인 블록에 있다. 사고 블록이 앞에 올 수 있으므로 위치가 아니라 type으로 고른다. usage는 input_tokens와 output_tokens로 요금 계산의 근거가 된다. stop_reason은 생성을 멈춘 이유이다(2026-11-14, API 참조 문서 기준).

stop_reason 뜻 요약 API의 처리
end_turn 모델이 자연스럽게 답을 끝냈다 정상
max_tokens max_tokens에 닿아 잘렸다 JSON이 끊기므로 형식 검사에서 실패한다(502)
refusal 안전 분류기가 요청을 거절했다 502와 「요약을 만들 수 없는 공고이다」
model_context_window_exceeded 모델의 컨텍스트 창을 넘었다 공고 길이를 6,000자로 제한해 막는다
stop_sequence, tool_use, pause_turn 멈춤 문자열, 도구 호출, 긴 차례의 일시 정지 쓰지 않는다

3. 토큰과 비용

3-1. 요금은 입력과 출력에 따로 붙는다

모델은 글자가 아니라 토큰 단위로 읽고 쓴다. 토큰은 모델이 쓰는 사전의 조각이며, 한국어 한 글자가 한 토큰이 되기도 하고 몇 글자가 한 토큰이 되기도 한다. 2026년판 5주차의 실측에서 같은 뜻의 인사말이 한국어로는 영어의 약 3배 토큰이었다.

호출 1회 요금 = input_tokens × 입력 단가 + output_tokens × 출력 단가
월 요금       = 호출 1회 요금 × 월 호출 수

단가는 모델마다 다르고, 출력 단가가 입력 단가보다 높다. 2026-11-14에 공식 가격표에서 확인한 값은 다음과 같다(100만 토큰당 달러)[A7].

모델 모델 이름(API) 입력 출력 비고
Claude Haiku 5.5 claude-haiku-5-5 0.10 0.50 프롬프트가 10만 토큰 이하일 때. 넘으면 0.50 / 2.50
Claude Haiku 4.5 claude-haiku-4-5 1 5 2026년 2학기에 쓴 모델
Claude Sonnet 5.5 claude-sonnet-5-5 2 10
Claude Opus 5.5 claude-opus-5-5 4 20

이 장의 기본 모델은 첫 줄이다. 공식 모델 목록은 Haiku 5.5를 분류, 추출처럼 양이 많고 빠른 응답이 필요한 일에 쓰는 모델로 소개한다[A4]. 공고 요약은 추출에 가깝다. 결과를 바로 받지 않아도 되는 일은 일괄 처리(Batch API)로 보내면 반값이고, 매번 같은 긴 시스템 프롬프트는 프롬프트 캐시로 읽으면 입력 단가의 10%이다[A7].

[최신 자료 자리: 모델 단가] 위 표의 단가, Haiku 5.5의 긴 프롬프트 기준(10만 토큰), 일괄 처리 할인, 캐시 읽기 배율. 확인할 곳 https://platform.claude.com/docs/en/about-claude/pricing. 2026-11-16에 다시 확인한 값은 표와 같고, 일괄 처리는 50% 할인, Haiku 5.5의 캐시 읽기는 100만 토큰당 0.01달러다.

3-2. 무제한 소비의 위험

OWASP는 LLM 응용의 10대 위험 가운데 하나로 「무제한 소비」(Unbounded Consumption. 2025년판 LLM10 / 2026년판 LLM06)를 꼽는다[A6][A6-26]. 사용량만큼 요금을 내는 구조를 노려 운영자에게 감당할 수 없는 비용을 지우는 공격을 「지갑 거부」(Denial of Wallet)라고 부른다. OWASP의 대책과 요약 API의 구현을 맞추어 보면 다음과 같다.

OWASP의 대책 요약 API의 구현 위치
입력 크기 제한 공고 본문 20~6,000자. 넘으면 422 api/schema.py의 SummaryRequest
요청 횟수 제한 접속지 하나에 1분 10회. 넘으면 429 api/app.py의 rate_limited()
출력 상한 max_tokens=1024 api/app.py
처리 시간 제한 SDK 요청 제한 시간 30초, 재시도 2회 api/llm.py의 _call_real()
반복 요청의 제거 같은 공고, 같은 판본, 같은 모델이면 저장한 결과를 돌려준다 api/app.py의 _cache
지출의 상한 키가 속한 작업 공간의 월 지출 한도 Claude Console

마지막 줄이 가장 바깥의 방어선이다. 코드의 제한이 모두 뚫려도 작업 공간의 한도에서 멈춘다. 그러나 한도에 닿으면 그 키를 쓰는 기능 전체가 멈추므로, 코드의 제한이 먼저 일해야 한다.

[그림 자리: Console의 작업 공간 사용 한도] Claude Console에서 작업 공간의 월 지출 한도를 정하는 화면(교수 시연용 계정으로 찍는다). 키 값과 조직 정보는 가리고 찍는다.

[최신 자료 자리: Console의 지출 한도 메뉴] 작업 공간의 지출 한도(spend limit)를 정하는 메뉴의 이름과 위치. 확인할 곳 https://platform.claude.com/. 2026-11-17 현재 확인하지 못하였다(부록 A-14-2와 같은 자리).

4. 환각

환각(hallucination)은 사실과 다르거나 주어진 자료와 맞지 않는 내용을 그럴듯하게 만들어 내는 현상이다[A10]. 모델은 “모른다”가 아니라 “다음에 올 법한 토큰”을 계산하므로, 자료에 없는 마감일을 물어도 그럴듯한 날짜를 만들어 낼 수 있다. 공고 요약에서 환각이 가장 위험한 자리는 셋이다. 마감일을 지어내거나 면접일을 마감일로 옮기면 사용자는 마감을 놓친다. 우대 사항을 필수 자격으로 옮기면 사용자는 지원할 수 있는데도 포기한다. 공고에 없는 연봉이나 정규직 전환 보장을 쓰면 사용자는 사실과 다른 기대로 지원한다.

키트의 모의 응답 v1에 이런 예가 들어 있다. P10 공고에는 연봉이 적혀 있지 않은데, v1의 모의 응답은 연봉을 말한다.

터미널 
grep -o '"P10": "[^"]*"' eval/모의응답/v1.json
grep -c "연봉" eval/공고/P10.txt
"P10": "정보보안 관제 요원 신입을 뽑는 공고입니다. 3교대 근무가 가능해야 하며 접수는 2027년 9월 3일까지입니다. 연봉은 업계 평균 수준으로 보입니다."
0

첫 명령은 v1의 P10 응답을, 둘째 명령은 공고 원문에서 「연봉」이 나온 줄의 수를 보인다. 이 응답은 수업용으로 만든 예시이지만, 모델이 실제로 이런 문장을 만들 수 있다는 점은 공식 문서가 인정한다. 공식 안내는 근거를 주고 “모르면 모른다고 말하게” 하는 대책들이 환각을 크게 줄이지만 없애지는 못하며, 중요한 정보는 늘 검증하라고 적는다[A10]. 이 장의 장치는 셋이다. 프롬프트로 근거를 공고 안으로 제한하고(6절), 마감일이 없으면 null을 쓰게 하며(5절), 평가 문항으로 그 장치가 통하는지 잰다(7절).

확인 5 v1의 P10 응답에 「연봉」이 있고, 공고 원문에서 「연봉」의 수가 0이다.

5. 구조화 출력

5-1. 왜 JSON으로 받는가

요약 결과는 사람이 읽기 전에 프로그램이 먼저 읽는다. 화면은 마감일을 따로 꺼내 강조하고, 자격 요건을 목록으로 그린다. 그러려면 응답이 이름(키)으로 값을 꺼낼 수 있는 JSON이어야 한다.

필드 타입 규칙
핵심업무 문자열 목록 1~5개. 공고의 주요 업무
자격요건 문자열 목록 필수 자격만. 우대 사항은 넣지 않는다
마감일 문자열 또는 null YYYY-MM-DD. 공고에 없거나 상시 채용이면 null
주의점 문자열 목록 지원자가 놓치기 쉬운 조건. 공고에 적힌 것만

프롬프트로 “JSON으로 답하라”고 지시하는 것만으로는 형식이 지켜지지 않는다. 2026년판 4주차의 실습에서 출력 형식만 JSON으로 바꾼 지시문은 20건 모두 코드 울타리(```)로 감싸여 채점기가 하나도 읽지 못했다.

5-2. 형식을 API로 강제하기

Claude API의 구조화 출력(structured outputs)은 JSON 스키마를 주면 응답이 그 스키마를 따르게 한다. 요청의 output_config.format에 type: "json_schema"와 스키마를 넣는다. 2026-11 기준 Haiku 5.5를 포함한 현행 모델이 이 기능을 지원한다[A3].

[파일: ch09/api/schema.py] (발췌)

SUMMARY_SCHEMA = {
    "type": "object",
    "properties": {
        "핵심업무": {"type": "array", "items": {"type": "string"},
                 "description": "공고에 적힌 주요 업무. 1~5개"},
        "자격요건": {"type": "array", "items": {"type": "string"},
                 "description": "필수 자격 요건. 우대 사항은 넣지 않는다"},
        "마감일": {"anyOf": [{"type": "string", "format": "date"}, {"type": "null"}],
                "description": "서류 접수 마감일(YYYY-MM-DD). 공고에 없거나 상시 채용이면 null"},
        "주의점": {"type": "array", "items": {"type": "string"},
                "description": "지원자가 놓치기 쉬운 조건. 공고에 적힌 것만"},
    },
    "required": list(FIELDS),
    "additionalProperties": False,
}

구조화 출력의 스키마에는 제약이 있다. 공식 문서가 밝힌 것 가운데 이 장과 관련된 것을 옮긴다[A3].

지원하는 것 지원하지 않는 것
기본 타입(object, array, string, integer, number, boolean, null) 재귀 스키마
enum, const, anyOf, required 숫자 제약(minimum, maximum)
문자열 형식 date, date-time, email, uri 등 문자열 길이 제약(minLength, maxLength)
additionalProperties: false(객체마다 반드시 이 값) 배열 길이 제약(minItems의 0과 1 외)

그래서 「핵심업무는 1~5개」 같은 개수 제약은 설명(description)으로만 전한다. 지원하지 않는 기능을 넣으면 400 오류가 난다. 형식을 설명하는 시스템 프롬프트가 더해지므로 입력 토큰도 는다[A3]. 형식은 이렇게 강제되지만 내용(마감일이 맞는가, 우대 사항이 섞였는가)은 강제되지 않는다. 그래서 서버는 응답을 Summary 모델로 다시 검사하고(8절), 내용은 평가 문항으로 잰다(7절).

[최신 자료 자리: 구조화 출력의 지원 모델과 스키마 제약] 지원 모델 목록과 위 표의 지원·미지원 항목. 확인할 곳 [A3]. 2026-11-14 집필 때의 문서 기준이다.

9. 출력의 안전한 표시

OWASP의 「부적절한 출력 처리」(Improper Output Handling. 2025년판 LLM05 / 2026년판 LLM10)는 LLM이 만든 글을 검증하지 않고 다른 구성 요소에 넘기는 문제이며, 대표적인 결과가 XSS이다. OWASP는 모델을 다른 사용자와 똑같이 취급하고 웹에 넣을 때 HTML 인코딩을 하라고 권한다[A6]. 공고 본문에는 누구든 무엇이든 적을 수 있고 모델은 그 문장을 요약에 옮기므로, 유의 사항 칸의 <img src=x onerror="...">가 요약의 주의점으로 옮겨질 수 있다. 화면에 글을 넣는 방법은 둘이다. element.innerHTML = 문자열은 문자열을 HTML로 해석해 요소를 만들고, element.textContent = 문자열은 해석하지 않고 글자 그대로 넣는다. MDN은 innerHTML을 XSS의 가장 흔한 통로로 꼽고, 사용자에게서 온 글이 단순한 글이어야 할 때는 textContent를 쓰라고 권한다[W1].

두 방법의 차이는 교수가 화면에서 시연한다. 8-1의 서버가 떠 있는 상태에서 브라우저로 자동 문서 http://127.0.0.1:8000/docs를 열고, 개발자 도구(F12)의 「콘솔」 탭에 다음을 넣는다. 시간이 남으면 직접 해 본다([선택]).

[브라우저] (개발자 도구의 콘솔)

const d = document.createElement("div"); document.body.append(d);
d.innerHTML = '<img src=x onerror="document.title=\'HACKED\'">';
// 탭 제목이 HACKED로 바뀐다. 새로 고침(F5) 뒤 같은 첫 줄과 다음 줄을 넣는다
d.textContent = '<img src=x onerror="document.title=\'HACKED\'">';

innerHTML로 넣으면 탭의 제목이 HACKED로 바뀐다. 글자를 넣었을 뿐인데 그 안의 코드가 실행된 것이다. 새로 고침 뒤 textContent로 넣으면 페이지 아래에 <img src=x ...>라는 글자가 그대로 보이고 탭 제목은 바뀌지 않는다. 새로 고침을 하는 까닭은 const d를 같은 페이지에서 두 번 선언하면 오류가 나기 때문이다.

[그림 자리: innerHTML과 textContent의 차이] 탭 제목이 HACKED로 바뀐 화면과, 같은 문자열이 글자 그대로 보이고 제목이 그대로인 화면. http://127.0.0.1:8000/docs의 개발자 도구 콘솔에서 찍는다.

모델 출력을 화면에 넣을 때의 원칙은 셋이다. 모델 출력은 textContent로만 넣고, 목록이 필요하면 document.createElement("li")로 요소를 만들어 그 요소의 textContent에 넣는다. 서버가 돌려준 오류 문구(detail)도 textContent로 넣는다. innerHTML, insertAdjacentHTML, document.write를 쓰지 않는다. 같은 원칙이 화면 밖에도 적용된다. 모델 출력을 데이터베이스 질의에 넣을 때는 매개변수화한 질의를 쓰고, 셸 명령에 넣지 않는다[A6].

docs/프롬프트비교.md를 VS Code에서 열어 1~6절의 「 」 자리를 채운다. 1절은 results/v3/metadata.json, 2절은 results/비교표.md, 3절은 판본 파일 머리의 바꾼 점과 비교표, 4절은 11-3에서 찾은 값과 공고의 칸 이름, 5절은 비교표와 cost_estimate.py의 결과에서 가져온다. 6절에는 모의 모드라는 것과 한 번 실행한 결과라는 것을 적는다.

채택 근거는 점수와 비용을 함께 적는다. 예를 들어 v3를 채택한다면 「마감일 10/10(v2는 7/10), 월 비용은 v2보다 약 1.3달러 많다(6.23 대 4.89달러, 월 3만 6천 건 가정)」처럼 쓴다. 마감일은 지원 여부를 바꾸는 필드이므로, 한 달 1.3달러로 마감일 오류 세 건을 없앤다면 받아들일 만하다는 판단이 붙는다. 이 판단은 숫자가 대신해 주지 않는다. 숫자는 판단의 근거를 보이게 할 뿐이다.

채택한 판본을 서비스에 적용한다. .env의 PROMPT_VERSION을 채택 판본으로 둔다. 키트의 기본값이 v3이므로 v3를 채택했으면 고칠 것이 없다. 다른 판본을 채택했으면 그 줄을 고치고 API 터미널에서 Ctrl+C로 서버를 끈 뒤 8-1의 명령으로 다시 띄운다.

정리

  • 키는 서버의 .env에만 있고, 브라우저는 우리 서버의 /api/summary만 부른다.
  • Messages API의 필수 항목은 model, max_tokens, messages이고, 응답의 블록은 type으로 고른다.
  • 요금은 입력과 출력 토큰에 각각 단가를 곱한 합이며, 모델 등급, 출력 길이, 반복 요청은 설계로 바꿀 수 있다.
  • 일관성은 샘플링 값이 아니라 구조화 출력, 지시와 예시, 캐시, 평가로 설계한다. 환각은 근거 제한과 「모르면 null」로 줄인다.
  • 형식은 API로 강제하고 서버에서 다시 검사하며, 내용은 평가 문항으로 잰다.
  • 판본은 한 번에 한 가지씩 바꾸고, 점수와 비용과 오답의 원문을 근거로 채택한다.
  • 모델 출력은 신뢰하지 않는 입력이므로 화면에는 textContent로만 넣는다.

개념 점검.

  1. 키를 브라우저 코드에 두면 안 되는 까닭을 요금과 관련지어 설명하라.
  2. stop_reason이 max_tokens일 때 요약 API가 502를 내는 까닭은 무엇인가.
  3. 구조화 출력으로 형식을 강제해도 평가 문항이 필요한 까닭은 무엇인가.
  4. v2와 v3의 비교가 「예시의 효과」를 보여 준다고 말할 수 있는 근거는 무엇인가.
  5. 합계 점수가 가장 높은 판본을 채택하기 전에 오답의 원문을 읽어야 하는 까닭은 무엇인가.
