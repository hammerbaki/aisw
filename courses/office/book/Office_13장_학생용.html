액세스 입문: 테이블과 쿼리

2027학년도 「컴퓨터활용」의 준비 중인 교재입니다. 편집 상태를 검토하기 위해 미리 공개한 것으로, 수업 전에 내용과 순서가 바뀔 수 있습니다.

학사 15주차 · 교재 13 · 5부 액세스 입문

본 장은 데이터베이스 프로그램인 액세스를 처음 다룬다. 1장에서 엑셀에 입력한 판매 자료 20행을 액세스의 테이블로 가져오고, 5장 「정렬, 필터, 차트」에서 필터로 수행한 선별(수량 30 이상)을 쿼리로 다시 수행하여 결과를 비교한다. 목적은 엑셀의 표와 데이터베이스의 테이블이 어떻게 다른지를 이해하는 것이며, 테이블 하나와 선택 쿼리 하나를 작성하는 데 그친다.

각 절 끝의 「따라 하기」는 2월 자료(판매_2026_02.xlsx, 19행)를 연습용 데이터베이스(연습_13_학번.accdb)로 가져와 수행하고, 5절의 핵심 실습은 1월 자료로 수행한다. 본 장의 기준 값과 동작은 실제 액세스(Microsoft 365, 한국어)에서 확인한 것이며 완성 파일 판매관리_13_완성.accdb와 같다.

수업 시간의 범위. 150분 수업에서는 번호를 붙인 절의 설명과 따라 하기, 핵심 실습까지 한다. 제목에 [선택]이 붙은 곳(3절의 「필드 속성」)과 심화 실습, 연습 문제는 시간이 남을 때나 수업 뒤에 한다.

학습 목표

  1. 엑셀의 표와 데이터베이스의 테이블의 차이를 데이터 형식, 기본 키, 자료와 화면의 분리라는 세 관점에서 설명한다.
  2. 빈 데이터베이스를 만들고 가져오기 마법사로 엑셀의 표를 테이블로 가져오며, 마법사의 화면마다 정해지는 것을 확인한다.
  3. 디자인 보기에서 필드의 데이터 형식과 기본 키를 읽고, 형식에 맞지 않는 값과 중복된 기본 키의 값이 거부되는 것을 확인한다.
  4. 조건 1개와 정렬을 포함하는 선택 쿼리를 작성하여 실행하고 저장하며, 디자인 눈금의 조건, 정렬, 표시 행이 결과의 행 수, 순서, 열을 각각 정한다는 것을 확인한다.
  5. 쿼리가 자료의 사본이 아니라 저장된 질의임을 테이블의 값을 변경하여 확인하고, 엑셀의 필터(5장)와 대조한다.

1. 엑셀의 표와 데이터베이스의 테이블

1-1. 데이터베이스와 액세스

데이터베이스는 여러 사람과 프로그램이 함께 사용할 수 있도록 일정한 규칙에 따라 저장한 자료의 모음이다. 엑셀은 수백 행 이하의 표를 한 사람이 다루는 데 적합하다. 자료가 수만 행으로 늘거나 여러 사람이 동시에 입력하면 자료의 형식과 중복을 프로그램이 관리하여야 하며, 이를 맡는 것이 데이터베이스 프로그램이다. 액세스는 개인용 PC의 데이터베이스 프로그램이다.

엑셀 액세스 의미
통합 문서(.xlsx) 데이터베이스(.accdb) 파일의 단위
시트(표) 테이블 자료를 행과 열로 저장한 것. 한 테이블에는 한 종류의 대상(판매 건)만 저장한다
열 필드 같은 종류의 값이 저장되는 세로 방향의 단위(예: 수량)
행 레코드 한 건의 자료(예: 판매번호 1001의 판매 건)
머리글 필드 이름 테이블의 구조에 속하는 이름. 레코드와 함께 정렬되거나 선별되지 않는다

1-2. 표와 테이블의 차이

구분 엑셀의 표 액세스의 테이블
열의 데이터 형식 셀마다 어떤 값이든 입력할 수 있다. 수량 열에 “많음”을 입력할 수 있다 필드마다 데이터 형식이 지정되며, 형식에 맞지 않는 값은 저장되지 않는다
행의 구별 행은 위치(행 번호)로 구별되며 정렬하면 달라진다. 같은 판매번호를 두 번 입력할 수 있다 레코드는 기본 키의 값으로 구별된다. 기본 키의 값은 중복되거나 비어 있을 수 없다
자료와 화면 한 시트에 자료, 수식, 서식, 요약 행이 함께 있고, 정렬과 필터는 표 자체를 변경한다 테이블에는 자료만 저장한다. 선별하고 정렬한 결과는 쿼리라는 별도의 개체로 조회하며 테이블은 변경되지 않는다

3장에서 수량 셀의 문자가 금액 수식의 #VALUE!로 드러났듯이, 엑셀은 잘못된 값을 받아들이고 계산의 단계에서 오류를 나타내지만 액세스는 입력의 단계에서 거부한다. 엑셀에서는 사용자가 자료의 규칙을 지켜야 하고, 액세스에서는 테이블이 규칙을 가지고 입력할 때마다 검사한다. 셋째 차이는 4절에서 확인한다.

1-3. 테이블에 적합한 표의 형태

본 장은 수강생의 통합 문서가 아니라 기준 파일을 가져온다. 사람이 읽도록 작성한 “판매내역” 시트를 그대로 가져오면 다음의 결과가 생긴다.

수강생의 통합 문서의 구성 그대로 가져올 경우의 결과
1행의 제목 제목이 첫 필드의 이름이 되고, 나머지 필드는 의미 없는 이름을 받는다
2행의 빈 행 값이 없는 레코드가 생긴다
3행의 머리글 머리글이 자료 한 건으로 저장되고, 숫자 열에 문자가 섞여 숫자 형식이 지정되지 못한다
25~29행의 요약 행 합계와 평균이 판매 건과 구별되지 않는 레코드가 된다
금액, 구성비, 목표 달성 열의 수식 계산된 값만 저장된다

데이터베이스에 적합한 표는 첫 행이 머리글이고 그 아래가 모두 자료인 표이다. 병합한 셀과 오류 값이 없고 한 열에 한 종류의 값만 있어야 한다. 지원 문서에 따르면 액세스는 원본의 처음 8개 행으로 필드의 데이터 형식을 정하므로, 처음 8개 행에 제목과 머리글이 든 통합 문서는 수량 열이 숫자로 추정되지 않는다. 기준 파일은 1행이 머리글, 2~21행이 자료이며, 8~10장의 파이썬 코드가 이 파일을 읽은 것도 같은 이유이다.

[그림 자리: 사람이 읽는 표와 프로그램이 읽는 표] 왼쪽에 수강생의 통합 문서(“판매내역” 시트의 1행 제목, 3행 머리글, 4~23행 자료, 25~29행 요약 행)를, 오른쪽에 기준 파일(1행 머리글, 2~21행 자료, 그 아래 빈 행)을 나란히 놓고, 왼쪽의 제목·빈 행·요약 행을 표시한 화면. 찍을 곳: Microsoft 365 엑셀, 판매현황_06_학번.xlsx와 판매_2026_01.xlsx를 나란히 연 창.

따라 하기

엑셀에서 두 파일의 형태를 비교하고, 엑셀의 표가 형식에 맞지 않는 값과 중복된 번호를 그대로 받아들이는 것을 확인한다. 같은 입력을 3절의 따라 하기에서 액세스에 다시 시도한다.

  1. 엑셀에서 컴퓨터활용\자료\판매_2026_02.xlsx를 열어 A1:F1의 머리글을 확인하고, A2:A20을 선택하여 상태 표시줄의 개수를 읽는다.
  2. 컴퓨터활용\실습\판매연습_06_학번.xlsx를 열어 “판매내역” 시트의 1행 제목, 3행 머리글, 4~22행 자료, 24~28행 요약 행을 확인한다.

2. 데이터베이스 파일과 개체

2-1. 액세스 파일과 개체

액세스의 파일(.accdb) 하나가 하나의 데이터베이스이며, 통합 문서가 여러 시트를 포함하듯이 여러 개체를 포함한다.

개체 역할 본 과목에서의 취급
테이블 자료를 저장한다 1개를 작성한다
쿼리 테이블에서 조건에 맞는 자료를 조회한다 선택 쿼리 1개를 작성한다
폼 자료를 입력하고 조회하는 화면을 구성한다 후속 과목에서 다룬다
보고서 자료를 인쇄 형태로 구성한다 후속 과목에서 다룬다

자료가 저장되는 개체는 테이블뿐이며, 나머지는 테이블의 자료를 조회하거나 표시하는 방법을 저장한다.

2-2. 화면의 구성

화면의 요소 위치와 역할 엑셀에서 대응하는 요소
탐색 창 화면 왼쪽. 개체의 목록이 종류별로 표시되며, 개체를 두 번 누르면 열린다 시트 탭
개체의 탭 화면 가운데의 위쪽. 열린 개체마다 탭이 있고, 탭을 마우스 오른쪽 단추로 눌러 저장하거나 닫는다 없다
레코드 탐색 영역 열린 테이블이나 쿼리의 아래쪽. 현재 레코드의 번호, 전체 레코드의 수, 이동 단추가 있다 상태 표시줄의 개수

본 장의 기준 값(레코드 20개, 쿼리 결과 8개)은 레코드 탐색 영역의 뒤의 숫자, 곧 전체 레코드의 수로 읽는다. 앞의 숫자는 커서가 놓인 레코드의 순번이다. 새 레코드를 입력하는 * 행은 전체 수에 들지 않는다.

[그림 자리: 액세스 화면의 세 영역] 액세스의 화면에서 왼쪽의 탐색 창(테이블과 쿼리의 목록), 가운데 위쪽의 개체 탭, 데이터시트 아래쪽의 레코드 탐색 영역(현재 레코드의 번호와 전체 레코드의 수, 이동 단추)에 번호를 붙여 표시한 화면. 찍을 곳: Microsoft 365 액세스, “판매내역” 테이블을 데이터시트 보기로 연 상태.

2-3. 빈 데이터베이스의 작성

빈 데이터베이스는 시작 화면의 [빈 데이터베이스]에서 파일 이름을 입력하고, 상자 옆의 폴더 모양 단추로 저장할 폴더를 지정한 뒤 [만들기]를 눌러 만든다. 폴더를 지정하지 않으면 상자 아래에 표시된 기본 폴더에 생성된다. 생성 직후에 열리는 빈 테이블 “테이블1”은 쓰지 않고 닫으며, 아무것도 입력하지 않고 닫으면 데이터베이스에 남지 않는다.

2-4. 저장 방식

구분 엑셀 액세스
파일 이름을 정하는 시점 작업한 뒤 저장하면서 정한다 데이터베이스를 만들 때 먼저 정한다
자료의 저장 사용자가 저장하여야 한다 다른 레코드로 이동하거나 테이블을 닫으면 즉시 저장된다. 저장 여부를 묻지 않는다
구조의 저장 구분이 없다 테이블의 설계, 쿼리의 내용, 열 너비 같은 레이아웃을 바꾸면 저장 여부를 묻는다
되돌리기 저장하지 않고 닫으면 파일을 연 시점으로 돌아간다 저장된 레코드는 닫는 방법으로 되돌릴 수 없다

입력하고 있는 값은 다른 레코드로 이동하기 전에 Esc로 취소한다. 한 번 누르면 현재 필드의, 두 번 누르면 그 레코드의 변경이 취소된다. 편집 중인 레코드의 왼쪽 끝에는 연필 모양의 표시가 있으며, 이 표시가 있는 동안은 아직 저장되지 않은 상태이다. 레코드를 즉시 저장하는 것은 여러 사람이 함께 쓰는 데이터베이스에서 다른 사용자가 최신의 자료를 조회하게 하기 위한 것이다.

따라 하기

  1. 액세스를 실행하고 시작 화면에서 [빈 데이터베이스]를 선택한다.
  2. 파일 이름에 연습_13_학번을 입력하고, 폴더 모양의 단추로 저장 위치를 컴퓨터활용\실습 폴더로 지정한 뒤 [만들기]를 누른다.
  3. 자동으로 열린 “테이블1”의 탭을 마우스 오른쪽 단추로 눌러 [닫기]를 선택한다.
  4. 액세스를 종료하지 않은 채 파일 탐색기에서 실습 폴더를 열어 연습_13_학번.accdb와, 같은 이름에 확장자가 .laccdb인 파일을 확인한다.

.laccdb는 잠금 파일이다. Microsoft의 문서에 따르면 공유 데이터베이스에서 어떤 레코드가 누구에 의해 잠겨 있는지를 확인하는 데 쓰이며, 마지막 사용자가 데이터베이스를 닫으면 삭제된다.

  • 확인 2 제목 표시줄에 연습_13_학번이 표시되고 탐색 창에 개체가 없다. 아무것도 저장하지 않았는데도 실습 폴더에 연습_13_학번.accdb가 있고, 액세스가 실행되어 있는 동안에는 .laccdb 파일이 함께 있다.

3. 엑셀 표의 가져오기

3-1. 가져오기와 연결

가져오기를 시작하면 첫 화면에서 자료를 저장하는 방법을 묻는다.

첫 화면의 항목 결과 본 과목
현재 데이터베이스의 새 테이블로 원본 데이터 가져오기 자료의 사본이 새 테이블로 저장된다. 이후 엑셀 파일과 테이블은 서로 무관하다 사용한다
다음 테이블에 레코드 복사본 추가 이미 있는 테이블의 끝에 레코드가 추가된다 사용하지 않는다
연결 테이블을 만들어 데이터 원본에 연결 자료는 엑셀 파일에 있고 연결 테이블이 이를 가리킨다. 액세스에서는 수정할 수 없다 사용하지 않는다

가져오기는 사본을 만들고 연결은 원본을 계속 참조한다는 점에서 7장의 붙여넣기 옵션과 같은 관계이다. 본 과목은 테이블에 형식과 기본 키를 지정하고 값을 입력해 보아야 하므로 가져오기만 사용한다.

3-2. 가져오기 마법사

엑셀의 표는 [외부 데이터] 탭 → [새 데이터 원본] → [파일에서] → [Excel]로 가져온다. 파일과 저장 방법을 고르면 가져오기 마법사가 첫 행의 처리, 필드별 옵션, 기본 키, 테이블 이름을 차례로 묻는다(3-3의 표). 기준 파일은 시트가 하나이므로 시트를 고르는 화면은 표시되지 않는다.

기본 키 화면에서 [Access에서 기본 키 추가]를 선택하면 액세스가 일련번호 필드(“ID”)를 새로 만들어 기본 키로 지정한다. 판매 자료에는 중복되지 않는 판매번호가 이미 있으므로 기본 키를 직접 선택하는 항목([기본 키 선택])에서 판매번호를 고른다. 마법사를 마친 뒤 가져오기 단계를 저장할 것인지 묻는 화면은 선택하지 않고 닫는다.

[그림 자리: 가져오기 마법사의 기본 키 화면] 가져오기 마법사의 기본 키 화면에서 세 선택지(액세스가 기본 키를 추가, 기본 키를 직접 선택, 기본 키 없음) 가운데 직접 선택하는 항목을 고르고 오른쪽 목록에서 판매번호를 지정한 모습. 찍을 곳: Microsoft 365 액세스, [외부 데이터] 탭 → [새 데이터 원본] → [파일에서] → [Excel]로 판매_2026_02.xlsx를 가져오는 마법사의 셋째 화면.

버전에 따른 차이: Access 2016에서는 [외부 데이터] 탭에서 [Excel]을 바로 누른다. 기본 키 화면의 둘째 항목은 버전에 따라 이름이 다르게 표시될 수 있으나, 목록에서 필드를 직접 고르는 항목이라는 점은 같다.

3-3. 마법사의 화면별 선택과 결과

마법사는 화면마다 테이블의 구조를 하나씩 정한다. 마친 뒤 테이블이 기대와 다르면 다음 표로 어느 화면에서 잘못 골랐는지를 찾는다.

화면 본 장에서의 선택 잘못 골랐을 때 테이블에 나타나는 결과
첫 화면(저장 방법) 새 테이블로 가져오기 연결: 아이콘에 화살표가 붙고 값을 수정할 수 없다. 추가: 기존 테이블의 레코드가 늘어난다
첫 행의 처리 [첫 행에 열 머리글이 있음]. 첫 행의 값이 필드 이름이 된다 필드 이름이 F1~F6이 되고 머리글이 레코드로 들어가 하나 많아진다

기본 키 직접 선택하여 판매번호를 지정한다 추가: “ID” 필드가 첫 필드로 생기고 판매번호는 기본 키가 아니다. 없음: 중복이 거부되지 않는다
테이블 이름 [테이블로 가져오기] 상자. 시트의 이름이 미리 들어 있다 같은 이름의 테이블이 있으면 덮어쓸 것인지 묻는다

필드 옵션 화면의 데이터 형식은 처음 8개 행으로 추정한 것이며, 실습 PC에서 1월과 2월의 기준 파일은 다음과 같이 지정되었다.

판매번호  숫자(필드 크기: 실수(Double))      숫자(실수(Double))

숫자 열이 정수가 아닌 실수(Double)가 되는 것은 엑셀이 셀의 숫자를 모두 배정밀도 부동 소수점 수(유효 숫자 15자리)로 저장하고, 액세스가 이를 같은 범위의 숫자 형식으로 받기 때문이다. 단가는 금액이므로 소수점 앞 15자리, 뒤 4자리까지를 반올림 없이 다루는 통화 형식으로 바꾼다. 단가가 모두 정수이므로 숫자로 두어도 값은 같으며, 완료 기준이 숫자를 인정하는 것은 이 때문이다.

원본의 값이 정해진 형식에 맞지 않으면 그 값은 빈 값으로 저장되고, 오류의 목록을 담은 테이블(오류, 필드, 행)이 탐색 창에 함께 생긴다. 기준 파일에서는 생기지 않으므로, 이 테이블이 보이면 다른 파일을 가져온 것이다.

3-4. 데이터 형식

데이터 형식은 필드에 저장할 수 있는 값의 종류이다. 본 과목은 네 가지를 쓴다.

데이터 형식 저장할 수 있는 값 “판매내역” 테이블의 필드
짧은 텍스트 255자 이내의 문자 거래처, 품목
숫자 숫자. 실수(Double)처럼 세부 종류로 표시될 수 있다 판매번호(기본 키), 수량
날짜/시간 날짜와 시각 판매일
통화 금액. 소수점 아래 넷째 자리까지 저장된다 단가

이 밖에 레코드마다 번호를 자동으로 매기는 일련 번호 형식이 있으며, 마법사가 추가하는 “ID” 필드가 이 형식이다. 엑셀의 통화 표시 형식은 값을 표시하는 방법이고, 액세스의 통화 형식은 저장할 수 있는 값의 종류이다.

형식이 지정된 필드에서는 첫째, 숫자 필드의 문자나 존재하지 않는 날짜가 입력하는 시점에 거부된다. 둘째, 숫자와 날짜가 크기 순으로 정렬된다. 2월 자료의 수량을 문자로 정렬하면 38의 다음에 4, 40, 41, 50, 6, 8의 순으로 놓인다. 셋째, 값이 모두 계산에 쓸 수 있는 수이다. 엑셀에서는 문자로 저장된 숫자가 합계에서 빠진다(1장).

3-5. 기본 키

기본 키는 레코드를 구별하는 필드이며 테이블마다 하나이다. 기본 키에는 같은 값을 두 레코드에 저장할 수 없고 값을 비워 둘 수 없다는 두 규칙이 적용된다.

4. 선택 쿼리

4-1. 쿼리의 의미

쿼리는 테이블의 자료에 대한 질의이며, 조건에 맞는 레코드를 골라 표시하는 쿼리를 선택 쿼리라고 한다. 쿼리에는 자료가 아니라 “어느 테이블에서, 어느 필드를, 어떤 조건과 순서로 표시하는가”라는 질의의 내용이 저장되며, 쿼리를 열면 그 시점의 테이블에 질의가 다시 적용된다. 이것이 1-2의 자료와 화면의 분리이다. 쿼리의 결과는 테이블을 들여다보는 창이므로 결과 화면에서 값을 수정하면 테이블이 바뀐다. 본 장에서는 결과 화면에서 값을 수정하지 않는다.

“수량 30 이상의 판매 건”을 매주 보고한다면, 엑셀에서는 매주 필터를 다시 지정하거나 결과를 복사하여야 하고 복사한 표는 그날의 자료로 고정된다. 쿼리는 한 번 저장해 두면 열 때마다 그날의 자료로 결과를 다시 만든다.

마지막 행에 대하여 지원 문서는 자료가 바뀐 뒤 필터를 다시 적용하면 다른 결과가 나타난다고 설명한다. 실습 PC에서 2월의 연습용 통합 문서에 수량 30 이상의 필터를 적용하고 판매번호 1030의 수량(E13)을 28로 바꾸자, 선별 결과는 11행 그대로였고 [다시 적용] 뒤에 10행이 되었다. 합계 G24는 바로 8,016,000에서 7,968,000으로 바뀌었다. 계산은 즉시, 선별은 다시 적용할 때 반영된다. 9장에서 같은 코드를 2월 자료에 다시 실행한 것처럼, 조건을 절차로 저장해 두면 같은 절차를 다시 수행할 수 있다.

>=30을 단가 열에 입력하면 모든 레코드가 선택된다. 쿼리는 [쿼리 디자인] 탭 → [결과] 그룹 → [실행]으로 실행하고, [홈] 탭 → [보기] 그룹 → [보기]의 화살표 → [디자인 보기]로 돌아가며, Ctrl + S로 이름을 붙여 저장한다.

[그림 자리: 쿼리의 디자인 보기] 쿼리의 디자인 보기에서 위쪽의 “판매내역” 필드 목록과 아래쪽의 디자인 눈금(필드, 테이블, 정렬, 표시, 조건, 또는 행)을 표시하고, 수량 열의 정렬 행에 내림차순, 조건 행에 >=30이 지정된 모습. 찍을 곳: Microsoft 365 액세스, [만들기] 탭 → [쿼리] 그룹 → [쿼리 디자인].

버전에 따른 차이: 테이블을 추가하는 화면은 버전에 따라 화면 오른쪽의 [테이블 추가] 창 또는 [테이블 표시] 대화 상자로 표시된다. 쿼리 디자인의 탭 이름은 [쿼리 디자인] 또는 [디자인]이다.

4-4. 조건의 표기

본 과목은 숫자의 비교와 문자의 일치만 다룬다. 결과는 2월 자료(“판매_02”, 19개의 레코드)에 적용한 것이다.

필드 조건 의미 결과
수량 >=30 30보다 크거나 같다 11개
수량 >30 30보다 크다 10개(수량이 30인 1030이 제외된다)
수량 >=40 40보다 크거나 같다 3개(1025, 1031, 1034)
수량 <10 10보다 작다 3개(1022, 1032, 1038)
수량 30 30과 같다 1개(1030)
거래처 "대한사무기" 값이 “대한사무기”와 같다 5개(1024, 1025, 1031, 1032, 1037)
품목 "토너" 값이 “토너”와 같다 3개(1022, 1032, 1038)
  • 크거나 같음은 >=, 작거나 같음은 <=로 쓰며 부등호를 먼저 입력한다. 5장의 필터에서 지정한 “크거나 같음, 30”이 >=30이다.
  • 숫자에는 쉼표, 단위, 큰따옴표를 붙이지 않는다. >=30개나 >=1,000은 숫자로 읽히지 않는다.
  • 문자의 조건은 Microsoft의 쿼리 조건 예제와 같이 큰따옴표로 묶어 입력한다("대한사무기", "A4 복사용지"). 빠뜨렸을 때 액세스가 붙여 주는지는 판에 따라 다를 수 있으므로(최신 자료 자리의 (7)) 처음부터 입력한다.
  • 문자의 조건은 값 전체와 같아야 한다. 거래처의 조건 "대한"의 결과는 0개이다(1월 자료도 0개).
  • 조건은 한 칸에 하나만 쓴다. 여러 조건은 후속 과목에서 다룬다.

수량 <10과 품목 "토너"의 결과가 같은 것은 토너의 수량이 두 달 모두 10 미만이기 때문이다(1월은 1003, 1005, 1011, 1018). 결과가 같아도 두 조건은 다른 질문이다.

4-5. 디자인 눈금의 변경과 결과

디자인 눈금의 조건은 결과의 행의 수를, 정렬은 행의 순서를, 표시는 보이는 열을 정하며, 각각 나머지를 바꾸지 않는다. 다음은 2월 자료의 쿼리 “수량30이상_02”(조건 >=30, 수량 내림차순, 다섯 필드 표시)에서 한 행씩 바꾸어 실습 PC에서 실행한 결과이다.

변경 결과의 행 수 결과의 순서(판매번호와 수량)
변경 없음(기준) 11 1025(50)이 첫 행, 1030(30)이 마지막 행
조건을 >=40으로 3 1025(50), 1031(41), 1034(40)

조건을 지움 19 1025(50)이 첫 행, 1038(4)이 마지막 행

4-6. SQL 보기

디자인 눈금의 내용은 액세스 내부에서 데이터베이스에 질의하는 표준 언어인 SQL의 문장으로 기록되며, 액세스의 모든 쿼리는 그 이면에서 SQL 문으로 처리된다. 쿼리를 연 상태에서 [홈] 탭 → [보기] 그룹 → [보기]의 화살표 → [SQL 보기]를 선택하면 SELECT로 시작하고 테이블의 이름(“판매내역”)과 배치한 필드의 이름이 든 문장이 보인다. 문장을 고치면 디자인 눈금도 바뀌므로 고치지 않는다. 본 과목은 이 문장을 핵심 실습에서 한 차례 확인하는 데 그치며, SQL 문의 작성은 후속 과목에서 다룬다.

  3. 수량 열의 [조건] 행에 >=30을 입력하고, [정렬] 행에서 내림차순을 선택한다.

(2) 조건과 정렬의 변경

  1. 디자인 보기로 돌아가 수량 열의 조건을 >=40으로 고치고 [실행]을 누른다.

단계 1. 데이터베이스 파일의 작성

  1. 컴퓨터활용\자료 폴더에 판매_2026_01.xlsx가 있는지 확인한다. 이 파일이 엑셀에서 열려 있으면 닫는다.

단계 3. 테이블의 확인

  2. [홈] 탭 → [보기] 그룹 → [보기]의 화살표 → [디자인 보기]를 선택하여 필드 6개의 데이터 형식이 3-4의 표와 일치하는지, 판매번호에 열쇠 표시가 있는지 확인한다.
  3. 같은 메뉴에서 [데이터시트 보기]로 돌아간다. 저장 여부를 물으면 [아니요]를 선택한다.
  4. 첫 레코드(판매번호 1001)의 수량 칸에 많음을 입력하고 Enter를 눌러 형식에 맞지 않는다는 안내를 확인한다. 텍스트로 변환하는 선택지는 고르지 않는다.

판매일과 단가의 표시(2026-01-02, 24000 또는 ₩24,000)는 형식 속성에 따른 것이며 판정에 영향이 없다.

  2. [테이블 추가] 창(버전에 따라 [테이블 표시] 대화 상자)에서 판매내역을 두 번 눌러 추가하고 창을 닫는다.

  5. 수량 열의 [정렬] 행을 눌러 내림차순을 선택한다.

빈번한 오류와 해결

「막힐 때」와 본문에서 다룬 증상은 싣지 않는다.

증상 원인 해결
다시 가져올 때 기존 테이블을 덮어쓸 것인지 묻는다 같은 이름의 테이블이 이미 있다 덮어쓰도록 선택한다
테이블 이름 앞에 화살표가 붙은 아이콘이 표시되고 값을 수정할 수 없다 가져오기의 첫 화면에서 연결을 선택하였다 연결 테이블을 삭제하고 새 테이블로 다시 가져온다. 연결 테이블을 삭제하여도 엑셀 파일은 남는다
수량 필드가 짧은 텍스트로 변경되었다 형식에 맞지 않는 값의 안내에서 텍스트로 변환하는 선택지를 눌렀다 디자인 보기에서 수량의 데이터 형식을 숫자로 변경하고 저장한다
값을 잘못 수정하였는데 닫아도 되돌려지지 않는다 다른 레코드로 이동한 시점에 이미 저장되었다(2-4) 원래의 값을 다시 입력한다. 1월 자료의 값은 1장의 원본 표에 있다
쿼리의 결과가 0행이거나 조건에 관한 오류가 표시된다 조건을 문자 열(거래처 등)에 입력하였거나, =>30처럼 기호의 순서를 바꾸었다 수량 열의 [조건] 행에 >=30을 다시 입력한다
파일을 다시 열면 보안 경고가 표시된다 액세스는 파일을 열 때 일부 기능을 차단한다 본인이 작성한 파일이면 경고 표시줄의 단추로 사용을 허용한다
탐색 창에 “테이블1”이 남아 있다 빈 테이블을 저장하였다 “테이블1”을 선택하고 Delete를 눌러 삭제한다

심화 실습

핵심 실습을 완료한 수강생은 조건의 대상을 문자 필드로 바꾼 선택 쿼리를 하나 더 작성한다.

  1. [쿼리 디자인]에서 “판매내역” 테이블을 추가하고 판매번호, 판매일, 거래처, 품목, 수량을 배치한다.
  2. 거래처 열의 [조건] 행에 "한빛상사"를 입력한다. 정렬은 지정하지 않는다.
  3. 실행하기 전에 결과의 행 수와 순서를 예상한다. 5장에서 거래처를 한빛상사로 선별한 결과는 5행이었다.
  4. 실행하여 결과가 5행(판매번호 1001, 1005, 1010, 1015, 1020)인지 확인한다. 실습 PC에서는 이 순서(판매번호 순)로 표시되었다.
  5. 쿼리를 한빛상사판매라는 이름으로 저장한다.

이어서 수량 열에 내림차순을 지정하여 첫 행(1020, 수량 32)을 확인하고 저장하지 않고 닫는다.

연습 문제

연습용 데이터베이스(연습_13_학번.accdb)에서 3월 자료(컴퓨터활용\자료\판매_2026_03.xlsx)로 수행한다. 절차는 제시하지 않는다. 결과가 기준 값과 일치하는지 스스로 점검한다. 각 문제의 끝에 실마리가 되는 절을 적었다.

문제 1. 3월 자료를 연습용 데이터베이스에 “판매_03”이라는 이름의 새 테이블로 가져온다. 기본 키는 판매번호로, 단가의 데이터 형식은 통화로 지정한다.

항목 기준 값
테이블 “판매_03”. 필드 6개
전체 레코드의 수 25
첫 레코드와 마지막 레코드의 판매번호 1040, 1064
기본 키 판매번호

실마리: 3절의 따라 하기 (1). 마법사의 첫 화면과 마지막 화면에서 고르는 것(3-3의 표)에 유의한다.

문제 2. “판매_03” 테이블에서 수량이 40 이상인 레코드를 수량의 내림차순으로 표시하는 선택 쿼리를 작성하여 “수량40이상_03”으로 저장한다. 표시하는 필드는 판매번호, 거래처, 품목, 수량이다.

항목 기준 값
결과의 레코드 수 3
결과의 순서 판매번호 1055(수량 59), 1053(수량 50), 1050(수량 44)

실마리: 4절의 따라 하기 (1)과 (2). 테이블을 추가하는 화면에서 고르는 테이블을 확인한다.

문제 3. “판매_03” 테이블에서 거래처가 서울오피스인 레코드를 판매번호의 오름차순으로 표시하는 선택 쿼리를 작성하여 “서울오피스_03”으로 저장한다. 결과에는 판매번호, 품목, 수량만 표시하고 거래처는 표시하지 않는다.

항목 기준 값
결과의 레코드 수 7
결과의 판매번호 1041, 1042, 1045, 1047, 1057, 1061, 1062
결과의 열 판매번호, 품목, 수량의 3개

실마리: 4-4의 문자 조건과 4절의 따라 하기 (6)의 표시 행. 조건에 쓰는 필드도 디자인 눈금에 배치하여야 한다.

개념 점검

  1. 엑셀의 통합 문서, 시트, 열, 행에 대응하는 액세스의 용어를 각각 제시하라.
  2. 필드에 데이터 형식이 지정되어 있을 때의 이점을 두 가지 기술하라.
  3. 기본 키로 지정된 필드에 적용되는 두 규칙을 제시하고, 판매 자료에서 거래처가 아닌 판매번호를 기본 키로 지정하는 이유를 기술하라.
  4. 엑셀에서 값을 잘못 수정한 경우와 액세스의 테이블에서 값을 잘못 수정하고 다른 레코드로 이동한 경우에, 저장하지 않고 닫았을 때의 결과는 각각 어떠한가.
  5. “수량30이상” 쿼리를 저장한 뒤 테이블에서 수량이 28인 레코드의 값을 30으로 수정하였다. 쿼리를 다시 열면 결과의 레코드 수는 어떻게 되는가. 그 이유를 쿼리에 저장되는 것이 무엇인지와 관련지어 기술하라.

정리

용어 의미
데이터베이스, 테이블 일정한 규칙에 따라 저장한 자료의 모음(.accdb 파일 하나)과, 그 안에서 자료를 필드와 레코드로 저장하는 개체
데이터 형식 필드에 저장할 수 있는 값의 종류. 값의 종류만 검사하고 범위는 검사하지 않는다
필드 속성 데이터 형식 안에서 필드의 세부 규칙을 정하는 항목(필드 크기, 형식, 필수, 인덱스 등)
기본 키, 인덱스 레코드를 구별하는 필드(값이 중복되거나 비어 있을 수 없다)와, 그 필드에 자동으로 만들어지는 중복 불가의 목록
가져오기, 연결 외부 자료의 사본을 테이블로 저장하는 기능과, 원본에 둔 채 참조하는 기능
선택 쿼리 조건에 맞는 레코드를 골라 표시하는 개체. 자료가 아니라 질의의 내용이 저장된다
