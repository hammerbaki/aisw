[12장] 생성형 AI를 활용한 파이썬 코드 작성

컴퓨터활용

12장

생성형 AI를 활용한 파이썬 코드 작성

2027학년도 「컴퓨터활용」의 준비 중인 교재입니다. 편집 상태를 검토하기 위해 미리 공개한 것으로, 수업 전에 내용과 순서가 바뀔 수 있습니다.

학사 14주차 · 교재 12 · 4부 바이브 코딩

본 장은 9~10장의 세 작업(거래처별 합계표의 저장, 월별 파일의 병합, 거래처별 분리)을 요구 명세서로 기술하여 생성형 AI가 파이썬 코드를 작성하게 하고, 실행 결과를 9~10장의 값과 대조하여 검증한다. 절차는 11장과 같다. 따라 하기(1~5절)는 2월 자료의 품목별 합계표로 한 차례 수행하고, 핵심 실습(6절)은 세 작업에 적용한다.

수업 시간의 범위. 150분 수업에서는 번호를 붙인 절의 설명과 따라 하기, 핵심 실습까지 한다. 심화 실습, 남은 연습 문제는 시간이 남을 때나 수업 뒤에 한다.

학습 목표

  1. 수식의 요청과 코드의 요청이 어떻게 다른지 설명한다.
  2. 목적, 입력, 처리 규칙, 출력, 검증 값, 제약으로 구성된 요구 명세서를 작성하고, 모호한 표현을 구체적인 표현으로 고쳐 쓴다.
  3. AI가 작성한 코드를 실행하기 전에 읽는 파일, 쓰는 폴더, 파일을 삭제하는 줄의 유무를 확인한다.
  4. 새 노트북에서 코드를 실행하고, 오류 메시지와 불일치한 값을 AI에게 전달하여 수정을 요청하고 그 내용을 기록한다.
  5. 실행 결과를 대조표로 검증하고, 코드의 각 부분을 9~10장의 코드와 대응시킨다.

준비 사항

항목 내용
실행 환경 학과 실습 사이트의 JupyterLab(부록 A)
자료 컴퓨터활용/자료 폴더의 월별 파일 12개(판매_2026_01.xlsx~판매_2026_12.xlsx). 시트 이름은 “판매내역”, 열은 판매번호, 판매일, 거래처, 품목, 수량, 단가의 6개이며 금액 열은 없다
선행 결과물 9~10장의 컴퓨터활용/결과 폴더. 본 장에서는 변경하지 않는다. 없어도 실습할 수 있다(기준 값은 본문에 있다)
AI 도구 11장에서 사용한 웹 기반의 대화형 AI 도구
작성 도구 메모장. 명세서는 컴퓨터활용\실습\연습_12_학번.txt(따라 하기)와 요구명세서_12_학번.txt(핵심 실습)

[최신 자료 자리: 실습 사이트의 판과 메뉴 이름] 실습 사이트의 JupyterLab, 파이썬, pandas, openpyxl의 판은 확인되지 않았다. 수업 전에 실습 사이트에서 JupyterLab의 판(도움말 메뉴의 정보 창)과, 노트북에서 실행한 pandas의 판을 확인하여 적는다. 본 장에 실은 출력은 Anaconda의 Python 3.14.6, pandas 3.0.3, openpyxl 3.1.5, IPython 9.15.0(윈도우)의 Jupyter 커널에서 2026-11-15에 실행하여 얻은 것이다. 2026-11-16에 PyPI에서 확인한 최신 안정판은 JupyterLab 4.6.6(2026-11-06 배포), pandas 3.1.1(2026-11-04 배포)이다(참고 자료 10, 11). 판이 다르면 오류 메시지의 가운데 부분(라이브러리 내부의 파일 이름과 줄 번호)이 달라질 수 있으나, 본 장에서 읽는 마지막 줄과 Cell In[…] 부분의 형태는 같다. 메뉴의 이름은 Launcher, [Rename], [Download], [Kernel] 메뉴 → [Restart Kernel and Run All Cells…]를 확인한다. 메뉴가 한국어로 표시되는 환경이면 대응하는 이름을 함께 적는다.

[최신 자료 자리: 학과가 지정한 AI 도구의 화면과 정책] 11장의 준비 사항과 같다. 새 대화의 시작, 대화 기록의 보관과 삭제, 입력 내용의 학습 활용과 거부 설정, 사용 한도를 수업 전에 해당 도구의 공식 도움말에서 확인한다. 코드를 다루는 본 장에서는 응답의 길이가 길어 사용 한도에 먼저 도달할 수 있으므로 한도의 값도 확인한다.

결과의 근거. 본 장의 코드 출력과 오류 메시지는 위의 환경에서 월별 파일 12개의 사본으로 실제로 실행한 출력이며, 줄인 곳은 밝혔다. 예로 든 코드는 교재가 9~10장의 형태로 작성한 것이고, AI의 응답은 재현되지 않으므로 싣지 않는다(11장 1-3).

1. 수식의 요청과 코드의 요청

1-1. 두 요청의 차이

구분 11장: 엑셀 수식 12장: 파이썬 코드
요청의 대상 한 셀에 입력하는 수식 한 줄 읽기, 계산, 집계, 저장으로 이어지는 여러 줄의 코드
AI에게 알려야 하는 것 시트 이름, 열 구성, 자료 범위 폴더와 파일 이름, 시트 이름, 열 구성, 처리의 순서, 저장할 위치와 형식
요청의 형태 몇 줄의 지시문 한 쪽 분량의 요구 명세서
실행하는 위치 엑셀의 셀 JupyterLab의 노트북
잘못되었을 때의 증상 오류 값 또는 값의 불일치 오류 메시지, 값의 불일치, 의도하지 않은 위치의 파일
검증의 수단 대조표 대조표

정할 사항이 많을수록 AI가 추측으로 채우는 부분도 늘어나므로, 코드의 요청에는 형식을 갖춘 문서가 필요하다.

1-2. 코드가 남기는 결과

틀린 수식은 지우면 흔적이 남지 않으나, 코드는 파일을 생성하고 같은 이름의 파일을 경고 없이 덮어쓴다(to_excel, 참고 자료 5). Ctrl + Z와 같은 취소의 수단은 없으며, 삭제하는 코드가 들어 있으면 파일이 지워진다. 그러므로 두 원칙을 지킨다.

  • 출력 폴더를 분리한다. AI의 코드는 결과_AI 폴더에 저장하게 하여, 기준이 되는 9~10장의 결과 폴더가 덮어쓰이지 않게 한다.
  • 실행하기 전에 코드를 확인한다(3-2).

2. 요구 명세서

2-1. 요구 명세서의 구성

요구 명세서는 코드가 무엇을 입력받아 어떻게 처리하고 무엇을 출력하여야 하는지를 기술한 문서이다. 11장 지시문의 맥락, 요청, 제약을 여섯 항목으로 세분한 것이다.

항목 기재하는 내용 11장의 지시문과의 대응
목적 코드가 수행하는 작업의 한 문장 요청
입력 폴더, 파일 이름, 시트 이름, 열 구성(없는 열도) 맥락
처리 규칙 계산과 집계를 순서대로 요청
출력 폴더, 파일 이름, 형식, 화면에 출력할 값 요청
검증 값 결과가 맞는지 판정하는 기준 값 (대조표의 수작업 결과)
제약 사용할 라이브러리, 실행 환경, 답의 형식 제약

AI 제품의 제공사는 순서나 누락이 중요한 지시를 번호 목록으로 제시하고 출력의 형식과 제약을 구체적으로 밝히도록 권고한다(참고 자료 7). 처리 규칙의 번호는 5절에서 코드의 줄과 대응시킬 때에도 쓴다.

2-2. 항목별 작성 기준

각 항목의 작성 기준과 고친 예(따라 하기의 작업)는 다음과 같다.

항목 작성 기준 모호한 표현 구체적인 표현
목적 결과물(표, 파일)이 드러나는 한 문장. 작업 하나에 결과물 하나 판매 자료를 정리한다 2월 판매 자료에서 품목별 금액 합계표를 만들어 엑셀 파일로 저장한다
입력 폴더, 파일, 시트, 머리글의 위치, 열의 이름을 실제와 한 글자도 다르지 않게. 없는 열도 쓴다 2월 판매 파일을 읽는다 폴더는 자료, 파일 이름은 판매_2026_02.xlsx, 시트 이름은 판매내역이다. 첫 행이 머리글이고 열은 판매번호, 판매일, 거래처, 품목, 수량, 단가의 6개이다. 금액 열은 없다

명세의 문장은 실행한 뒤에 “이 문장대로 되었는가”를 예 또는 아니오로 답할 수 있어야 한다. “정리한다”, “간단하게”는 그렇게 답할 수 없다. 또한 다음에 유의한다.

  • 입력은 월별 파일로 한다. read_excel은 따로 지정하지 않으면 첫 번째 시트의 첫 행을 머리글로 삼으며, xlsx 파일을 openpyxl로 읽는다(참고 자료 4). 제목 행과 요약 행이 있는 1~6장의 통합 문서는 입력으로 쓰지 않는다.
  • 화면에 출력할 값을 정한다. 정하지 않으면 대조할 값이 표시되지 않는다. 행 수는 머리글을 제외한 자료 행의 수로 정한다.
  • 이름과 학번을 쓰지 않는다. 명세서는 AI 도구에 그대로 입력된다(11장 2-5).

2-7. 모호한 문장의 수정

  1. 판정 질문을 만든다. “결과를 엑셀로 저장한다”는 “실행한 뒤에 엑셀 파일이 생겼는가”가 되지만, 폴더와 이름이 정해지지 않아 판정할 수 없다.
  2. 판정에 필요한데 빠진 것을 찾는다. 위의 예에서는 폴더 이름, 파일 이름, 파일 안의 열과 행이다.
  3. 빠진 것을 실제 이름과 숫자로 채운다. 조건에는 경계의 포함 여부를 쓰고, “많이”, “최근”, “깔끔하게” 같은 낱말은 숫자나 이름으로 바꾼다.
  4. 한 문장에 처리 하나만 남긴다. 그래야 5절에서 코드의 줄과 대응시킬 수 있다.

3-2. 실행하기 전의 확인

붙여 넣은 코드는 실행하기 전에 다음을 확인한다. 폴더와 파일의 이름은 따옴표 안에 문자 그대로 적혀 있으므로 문법을 몰라도 읽을 수 있다.

확인할 사항 코드에서 찾는 것 판단 기준
읽는 파일 read_excel이나 glob의 괄호 안의 따옴표 안 명세의 입력과 같은 폴더와 파일 이름인가
읽는 파일의 범위 glob의 괄호 안에서 *(어떤 문자열이든)의 앞뒤 글자 판매_2026_*.xlsx처럼 월별 파일만 고르는가. *.xlsx는 다른 파일까지 읽는다(3-3의 예 2)
쓰는 폴더 to_excel, savefig, makedirs, mkdir의 괄호 안 모든 경로가 결과_AI로 시작하는가. 결과/나 자료/로 시작하는 저장 경로가 없는가
파일을 삭제하는 줄 remove, unlink, rmtree 없어야 한다. 파일이나 폴더를 삭제하는 기능이다(참고 자료 6)
파일을 옮기는 줄 move 없어야 한다
검증 값의 숫자 4464000, 8016000 등 없어야 한다. 있으면 적어 넣은 값을 출력하는 코드일 수 있다

어긋나는 줄이 있으면 실행하지 않고, 그 줄이 하는 일을 물어 그 줄을 뺀 코드 전체를 다시 요청한다. 덮어쓰기는 쓰는 폴더의 확인으로 막는다. 이 확인은 명세의 범위 밖의 파일을 건드리지 않는지를 보며, 계산은 실행한 뒤에 대조표로 판정한다.

3-3. 실행 전 확인의 예

3-2의 표를 교재가 작성한 두 코드에 적용한다. 따옴표 안의 글자와 표의 낱말만 찾는다.

예 1. 쓰는 폴더가 어긋난 코드. 작업 1의 명세로 받은 코드가 다음과 같다고 하자.

import os
import pandas as pd

sales = pd.read_excel("자료/판매_2026_01.xlsx")
sales["금액"] = sales["수량"] * sales["단가"]
summary = sales.pivot_table(index="거래처", values="금액", aggfunc="sum")
print(summary)
os.makedirs("결과", exist_ok=True)
summary.to_excel("결과/거래처별합계_2026_01.xlsx")

3-2의 표를 적용한 기록은 다음과 같다.

읽는 파일   read_excel의 괄호 안: 자료/판매_2026_01.xlsx   → 명세의 입력과 같다
쓰는 폴더   makedirs의 괄호 안: 결과                         → 결과_AI가 아니다
            to_excel의 괄호 안: 결과/거래처별합계_2026_01.xlsx → 결과_AI가 아니다
삭제하는 줄 remove, unlink, rmtree                            → 없다
옮기는 줄   move                                              → 없다
검증 값     1756000, 6479000 등                               → 없다
판정        실행하지 않는다

계산은 맞으므로 대조표는 모두 “일치”가 될 것이다. 그러나 저장 경로가 9장의 결과와 같아 실행하는 순간 9장의 결과가 덮어쓰인다. 실행하지 않고 저장 경로를 결과_AI로 하라고 다시 요청한다.

예 2. 읽는 범위와 쓰는 폴더가 함께 어긋난 코드. 작업 2의 명세로 받은 코드이다.

from pathlib import Path
import pandas as pd

files = sorted(Path("자료").glob("*.xlsx"))
tables = []
for f in files:
    tables.append(pd.read_excel(f))
year = pd.concat(tables, ignore_index=True)
year["금액"] = year["수량"] * year["단가"]
print(len(files), "개 파일,", len(year), "행, 금액 합계", year["금액"].sum())
year.to_excel("자료/판매_2026_연간.xlsx", index=False)

glob의 괄호 안이 *.xlsx이므로 자료 폴더의 엑셀 파일을 모두 읽고, 저장 경로는 자료/로 시작한다. 실제로 두 번 실행한 출력은 다음과 같다.

12 개 파일, 266 행, 금액 합계 86611000
13 개 파일, 532 행, 금액 합계 173222000

첫 실행은 기준 값(266행, 86,611,000)과 일치한다. 그러나 이 실행이 자료 폴더에 판매_2026_연간.xlsx를 만들었으므로 두 번째 실행은 13개 파일을 읽어 정확히 2배가 된다. 명세에 “그 밖의 파일은 읽지 않는다”와 “자료 폴더에는 저장하지 않는다”가 있었는지 확인하고, 없으면 명세서를 고쳐 다시 요청한다.

두 예의 첫 실행은 대조표를 모두 통과한다. 대조표는 계산을, 실행 전의 확인은 파일을 판정하므로 하나로 다른 하나를 대신할 수 없다.

3-4. 실행 결과의 대조

실행한 뒤에는 두 곳에서 대조한다.

대조하는 곳 방법 발견할 수 있는 문제
화면의 출력 출력된 값을 대조표에 옮겨 기준 값과 비교한다 계산, 조건, 읽은 파일의 오류
생성된 파일 결과_AI의 파일 이름을 보고, 내려받은 파일의 값이 있는 열을 엑셀에서 선택하여 상태 표시줄의 개수와 합계를 읽는다 파일 이름, 저장 형식(총합계 행의 포함, 열의 누락)의 오류

화면의 값과 파일의 값은 코드의 다른 줄에서 만들어지므로 화면이 일치하여도 파일이 명세와 다를 수 있다. 파이썬의 출력에는 쉼표가 없으므로 대조표에는 쉼표를 넣어 옮긴다.

출력을 읽는 곳. 따라 하기의 작업을 9장의 형태로 작성한 코드의 출력이다. AI의 코드도 같거나 비슷한 모양이 된다.

첫 줄의 금액 합계를 낸 열의 이름 수량이나 단가이면 다른 열을 합한 것이다(4-3)
둘째 줄의 품목 행을 나눈 기준 처리 규칙 (2)의 “품목별”과 같은가

5-1. 수용 기준

AI가 작성한 코드는 결과가 기준 값과 일치하고, 코드의 각 부분이 수행하는 일을 설명할 수 있는 경우에 한하여 수용한다(11장의 수용 기준). 본 과목은 문법을 다루지 않으므로, 코드의 각 줄이 어느 단계에 속하는지를 지목할 수 있으면 기준을 충족한 것으로 본다.

5-2. 단계의 대응

9~10장의 코드는 다음의 단계로 구성되었다. AI의 코드도 표현은 달라도 같은 단계로 구성된다. 결과가 같은지는 대조표가 확인하고, 수강생은 그 줄이 어느 단계인지를 확인한다.
