부록

2027학년도 「비즈니스빅데이터분석」의 준비 중인 교재입니다. 편집 상태를 검토하기 위해 미리 공개한 것으로, 수업 전에 내용과 순서가 바뀔 수 있습니다.

「비즈니스 빅데이터 분석」 교재 공통 부록

부록은 다섯 부분으로 구성된다. A는 실습 환경, B는 시험 규정, C는 함수와 공식 문서의 위치, D는 장별 완료 기준, E는 수업에서 자주 나는 오류와 대처이다. 각 장의 강의안은 설치와 접속을 다루지 않고 부록 A를 가리킨다. 부록 B와 C는 시험에서 쓸 수 없는 참고 자료이므로, 시험 전에 내용을 익혀 두는 용도로 쓴다.

부록 A의 단계마다 붙은 [확인 N] 줄은 그 단계를 마친 뒤 자기 화면에서 보아야 할 값이나 모양이다. 확인이 화면과 다르면 다음 단계로 넘어가지 않고 부록 E에서 원인을 찾는다. 학기마다 바뀌는 값(학교 실습 환경과 시험 환경의 판, 시험 환경의 자원, 사전 환경점검의 기간)은 「최신 자료 자리」로 두었다. 자리 표시 안의 값은 확인한 날짜의 값이며, 수업 전에 다시 확인한다.

부록 A. 실습 환경

A.1 파일과 폴더의 구조

교재의 노트북과 실습 자료는 다음 구조로 배포된다. 학교 서버의 주소와 계정, 파일을 받는 방법은 강의에서 안내한다.

(교재 폴더)
└─ courses/aice/
    ├─ book/
    │   ├─ AICE_00주차_실습_학생용.ipynb      사전 진단
    │   ├─ AICE_01주차_실습_학생용.ipynb      교재 01의 실습 노트북
    │   ├─ ...
    │   └─ AICE_NN주차_학생용.md              강의안
    └─ kit/data/AICE_공통/
        ├─ customers.csv                      학기 공통 자료
        ├─ laptops.csv                        사전 진단, 시간 제한 문항(교재 01~06, 09)
        └─ loans.csv                          시간 제한 문항(교재 07~10)

모든 노트북은 자료 폴더의 위치를 첫 부분에서 변수 DATA에 저장하고, 파일 이름을 이어 붙여 읽는다.

DATA = "../kit/data/AICE_공통/"   # 자료 폴더의 위치
df = pd.read_csv(DATA + "customers.csv")

..은 한 단계 위의 폴더를 뜻한다. 노트북이 있는 courses/aice/book/에서 한 단계 올라가(courses/aice/) kit/data/AICE_공통/으로 내려가는 경로이다. 끝의 /는 뒤에 파일 이름을 이어 붙이기 위한 것이므로 빼지 않는다. 이 경로는 노트북과 자료가 위의 구조로 놓여 있을 때에만 맞다. 구조를 바꾸었으면 DATA 한 줄만 고친다.

놓인 상태 DATA의 값
위의 구조 그대로 "../kit/data/AICE_공통/"
노트북과 CSV를 같은 폴더에 두었다 "./"
Colab에서 파일을 올렸다(A.5) "/content/"
Colab에서 Google Drive를 연결하였다(A.5) "/content/drive/" 아래에서 CSV를 둔 폴더의 경로. Colab의 파일 패널에서 확인한다

경로 오류(FileNotFoundError)가 나면 노트북이 지금 어느 폴더에서 실행되고 있는지를 먼저 확인한다.

import os
print(os.getcwd())          # 지금의 폴더
print(os.listdir(DATA))     # DATA 폴더 안의 파일 목록

os.getcwd()의 출력은 노트북 파일이 있는 폴더여야 한다. 위의 구조라면 끝이 courses/aice/book(윈도우에서는 courses\aice\book)이다. os.listdir(DATA)가 FileNotFoundError를 내면 DATA 폴더 자체가 없는 것이고, 목록이 나오는데 파일 이름이 다르면 파일 이름의 철자를 고친다.

세 파일이 있는지는 파일을 열지 않고 다음 셀로 한 번에 확인할 수 있다. 사전 진단 노트북의 2절에 같은 셀이 있다(교재 00의 0.3절).

import os

for name in ["customers.csv", "laptops.csv", "loans.csv"]:
    print(name, os.path.exists(DATA + name))
  • 확인 1 os.getcwd()의 출력이 노트북이 있는 폴더로 끝난다.
  • 확인 2 위 셀의 출력 세 줄이 모두 True로 끝난다. False가 있으면 위의 표에서 자기 상태에 맞는 DATA를 고른다.

아래 셀은 일곱 라이브러리의 설치 여부와 판 번호를 한 번에 출력한다. 사전 진단 노트북의 1절에 같은 셀이 있다. importlib.metadata는 파이썬의 표준 라이브러리이므로 따로 설치할 것이 없고, 라이브러리를 실제로 불러오지 않으므로 빨리 끝난다.

from importlib.metadata import version, PackageNotFoundError

for name in ["numpy", "pandas", "matplotlib", "seaborn", "scikit-learn", "xgboost", "tensorflow"]:
    try:
        print(name, version(name))
    except PackageNotFoundError:
        print(name, "설치되어 있지 않다")
  • 확인 3 출력이 일곱 줄이고, 각 줄이 라이브러리 이름과 판 번호 또는 설치되어 있지 않다로 끝난다. 줄이 일곱보다 적으면 셀이 중간에 멈춘 것이므로 마지막 줄의 오류를 부록 E.1에서 찾는다.

version에는 불러오는 이름이 아니라 설치 이름을 준다. version("sklearn")처럼 불러오는 이름을 주면 scikit-learn이 설치되어 있어도 PackageNotFoundError: No package metadata was found for sklearn이 난다(교재의 실행 환경에서 확인하였다).

출력에서 설치되어 있지 않다가 나온 라이브러리를 A.3의 명령으로 설치한다. numpy, pandas, matplotlib, seaborn, scikit-learn은 2주차 전에, xgboost는 9주차 전에, tensorflow는 11주차 전에 갖추어 둔다. 이 셀은 설치 이름으로 찾으므로, TensorFlow를 tensorflow-cpu처럼 다른 이름으로 설치한 환경에서는 설치되어 있지 않다로 나올 수 있다. 그때에는 A.4의 셀로 확인한다.

A.4 TensorFlow가 동작하는지 확인하기

tensorflow를 설치한 뒤 아래 셀을 실행한다. 작은 신경망을 무작위 자료로 두 에폭 학습시키는 셀이다. 판 번호, Keras가 쓰는 계산 엔진(backend), 학습 완료: 2 에폭이 차례로 출력되면 9~10장의 실습을 할 수 있다.

import os
os.environ["KERAS_BACKEND"] = "tensorflow"   # Keras가 TensorFlow를 쓰도록 지정한다

import numpy as np
import tensorflow as tf
import keras

print("tensorflow", tf.__version__)
print("keras", keras.__version__, "backend", keras.config.backend())

X = np.random.rand(100, 4)
y = np.random.rand(100)
model = keras.Sequential([keras.Input(shape=(4,)), keras.layers.Dense(8, activation="relu"), keras.layers.Dense(1)])
model.compile(optimizer="adam", loss="mse")
history = model.fit(X, y, epochs=2, verbose=0)
print("학습 완료:", len(history.history["loss"]), "에폭")

TensorFlow를 불러올 때 계산 장치와 관련된 안내 문장(WARNING이나 I0000으로 시작하는 줄)이 함께 출력될 수 있다. 셀이 끝까지 실행되어 마지막 줄이 출력되면 문제가 없다. 처음 불러올 때에는 다른 라이브러리보다 시간이 오래 걸린다.

  • 확인 6 keras로 시작하는 줄의 끝이 backend tensorflow이고, 마지막 줄이 학습 완료: 2 에폭이다.

Keras의 backend 설정. Keras 3은 TensorFlow 외에 다른 계산 엔진도 쓸 수 있으며, 어느 엔진을 쓸지를 환경 변수 KERAS_BACKEND나 사용자 폴더의 설정 파일 ~/.keras/keras.json의 "backend" 값으로 정한다. 이 값이 tensorflow가 아니고 그 엔진이 설치되어 있지 않으면, import keras나 from tensorflow import keras를 실행할 때 ValueError: Unable to import backend : theano와 같은 오류가 난다(마지막 낱말은 설정 파일에 적힌 엔진의 이름이다). import tensorflow as tf만으로는 오류가 나지 않으므로, Keras를 처음 쓰는 순간에 오류를 만나게 된다. 다른 프로그램이 예전에 만든 설정 파일이 남아 있는 PC에서 이런 일이 생긴다.

설정은 다음 셀로 확인한다.

import os

print("KERAS_BACKEND:", os.environ.get("KERAS_BACKEND"))
path = os.path.join(os.path.expanduser("~"), ".keras", "keras.json")
print(path)

KERAS_BACKEND가 None이고 keras.json의 "backend"가 "tensorflow"가 아니면 다음 가운데 하나로 해결한다.

  1. 노트북에서 환경 변수를 지정한다. 노트북의 첫 셀에 os.environ["KERAS_BACKEND"] = "tensorflow"를 두고, Keras를 불러오기 전에 실행한다. 이미 Keras를 불러오다 오류가 났다면 커널을 다시 시작한 뒤 이 셀부터 실행한다. 위의 확인 셀이 이 방법을 쓴다.
  2. 설정 파일의 값을 고친다. keras.json의 "backend" 값을 "tensorflow"로 바꾸고 커널을 다시 시작한다. 같은 PC의 다른 프로그램이 그 파일을 쓰고 있을 수 있으므로, 자기 PC가 아니면 1의 방법을 쓴다.
  • 확인 7 위의 설정 확인 셀에서 KERAS_BACKEND가 tensorflow이거나, keras.json의 "backend"가 "tensorflow"이다. 둘 다 아니면 A.4의 확인 셀이 ValueError로 멈춘다.

수업과 시험에서 자주 나는 오류와 경고를 단계별로 모았다. 오류 메시지는 마지막 줄부터 읽는다. 마지막 줄의 콜론 앞이 오류의 이름이고, 뒤가 내용이다. 아래 메시지는 2026-11-14와 2026-11-15에 부록 A.2의 판(pandas 3.1.1, scikit-learn 1.9.1, matplotlib 3.11.2, keras 3.15.1)으로 실제로 실행하여 확인한 것이다. 열 이름과 숫자는 실행한 예의 값이므로 상황에 따라 달라진다. 판이 다르면 문구가 조금 다를 수 있다.

E.0 메시지를 읽는 순서

  1. 마지막 줄의 콜론 앞(오류의 이름)을 읽는다. 이름이 원인의 종류를 알려 준다. NameError는 이름이 아직 없다는 것, KeyError는 없는 열이나 키를 가리켰다는 것, ValueError는 값의 종류나 모양이 맞지 않는다는 것, TypeError는 함수가 아닌 것을 함수처럼 쓰거나 지원하지 않는 연산을 했다는 것, FileNotFoundError는 경로에 파일이 없다는 것이다.
  2. 콜론 뒤의 따옴표 안을 읽는다. 파이썬이 실제로 찾은 이름, 경로, 값이 그대로 나온다. 철자와 끝의 /는 여기에서 찾는다.
  3. 오류가 난 셀만 고칠지, 위의 셀을 다시 실행할지를 정한다. NameError와 같은 셀을 두 번 실행하여 생긴 KeyError는 셀의 코드가 아니라 실행 순서의 문제이다. 위에서부터 다시 실행한다.
  4. 아래 표에서 같은 이름의 행을 찾는다. 같은 이름의 행이 여럿이면 따옴표 안의 내용으로 고른다.

오류가 나지 않는데 값이 이상한 경우도 있다(E.2의 마지막 행들, E.4의 nan). 이런 경우는 셀 끝에 크기(shape)와 결측치 수를 출력해 두어야 알아차릴 수 있다.
