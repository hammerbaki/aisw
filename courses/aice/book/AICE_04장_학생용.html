머신러닝 모델은 숫자만 입력으로 받는다. Seoul, VIP, Card와 같은 글자 값이 남아 있으면 scikit-learn의 모델은 학습 단계에서 오류를 낸다. 시험지의 전처리 문항은 이 단계를 “지정한 열을 원핫 인코딩하라”, “범주 값을 통합한 뒤 변환하라”와 같은 가이드로 묻는다. 인코딩의 결과는 곧바로 분할과 모델링 문항의 입력이 되므로, 열을 하나 빠뜨리거나 목표 열까지 인코딩하면 뒤의 문항이 모두 영향을 받는다.

본 장은 범주형 열의 자료형을 확인하고, 표기가 섞인 값을 정리하여 통합한 뒤, 원핫 인코딩과 라벨 인코딩으로 숫자로 바꾸는 방법을 다룬다. 두 방법을 언제 쓰는지와 목표 열을 어떻게 다루는지도 함께 다룬다. 중심 실습에서는 3장의 정제본 df_clean을 인코딩하여 인코딩본 df_enc(2940행, 26열)를 만든다. df_enc는 5장(분할과 스케일링)부터 10장까지 모든 장의 출발점이다.

학습 목표

  1. 열의 자료형을 확인하고, 수치형 열과 범주형 열을 select_dtypes로 구분하며, astype으로 자료형을 바꾼다.
  2. 표기가 섞인 범주 값을 문자열 메서드와 replace로 정리하고, 빈도가 낮은 범주를 하나로 통합한다.
  3. map으로 이진 범주와 순서가 있는 범주를 정해진 정수로 바꾸고, 사전에 없는 값이 결측치가 되는 점을 확인한다.
  4. pd.get_dummies의 columns, drop_first, dtype 인자를 지정하여 원핫 인코딩하고, 인코딩 후의 열 수를 계산한다.
  5. LabelEncoder로 라벨 인코딩하고, 번호가 알파벳 순서로 매겨지는 점과 classes_, inverse_transform의 쓰임을 설명한다.
  6. 범주의 순서, 범주의 수, 목표 열 여부에 따라 인코딩 방법을 고르고, 목표 열을 입력과 따로 다룬다.

1. 자료형의 확인과 변환

1.1 dtypes로 자료형 확인

인코딩의 대상은 숫자가 아닌 열이다. 먼저 열마다 자료형을 확인한다. dtypes는 열 이름을 인덱스로, 자료형을 값으로 하는 시리즈이다. 괄호가 없는 속성이다.

str로 표시된 6개 열(gender, region, grade, app_user, payment, marketing_agree)이 글자로 된 범주형 열이다. 나머지 10개 열은 정수(int64)나 실수(float64)이다. churn은 0과 1로 된 정수 열이므로 이미 숫자이다. 이처럼 숫자로 저장되어 있어도 뜻이 범주인 열이 있다. 그런 열은 인코딩할 필요가 없지만, 모델의 입력으로 쓸지는 따로 판단한다.

dtypes의 맨 아래 dtype: object를 “모든 열이 object”로 잘못 읽는 경우가 많다. 이 줄은 출력된 시리즈의 값(자료형 이름)이 어떤 자료형으로 담겼는지를 말할 뿐이고, 각 열의 자료형은 위의 16줄에 있다.

1.2 select_dtypes에 의한 열 선택

select_dtypes는 자료형을 기준으로 열을 고른다. include에 고를 자료형을, exclude에 뺄 자료형을 준다. 둘 가운데 하나 이상을 지정해야 한다. "number"는 정수와 실수를 모두 포함하는 이름이다.

# [예제 3]
df_clean.select_dtypes(exclude="number").columns
Index(['gender', 'region', 'grade', 'app_user', 'payment', 'marketing_agree'], dtype='str')
# [예제 4]
df_clean.select_dtypes(include="number").columns
Index(['age', 'tenure_months', 'visits_per_month', 'avg_session_min', 'cart_items', 'coupon_use_rate',
       'cs_calls', 'last_login_days', 'annual_spend', 'churn'],
      dtype='str')

결과는 데이터프레임이므로 열 이름만 필요하면 .columns를 붙인다. 출력 끝의 dtype='str'은 열 이름(인덱스)의 자료형이다.

pandas 2.x를 쓰는 자료에서는 문자열 열을 고를 때 select_dtypes(include="object")라고 쓰는 경우가 많다. pandas 3.0부터 문자열 열의 기본 자료형이 object에서 str로 바뀌었기 때문에, 이 코드는 결과를 돌려주기는 하지만 경고를 낸다. 아래 셀은 그 경고를 화면에 출력하기 위하여 warnings 모듈로 기록한 것이다. 노트북에서 df_clean.select_dtypes(include="object")만 실행하면 같은 내용의 경고 상자가 출력된다.

# [예제 5]
import warnings

with warnings.catch_warnings(record=True) as w:
    warnings.simplefilter("always")
    cols = df_clean.select_dtypes(include="object").columns
print(list(cols))
print(w[0].category.__name__)
print(str(w[0].message).split(". ")[0])

경고의 종류는 Pandas4Warning이다. 다음 큰 판(pandas 4)에서 동작이 바뀐다는 예고이며, 지금은 하위 호환을 위하여 str 열을 포함해 준다는 뜻이다. 판에 관계없이 같은 결과를 얻으려면 exclude="number"를 쓴다. 본 교재의 코드는 모두 이 방식을 쓴다. 시험 환경의 pandas 판은 확인되지 않았으므로, 판에 의존하지 않는 쓰기 방식을 익혀 두는 것이 안전하다.

1.3 astype에 의한 변환

astype은 열의 자료형을 지정한 자료형으로 바꾼 새 시리즈를 돌려준다. 원래의 열은 바뀌지 않으므로 결과를 변수에 저장한다.

# [예제 6]
age_int = df_clean["age"].astype(int)
print(df_clean["age"].dtype, "->", age_int.dtype)
age_int.head(3)
float64 -> int64
0    30
1    43
2    25
Name: age, dtype: int64

age는 원본에 결측치가 있어 float64로 읽혔다(1장 3.2절). 3장에서 결측치를 중앙값으로 채웠으므로 이제 정수로 바꿀 수 있다. 결측치가 남아 있는 열을 astype(int)로 바꾸면 IntCastingNaNError가 난다. 정수로 바꾸기 전에 결측치 수를 확인하는 까닭이다.

  • 확인 5 첫 줄이 float64 -> int64이고, 앞 세 값이 30, 43, 25이다.

아래 셀은 결측치가 하나 있는 작은 시리즈를 정수로 바꾸려 한 것이다. 정수 자료형(int64)에는 결측치를 나타낼 자리가 없으므로 변환이 거부된다. 메시지는 결측치를 바꾸거나 지우라고 안내하고, 결측치를 담을 수 있는 정수 자료형(Int64, 대문자 I)을 대안으로 든다. 본 과목은 결측치를 먼저 처리하는 방식을 쓴다.

# [예제 9]
pd.Series([30.0, None, 41.0]).astype(int)
IntCastingNaNError: Cannot convert non-finite values (NA or inf) to integer. Replace or remove non-finite values or cast to an integer type that supports these values (e.g. 'Int64')

글자 값을 숫자로 바꾸는 일은 astype으로 할 수 없다. 글자 "VIP"가 어떤 정수인지 pandas는 알 수 없기 때문이다.

# [예제 7]
df_clean["grade"].astype(int)
ValueError: invalid literal for int() with base 10: 'VIP'

이 오류는 “인코딩이 필요하다”는 신호이다. 글자 범주를 숫자로 바꾸려면 2절의 map, 3절의 원핫 인코딩, 4절의 라벨 인코딩 가운데 하나를 쓴다. 반대 방향, 즉 숫자를 글자로 바꾸는 일은 astype(str)로 할 수 있다.

# [예제 8]
df_clean["churn"].astype(str).head(3)

2    1

2.2 문자열 정리: str.strip, str.title, str.lower

시리즈의 str 접근자는 문자열 메서드를 열 전체에 한 번에 적용한다. 파이썬 문자열의 메서드와 이름과 동작이 같다.

문자열 정리의 단계별 확인

정리는 여러 메서드를 이어 붙이므로, 어느 단계가 무엇을 해결하였는지 보이지 않는다. 단계마다 결과를 변수에 담고 고유값의 수를 세면 각 단계의 효과가 드러난다. 아래 셀의 step1~step3은 차례로 공백 제거, 대소문자 정리, 치환을 한 결과이다. 둘째 줄은 공백 제거를 빼고 대소문자만 정리한 경우이다.

# [예제 14]
raw = df_clean["region"]
step1 = raw.str.strip()
step2 = step1.str.title()
step3 = step2.replace({"Gyeonggi-Do": "Gyeonggi"})
print(raw.nunique(), step1.nunique(), step2.nunique(), step3.nunique())
print(raw.str.title().nunique())

2.3 replace에 의한 치환

replace는 지정한 값을 다른 값으로 바꾼다. {바꿀 값: 새 값}의 사전을 주면 여러 값을 한 번에 바꿀 수 있다. 사전에 없는 값은 그대로 남는다.

# [예제 15]
r = r.replace({"Gyeonggi-Do": "Gyeonggi"})
print(r.nunique())
9

Gyeonggi-Do를 Gyeonggi로 바꾸어 실제 지역 수와 같은 9개가 되었다. replace의 첫 인자에 리스트를 주고 둘째 인자에 값 하나를 주면, 리스트의 모든 값을 그 값 하나로 바꾼다. 2.4절에서 이 형식을 쓴다.

형식 예 뜻
값 하나 → 값 하나 s.replace("A", "B") A를 B로
사전 s.replace({"A": "B", "C": "D"}) A를 B로, C를 D로
리스트 → 값 하나 s.replace(["A", "C"], "Z") A와 C를 모두 Z로

2.4 빈도가 낮은 범주의 통합

회원 수가 적은 지역은 그대로 두면 원핫 인코딩 후에 1이 거의 없는 열이 된다. 그런 열은 모델이 학습할 근거가 적고 열의 수만 늘린다. 그래서 빈도가 기준보다 낮은 범주를 Other 같은 하나의 범주로 묶는다. 기준은 가이드가 정한다. 본 과목에서는 100명 미만으로 한다.

# [예제 16]
counts = r.value_counts()
rare = counts[counts < 100].index
print(list(rare))
r = r.replace(list(rare), "Other")
r.value_counts()

2.5 map에 의한 변환

map은 시리즈의 값마다 사전에서 짝을 찾아 바꾼다. 글자 범주를 정해진 정수로 바꿀 때 쓴다. 범주에 순서가 있으면 그 순서대로 번호를 준다. 회원 등급은 Bronze < Silver < Gold < VIP의 순서가 있으므로 0, 1, 2, 3을 준다.

# [예제 17]
g = df_clean["grade"].map({"Bronze": 0, "Silver": 1, "Gold": 2, "VIP": 3})
g.value_counts().sort_index()

값이 둘뿐인 이진 범주도 map으로 0과 1로 바꾼다. 어느 값을 1로 할지는 가이드를 따른다. 가이드가 없으면 “그렇다”(Y)를 1로 한다.

p_map = df_clean["payment"].map({"Card": 0, "Mobile": 1})

2.6 map이 만든 결측치 찾기

map의 결측치는 두 가지 경우에 생긴다. 사전에 범주를 빠뜨린 경우(2.5절의 마지막 셀)와, 사전의 키와 자료의 값이 표기가 다른 경우이다. 뒤의 경우는 사전이 완전해 보이므로 찾기가 더 어렵다. 공식 문서도 사전에 없는 값은 NaN으로 바뀐다고 설명한다. 아래 셀은 9개 지역을 모두 담은 사전으로 정리하기 전의 region을 바꾼 것이다.

# [예제 20]
region_code = {"Seoul": 0, "Gyeonggi": 1, "Busan": 2, "Incheon": 3, "Daegu": 4,
               "Daejeon": 5, "Gwangju": 6, "Ulsan": 7, "Sejong": 8}
m = df_clean["region"].map(region_code)
print(m.isna().sum())
print(sorted(df_clean.loc[m.isna(), "region"].unique()))
86

3. 원핫 인코딩과 선택 인자

3.1 원핫 인코딩의 원리

원핫 인코딩은 범주 하나마다 열을 하나씩 만들고, 해당하는 열에만 1을, 나머지에는 0을 넣는 방식이다. 결제 수단처럼 범주 사이에 순서가 없을 때 쓴다. Card를 0, Mobile을 1, Point를 2로 바꾸면 모델은 Point가 Card보다 “크다”고 해석할 수 있다. 원핫 인코딩은 이런 거짓 순서를 만들지 않는다.

변환을 다섯 행의 작은 표로 손으로 따라가 본다. 결제 수단이 차례로 Card, Point, Card, Mobile, Point인 다섯 회원이 있다. 범주는 Card, Mobile, Point의 셋이므로 열 셋을 만들고, 행마다 자기 범주의 열에만 1을 적는다.

행 payment payment_Card payment_Mobile payment_Point 행의 합
0 Card 1 0 0 1
1 Point 0 0 1 1
2 Card 1 0 0 1
3 Mobile 0 1 0 1
4 Point 0 0 1 1
열의 합 2 1 2 5

손 계산에서 원핫 인코딩의 두 성질이 드러난다. 첫째, 어느 행이든 1은 정확히 하나이므로 행의 합은 언제나 1이다(3.7절의 다중공선성과 이어진다). 둘째, 각 열의 합은 그 범주의 빈도와 같다. 그래서 원핫 열의 합계로 value_counts()의 결과를 다시 확인할 수 있다. 같은 변환을 코드로 실행한다.

[그림 자리: 원핫 인코딩의 표 변환 도식] 왼쪽에 payment 한 열(Card, Point, Card, Mobile, Point)의 표, 오른쪽에 payment_Card, payment_Mobile, payment_Point 세 열의 0/1 표를 두고 가운데에 pd.get_dummies(columns=["payment"], dtype=int)라고 적은 화살표로 잇는다. 같은 범주의 행을 같은 색으로 칠하여, 왼쪽의 글자가 오른쪽의 어느 열의 1이 되는지 보이게 한다. 원래 열이 사라지고 새 열이 오른쪽 끝에 붙는다는 것을 점선 상자로 표시한다. 그림 안의 글자는 영문으로 쓴다. 만들 곳: 도식 작성 도구.

pandas의 pd.get_dummies가 원핫 인코딩을 한다. 시리즈 하나를 주면 범주마다 열이 생긴다.

열 이름은 범주의 이름이고, 열은 알파벳 순서로 놓인다. 값이 True와 False인 것에 주의한다. pandas 2.0부터 get_dummies의 기본 자료형(dtype)은 bool이다. 그 이전 판과 많은 참고 자료에서는 0과 1의 정수로 나온다. scikit-learn의 모델은 bool 열도 받지만, 가이드가 0과 1을 요구하거나 결과를 합계·평균으로 확인하려면 정수로 받는 것이 편하다.

3.3 drop_first

범주가 k개이면 원핫 열 k개 가운데 하나는 나머지로부터 알 수 있다. 네 열 가운데 셋이 모두 0이면 남은 하나는 반드시 1이기 때문이다. drop_first=True는 첫 범주(알파벳 순서의 첫째)의 열을 빼고 k-1개만 만든다.

# [예제 24]

print(enc_d.shape)
list(enc_d.columns[-3:])
(2940, 18)
['payment_Mobile', 'payment_Point', 'payment_Transfer']

payment_Card가 빠졌다. 세 열이 모두 0인 행이 Card이다. 열 하나가 나머지 열의 합으로 정해지는 관계는 선형 회귀처럼 계수를 계산하는 모델에서 계수의 해석을 어렵게 한다. 트리 계열 모델에는 영향이 거의 없다. 시험에서는 가이드가 drop_first를 지정할 때만 쓴다. 지정이 없으면 기본값(False)을 따른다.

3.5 인코딩 후의 열 수

시험은 인코딩 결과의 열 수를 답 변수로 묻는 경우가 많다. 열 수는 다음 식으로 계산하고, 코드의 shape로 확인한다.

  • drop_first=False: 인코딩 후의 열 수 = 원래 열 수 - 인코딩한 열 수 + 인코딩한 열들의 범주 수의 합
  • drop_first=True: 위의 값 - 인코딩한 열 수

3.7 drop_first와 다중공선성

3.3절에서 “범주가 k개이면 원핫 열 하나는 나머지로부터 알 수 있다”고 하였다. 이 관계를 선형 회귀와 연결한다. 선형 회귀는 예측값 = 절편 + 계수1 × 열1 + 계수2 × 열2 + …의 꼴이며, 절편은 “모든 행에서 값이 1인 열”의 계수로 볼 수 있다. 그런데 3.1절의 손 계산에서 원핫 열의 행 합은 언제나 1이었다. 즉 원핫 열을 모두 더하면 절편의 열과 똑같은 열이 된다.

여러 입력 열 사이에 이런 선형 관계(한 열이 다른 열들의 합이나 배수로 정확히 정해지는 관계)가 있는 것을 다중공선성이라 한다. 특히 위처럼 완전히 정해지는 경우를 완전한 다중공선성이라 한다. scikit-learn의 공식 문서는 OneHotEncoder의 drop 인자를 설명하면서, 완전한 공선성이 있는 열은 규제가 없는 선형 회귀 모델에 넣을 때 문제가 될 수 있다고 적는다. 선형 회귀의 안내서도 열들이 서로 거의 선형으로 의존하면 계수의 추정이 불안정해진다고 설명한다.

여섯 회원의 작은 예로 확인한다. 결제 수단이 Card, Mobile, Point를 두 번씩 반복하고, 구매액이 10, 14, 20, 12, 16, 22이다. 범주별 평균은 Card 11, Mobile 15, Point 21이다.

# [예제 29]
import numpy as np

toy = pd.DataFrame({"payment": ["Card", "Mobile", "Point", "Card", "Mobile", "Point"],
                    "spend": [10, 14, 20, 12, 16, 22]})
full = pd.get_dummies(toy["payment"], dtype=int)
first = pd.get_dummies(toy["payment"], drop_first=True, dtype=int)
print(full.sum(axis=1).tolist())
print(np.linalg.matrix_rank(full.assign(const=1)), full.shape[1] + 1)
print(np.linalg.matrix_rank(first.assign(const=1)), first.shape[1] + 1)
[1, 1, 1, 1, 1, 1]
3 4
3 3
  • 확인 15 첫 줄이 여섯 개의 1이고, 둘째 줄이 3 4, 셋째 줄이 3 3이다.

첫 줄은 원핫 열 셋의 행 합이 모두 1이라는 것을 보인다. 둘째 줄의 첫 값은 원핫 열 셋에 절편의 열(const, 모두 1)을 더한 표의 계수(rank), 즉 서로 독립인 열의 수이다. 열은 넷인데 독립인 열은 셋뿐이다. 한 열이 다른 열로 정해지기 때문이다. drop_first=True로 만든 두 열에 절편의 열을 더하면 열 셋이 모두 독립이다(셋째 줄). np.linalg.matrix_rank는 넘파이의 함수로, 행렬의 계수를 구한다. 여기서는 열들이 서로 독립인지를 보는 도구로만 쓴다.

4. 라벨 인코딩

4.1 LabelEncoder의 fit_transform과 classes_

라벨 인코딩은 범주마다 0부터 k-1까지의 정수를 하나씩 주는 방식이다. 열의 수는 늘지 않는다. scikit-learn의 LabelEncoder가 이 일을 한다. scikit-learn의 변환기는 객체를 만들고, fit으로 규칙을 배우고, transform으로 적용하는 순서로 쓴다. fit_transform은 두 단계를 한 번에 한다.

# [예제 33]
from sklearn.preprocessing import LabelEncoder

le = LabelEncoder()
grade_le = le.fit_transform(df_clean["grade"])
print(grade_le[:5])
print(le.classes_)
[3 1 0 1 1]
['Bronze' 'Gold' 'Silver' 'VIP']

classes_는 fit이 배운 범주의 목록이며, 목록의 위치가 곧 번호이다. Bronze가 0, Gold가 1, Silver가 2, VIP가 3이다. 번호는 알파벳 순서로 매겨진다. 등급의 높낮이와 다르다. Gold(1)가 Silver(2)보다 작은 번호를 받았다. 결과는 넘파이 배열이므로 앞의 5개를 [:5]로 보았다.

  • 확인 17 첫 줄이 [3 1 0 1 1], 둘째 줄이 ['Bronze' 'Gold' 'Silver' 'VIP']이다.

결과 읽기

묻는 것 읽는 자리 이 출력의 값
첫 회원의 등급 번호 첫 줄의 첫 값 3(classes_의 3번 자리, VIP)
번호 0의 범주 둘째 줄의 첫 값 Bronze
번호 1의 범주 둘째 줄의 둘째 값 Gold(등급의 높낮이로는 셋째)
범주의 수 둘째 줄의 값의 수 4(번호는 0~3)

번호를 읽을 때에는 언제나 classes_를 함께 출력한다. 번호만 보아서는 어느 범주인지 알 수 없고, 같은 범주라도 자료에 어떤 값들이 있었는가에 따라 번호가 달라진다. 예를 들어 Bronze가 없는 자료로 fit하면 Gold가 0번이 된다.

# [예제 34]
pair = pd.DataFrame({"grade": df_clean["grade"], "label": grade_le})
pair.drop_duplicates().sort_values("label")

2  Bronze      0
1    Gold      1
5  Silver      2
0     VIP      3

번호와 등급의 짝을 표로 확인하였다. 2.5절의 map은 0, 1, 2, 3을 Bronze, Silver, Gold, VIP에 주었으나 LabelEncoder는 Bronze, Gold, Silver, VIP에 준다. 순서가 있는 범주를 정해진 순서대로 바꾸려면 LabelEncoder가 아니라 map을 쓴다. 표준 처리 과정(중심 실습)에서 grade를 map으로 바꾸는 까닭이다.

4.2 inverse_transform과 transform

inverse_transform은 번호를 원래의 범주로 되돌린다. 분류 모델의 예측은 번호로 나오므로, 결과를 사람이 읽을 이름으로 바꿀 때 쓴다(10장).

# [예제 35]
le.inverse_transform([0, 1, 2, 3])
array(['Bronze', 'Gold', 'Silver', 'VIP'], dtype=object)

이미 fit한 인코더에 새 값을 주면 transform만 한다. 같은 규칙을 다른 자료에 그대로 적용할 때 쓴다.

# [예제 36]
le.transform(["VIP", "Bronze"])
array([3, 0])
메서드·속성 하는 일
fit(y) 범주의 목록을 배운다(알파벳 순서로 정렬)
transform(y) 배운 목록에 따라 번호로 바꾼다
fit_transform(y) 두 일을 한 번에
inverse_transform(번호) 번호를 범주로 되돌린다
classes_ 배운 범주의 목록. 위치가 번호

4.3 흔한 오류 두 가지

fit할 때 없던 값을 transform에 주면 오류가 난다. 인코더는 배운 범주에만 번호를 줄 수 있기 때문이다.

# [예제 37]
le.transform(["Platinum"])
ValueError: y contains previously unseen labels: 'Platinum'

LabelEncoder는 한 번에 열 하나(1차원)만 받는다. 데이터프레임에서 두 열을 골라 넘기면 오류가 난다. 이름(label)이 뜻하는 대로 목표 열의 값을 위한 도구이기 때문이다. 공식 문서도 이 인코더를 목표 값(y)에 쓰고 입력(X)에는 쓰지 말라고 안내한다.

# [예제 38]
LabelEncoder().fit_transform(df_clean[["grade", "payment"]])
ValueError: y should be a 1d array, got an array of shape (2940, 2) instead.

여러 입력 열을 정수로 바꿔야 하면 열마다 따로 인코더를 만들거나, map을 쓰거나, 입력용으로 만들어진 OrdinalEncoder를 쓴다. 본 과목은 map을 쓴다.

데이터프레임에서 열 하나를 대괄호 둘(df_clean[["grade"]])로 고르면 결과는 시리즈가 아니라 열이 하나인 데이터프레임(2차원)이다. 이것을 LabelEncoder에 주면 오류는 나지 않고 결과도 같지만 경고가 난다. 아래 셀은 그 경고를 기록하여 출력한 것이다.

5.1 모델의 종류에 따른 선택

앞의 표를 이 과목에서 다루는 세 종류의 모델(6~10장)로 나누어 정리한다. 선형 모델은 입력에 계수를 곱해 더하므로 번호의 크기와 간격이 그대로 예측에 들어간다. 트리 모델은 “이 열의 값이 기준보다 작은가”를 묻는 분기를 거듭하므로 번호의 크기 자체보다 번호가 나누는 경계가 중요하다. 신경망은 입력에 가중치를 곱해 더하는 층을 쌓은 것이어서 입력의 크기에 대해서는 선형 모델과 비슷하게 동작한다.

인코딩 선형 모델(선형 회귀, 로지스틱 회귀) 트리 모델(의사결정나무, 랜덤 포레스트, XGBoost) 신경망(Keras)
원핫(순서 없는 입력) 알맞다. 계수를 해석하려면 drop_first를 검토한다(3.7절) 쓸 수 있다. 범주가 많으면 열이 많아져 학습이 느려진다 알맞다. 입력으로 흔히 쓰는 방식이다
라벨(순서 없는 입력에 임의의 번호) 쓰지 않는다. 없는 순서와 간격을 학습한다 쓸 수 있다. 분기를 여러 번 세워 범주를 나눌 수 있다 쓰지 않는다. 번호의 크기가 입력값으로 들어간다
순서형(map, 순서 있는 입력) 쓸 수 있다. 번호의 간격이 같다고 가정한다 알맞다 쓸 수 있다. 다른 열과 함께 스케일링한다(5장)
목표 열(분류) LabelEncoder로 정수 번호 정수 번호. XGBoost는 0부터 차례로 매긴 번호가 필요하다(7장. 1, 2, 3으로 주면 ValueError: Invalid classes inferred from unique values of y가 난다) 정수 번호 또는 그 번호의 원핫(9장)
목표 열(회귀) 인코딩하지 않는다 인코딩하지 않는다 인코딩하지 않는다

본 과목은 6~10장에서 세 종류의 모델을 같은 인코딩본(df_enc)으로 학습시킨다. 순서 없는 입력은 원핫, 순서 있는 입력과 이진 범주는 map으로 바꾸었으므로, 표의 어느 열에서도 “쓰지 않는다”에 해당하는 조합이 없다. 이것이 표준 처리 과정이 라벨 인코딩을 입력에 쓰지 않는 까닭이다.

5.2 훈련용과 검증용의 열 일치

5장에서는 인코딩본을 훈련용과 검증용으로 나눈다. 본 과목은 먼저 인코딩하고 나중에 나누므로 두 데이터의 열이 언제나 같다. 그런데 두 데이터를 따로 인코딩하면 한쪽에만 있는 범주 때문에 열이 달라진다. 아래 셀은 훈련용 4행에는 결제 수단이 셋(Card, Mobile, Point) 있고, 검증용 2행에는 둘(Card, Mobile)만 있는 작은 예이다. 두 데이터를 따로 원핫 인코딩하고, 훈련용으로 선형 회귀를 학습시킨다.

# [예제 42]
tr = pd.DataFrame({"payment": ["Card", "Mobile", "Point", "Card"], "visits": [3, 5, 8, 4],
                   "spend": [100, 150, 260, 120]})
va = pd.DataFrame({"payment": ["Card", "Mobile"], "visits": [6, 2], "spend": [180, 90]})
Xtr = pd.get_dummies(tr.drop(columns=["spend"]), columns=["payment"], dtype=int)
Xva = pd.get_dummies(va.drop(columns=["spend"]), columns=["payment"], dtype=int)
model = LinearRegression().fit(Xtr, tr["spend"])

# 여기에 코드를 작성한다

스스로 점검

다음 물음에 답한 뒤 해당 절을 다시 읽어 확인한다.

  1. df.dtypes의 출력 맨 아래에 dtype: object가 있다. 이것은 무엇의 자료형인가.
  2. region을 str.title()로만 정리하면 고유값이 11개, str.strip()을 먼저 하면 10개이다. 차이 1개는 어떤 표기에서 생기는가.
  3. 결제 수단이 Card, Point, Point, Transfer인 네 행을 손으로 원핫 인코딩한 표를 그리고, drop_first=True이면 어느 열이 빠지는지 쓴다.
  4. 16열의 표에서 범주가 3개, 5개인 두 열을 원핫 인코딩하면 열이 몇 개가 되는가. drop_first=True이면 몇 개인가.
  5. map의 결과에 결측치가 생겼다. 사전에 없는 값을 찾는 코드 두 가지를 쓴다.
  6. 원핫 열을 모두 쓰고 절편이 있는 선형 회귀를 학습시키면 계수가 하나로 정해지지 않는 까닭을 “행의 합”으로 설명한다.
  7. 훈련용과 검증용을 따로 원핫 인코딩하였더니 예측에서 Feature names seen at fit time, yet now missing이 났다. 원인과 대처를 쓴다.
  8. 순서가 없는 입력 열에 라벨 인코딩을 쓰면 선형 모델과 트리 모델에서 각각 어떤 문제가 생기는가.

9. 정리

주제 기억할 것
자료형 확인 dtypes, select_dtypes(exclude="number"). pandas 3에서 include="object"는 경고를 낸다
자료형 변환 astype(int), astype(str). 글자 → 숫자는 astype으로 할 수 없다
표기 정리 str.strip(), str.title(), str.lower(), replace({기존: 새 값})
범주 통합 value_counts()로 빈도를 보고, 기준 미만의 범주를 replace(목록, "Other")
map 사전으로 정해진 번호를 준다. 사전에 없는 값은 NaN. 순서형 인코딩과 이진 변환에 쓴다
원핫 인코딩 pd.get_dummies(df, columns=[...], dtype=int). 기본 자료형은 bool. drop_first=True는 첫 범주를 뺀다
열 수 원래 열 수 - 인코딩한 열 수 + 범주 수의 합
라벨 인코딩 LabelEncoder().fit_transform(열). 번호는 알파벳 순서. classes_, inverse_transform. 1차원만 받는다
적용 기준 순서 없는 입력은 원핫, 순서 있는 입력은 map, 글자로 된 목표는 LabelEncoder
목표 열 먼저 떼어 낸 뒤 입력만 인코딩한다
map의 결측치 사전에 없는 값은 NaN. s[결과.isna()].unique()나 집합 차로 찾는다
열 비교 set(전.columns) - set(후.columns)는 사라진 열, 반대는 생긴 열
다중공선성 원핫 열의 행 합은 1이다. 선형 회귀의 계수를 해석하려면 drop_first=True
열 불일치 따로 인코딩하면 열이 달라진다. 먼저 인코딩하고 나누거나 reindex(columns=..., fill_value=0)
모델과 인코딩 선형·신경망은 순서 없는 입력에 원핫, 트리는 어느 쪽이든 쓸 수 있다. 목표는 정수 번호
