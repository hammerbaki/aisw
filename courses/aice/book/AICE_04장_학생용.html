2027학년도 「비즈니스빅데이터분석」의 준비 중인 교재입니다. 편집 상태를 검토하기 위해 미리 공개한 것으로, 수업 전에 내용과 순서가 바뀔 수 있습니다.

학사 5주차 · 교재 04 · 2부 데이터 전처리 · 출제 분야: 데이터 전처리 > 라벨 인코딩/원핫 인코딩

머신러닝 모델은 숫자만 입력으로 받는다. Seoul, VIP, Card와 같은 글자 값이 남아 있으면 scikit-learn의 모델은 학습 단계에서 오류를 낸다. 시험지의 전처리 문항은 이 단계를 “지정한 열을 원핫 인코딩하라”, “범주 값을 통합한 뒤 변환하라”와 같은 가이드로 묻는다. 인코딩의 결과는 곧바로 분할과 모델링 문항의 입력이 되므로, 열을 하나 빠뜨리거나 목표 열까지 인코딩하면 뒤의 문항이 모두 영향을 받는다.

본 장은 범주형 열의 자료형을 확인하고, 표기가 섞인 값을 정리하여 통합한 뒤, 원핫 인코딩과 라벨 인코딩으로 숫자로 바꾸는 방법을 다룬다. 두 방법을 언제 쓰는지와 목표 열을 어떻게 다루는지도 함께 다룬다. 중심 실습에서는 3장의 정제본 df_clean을 인코딩하여 인코딩본 df_enc(2940행, 26열)를 만든다. df_enc는 5장(분할과 스케일링)부터 10장까지 모든 장의 출발점이다.

학습 목표

  1. 열의 자료형을 확인하고, 수치형 열과 범주형 열을 select_dtypes로 구분하며, astype으로 자료형을 바꾼다.
  2. 표기가 섞인 범주 값을 문자열 메서드와 replace로 정리하고, 빈도가 낮은 범주를 하나로 통합한다.
  3. map으로 이진 범주와 순서가 있는 범주를 정해진 정수로 바꾸고, 사전에 없는 값이 결측치가 되는 점을 확인한다.
  4. pd.get_dummies의 columns, drop_first, dtype 인자를 지정하여 원핫 인코딩하고, 인코딩 후의 열 수를 계산한다.
  5. LabelEncoder로 라벨 인코딩하고, 번호가 알파벳 순서로 매겨지는 점과 classes_, inverse_transform의 쓰임을 설명한다.
  6. 범주의 순서, 범주의 수, 목표 열 여부에 따라 인코딩 방법을 고르고, 목표 열을 입력과 따로 다룬다.

1.1 dtypes로 자료형 확인

dtypes는 열 이름을 인덱스로, 자료형을 값으로 하는 시리즈이며, 괄호가 없는 속성이다.

str로 표시된 6개 열이 글자로 된 범주형 열이고, 나머지 10개 열은 정수(int64)나 실수(float64)이다. age는 원본의 결측치 때문에 실수로 읽혀 3장에서 채운 뒤에도 float64로 남아 있다. churn은 0과 1로 된 정수 열이므로, 뜻은 범주이지만 인코딩할 필요가 없다. 맨 아래 줄 dtype: object는 이 시리즈 자체(자료형 이름들)의 자료형이며, “모든 열이 object”라는 뜻이 아니다.

  • 확인 2 출력의 16줄 가운데 str이 6줄, int64가 5줄, float64가 5줄이다.

1.2 select_dtypes에 의한 열 선택

select_dtypes는 자료형을 기준으로 열을 고른다. include에 고를 자료형을, exclude에 뺄 자료형을 준다. "number"는 정수와 실수를 모두 포함하는 이름이다. 결과는 데이터프레임이므로 열 이름만 필요하면 .columns를 붙인다.

# [예제 3]
print(list(df_clean.select_dtypes(exclude="number").columns))
print(list(df_clean.select_dtypes(include="number").columns))
['gender', 'region', 'grade', 'app_user', 'payment', 'marketing_agree']
['age', 'tenure_months', 'visits_per_month', 'avg_session_min', 'cart_items', 'coupon_use_rate', 'cs_calls', 'last_login_days', 'annual_spend', 'churn']

pandas 2.x를 쓰는 자료에서는 문자열 열을 고를 때 select_dtypes(include="object")라고 쓰는 경우가 많다. pandas 3.0부터 문자열 열의 기본 자료형이 object에서 str로 바뀌었으므로, 이 코드는 결과를 돌려주기는 하지만 Pandas4Warning: For backward compatibility, 'str' dtypes are included by select_dtypes when 'object' dtype is specified라는 경고를 낸다. 다음 큰 판(pandas 4)에서 동작이 바뀐다는 예고이다. 판에 관계없이 같은 결과를 얻으려면 exclude="number"를 쓴다. 본 교재의 코드는 모두 이 방식을 쓴다.

[최신 자료 자리: AICE 시험 환경의 pandas 판] 시험 환경에 설치된 pandas의 판. 2.x이면 문자열 열이 object로 표시되고, get_dummies의 기본 자료형(bool)은 같으며, select_dtypes(include="object")는 경고를 내지 않는다. 확인할 곳: AICE 공식 사이트(https://aice.study/certi/practice)의 사전 환경점검 화면과 수험자 가이드. 과목 설계(2026-11-13 조사)에서 이 값은 미확인 사항으로 남았다. 수업 전에 확인한다.

[그림 자리: 주피터에서 Pandas4Warning 경고 상자가 출력된 화면] df_clean.select_dtypes(include="object")를 실행한 셀 아래에 분홍색 바탕의 경고 상자와 그 아래의 결과 표가 함께 나온 화면. 경고가 있어도 결과는 출력된다는 점이 보이게 찍는다. 찍을 곳: 학교 실습 환경의 주피터.

1.3 astype에 의한 변환

astype은 열의 자료형을 지정한 자료형으로 바꾼 새 시리즈를 돌려준다. 원래의 열은 바뀌지 않으므로 결과를 변수에 저장한다.

# [예제 4]
age_int = df_clean["age"].astype(int)
print(df_clean["age"].dtype, "->", age_int.dtype)
age_int.head(3)
float64 -> int64
0    30
1    43
2    25
Name: age, dtype: int64

3장에서 age의 결측치를 채웠으므로 정수로 바꿀 수 있다. 정수 자료형(int64)에는 결측치를 나타낼 자리가 없으므로, 결측치가 남은 열을 astype(int)로 바꾸면 IntCastingNaNError가 난다. 본 과목은 결측치를 먼저 처리한다. 글자 값을 숫자로 바꾸는 일은 astype으로 할 수 없다. df_clean["grade"].astype(int)가 내는 ValueError는 “인코딩이 필요하다”는 신호이며, 2절의 map, 3절의 원핫 인코딩, 4절의 라벨 인코딩 가운데 하나를 쓴다.

변환 코드 비고
실수 → 정수 s.astype(int) 결측치가 있으면 오류. 소수점 아래는 반올림하지 않고 버린다
숫자 → 글자 s.astype(str) 0과 1이 글자 "0", "1"이 된다
글자 → 숫자 astype으로는 할 수 없다 map, get_dummies, LabelEncoder

2.3 replace에 의한 치환

replace는 지정한 값을 다른 값으로 바꾼다. {바꿀 값: 새 값}의 사전을 주면 여러 값을 한 번에 바꿀 수 있고, 사전에 없는 값은 그대로 남는다. 2.2절의 step3은 Gyeonggi-Do를 Gyeonggi로 바꾸어 실제 지역 수와 같은 9개를 만들었다.

형식 예 뜻
값 하나 → 값 하나 s.replace("A", "B") A를 B로
사전 s.replace({"A": "B", "C": "D"}) A를 B로, C를 D로
리스트 → 값 하나 s.replace(["A", "C"], "Z") A와 C를 모두 Z로(2.4절)

2.5 map에 의한 변환

map은 시리즈의 값마다 사전에서 짝을 찾아 바꾼다. 글자 범주를 정해진 정수로 바꿀 때 쓴다. 범주에 순서가 있으면 그 순서대로 번호를 준다. 회원 등급은 Bronze < Silver < Gold < VIP의 순서가 있으므로 0, 1, 2, 3을 준다.

# [예제 9]

3. 원핫 인코딩과 선택 인자

3.1 원핫 인코딩의 원리

원핫 인코딩은 범주 하나마다 열을 하나씩 만들고, 해당하는 열에만 1을, 나머지에는 0을 넣는 방식이다. 결제 수단처럼 범주 사이에 순서가 없을 때 쓴다. Card를 0, Mobile을 1, Point를 2로 바꾸면 모델은 Point가 Card보다 “크다”고 해석할 수 있는데, 원핫 인코딩은 이런 거짓 순서를 만들지 않는다. 결제 수단이 차례로 Card, Point, Card, Mobile, Point인 다섯 회원을 손으로 변환한다.

행 payment payment_Card payment_Mobile payment_Point 행의 합
0 Card 1 0 0 1
1 Point 0 0 1 1
2 Card 1 0 0 1
3 Mobile 0 1 0 1
4 Point 0 0 1 1
열의 합 2 1 2 5

어느 행이든 1은 정확히 하나이므로 행의 합은 언제나 1이다(3.7절). 각 열의 합은 그 범주의 빈도와 같으므로 원핫 열의 합계로 value_counts()의 결과를 다시 확인할 수 있다. pandas의 pd.get_dummies가 원핫 인코딩을 한다.

# [예제 12]
toy = pd.DataFrame({"payment": ["Card", "Point", "Card", "Mobile", "Point"]})
pd.get_dummies(toy, columns=["payment"], dtype=int)
   payment_Card  payment_Mobile  payment_Point
0             1               0              0
1             0               0              1
2             1               0              0
3             0               1              0
4             0               0              1

[그림 자리: 원핫 인코딩의 표 변환 도식] 왼쪽에 payment 한 열(Card, Point, Card, Mobile, Point)의 표, 오른쪽에 payment_Card, payment_Mobile, payment_Point 세 열의 0/1 표를 두고 가운데에 pd.get_dummies(columns=["payment"], dtype=int)라고 적은 화살표로 잇는다. 같은 범주의 행을 같은 색으로 칠하여, 왼쪽의 글자가 오른쪽의 어느 열의 1이 되는지 보이게 한다. 원래 열이 사라지고 새 열이 오른쪽 끝에 붙는다는 것을 점선 상자로 표시한다. 그림 안의 글자는 영문으로 쓴다. 만들 곳: 도식 작성 도구.

출력은 손으로 만든 표와 같다. 새 열은 범주의 알파벳 순서로 놓인다. pandas 2.0부터 get_dummies의 기본 자료형(dtype)은 bool이어서 dtype을 주지 않으면 값이 True와 False로 나온다. 그 이전 판과 많은 참고 자료에서는 0과 1의 정수로 나온다. scikit-learn의 모델은 bool 열도 받지만, 가이드가 0과 1을 요구하거나 결과를 합계·평균으로 확인하려면 dtype=int를 준다.

3.2 columns와 dtype

실제 작업에서는 데이터프레임 전체를 주고 인코딩할 열을 columns에 리스트로 지정한다. 지정한 열은 원핫 열로 바뀌고, 나머지 열은 그대로 남는다.

# [예제 13]
enc = pd.get_dummies(df_clean, columns=["payment"], dtype=int)
print(df_clean.shape, "->", enc.shape)
enc.iloc[:3, -5:]
(2940, 16) -> (2940, 19)
   churn  payment_Card  payment_Mobile  payment_Point  payment_Transfer
0      0             1               0              0                 0
1      0             0               1              0                 0
2      1             0               0              0                 1

payment 열 하나가 사라지고 4개의 열이 오른쪽 끝에 붙어, 16열이 19열이 되었다. 새 열의 이름은 원래 열 이름_범주의 꼴이다. 원래 열의 값은 남지 않으므로, 원본(df_clean)을 고치지 않고 결과를 새 변수에 저장한다.

  • 확인 7 첫 줄이 (2940, 16) -> (2940, 19)이고, 표의 열이 churn과 payment_로 시작하는 네 열이며 값이 0과 1이다.

3.3 drop_first

범주가 k개이면 원핫 열 k개 가운데 하나는 나머지로부터 알 수 있다. 네 열 가운데 셋이 모두 0이면 남은 하나는 반드시 1이기 때문이다. drop_first=True는 첫 범주(알파벳 순서의 첫째)의 열을 빼고 k-1개만 만든다.

# [예제 14]
enc_d = pd.get_dummies(df_clean, columns=["payment"], drop_first=True, dtype=int)
print(enc_d.shape)
list(enc_d.columns[-3:])
(2940, 18)
['payment_Mobile', 'payment_Point', 'payment_Transfer']

payment_Card가 빠졌고, 세 열이 모두 0인 행이 Card이다. 시험에서는 가이드가 drop_first를 지정할 때만 쓰고, 지정이 없으면 기본값(False)을 따른다.

3.4 prefix와 columns의 생략

prefix는 새 열 이름의 앞부분을 바꾼다(예: prefix="pay"이면 pay_Card). columns를 생략하면 수치형이 아닌 열이 모두 인코딩된다. 편해 보이지만 정리하지 않은 열까지 인코딩되고, 글자로 된 목표 열도 인코딩되어 사라진다(6절).

# [예제 15]
all_enc = pd.get_dummies(df_clean, dtype=int)
print(all_enc.shape)

3.7 drop_first와 다중공선성

선형 회귀는 예측값 = 절편 + 계수1 × 열1 + 계수2 × 열2 + …의 꼴이며, 절편은 “모든 행에서 값이 1인 열”의 계수로 볼 수 있다. 원핫 열의 행 합은 언제나 1이므로, 원핫 열을 모두 더하면 절편의 열과 똑같은 열이 된다. 입력 열 사이에 이처럼 한 열이 다른 열들로 정확히 정해지는 관계가 있는 것을 완전한 다중공선성이라 한다. scikit-learn의 공식 문서는 완전한 공선성이 있는 열이 규제가 없는 선형 회귀 모델에서 문제가 될 수 있다고 적는다. 원핫 열을 모두 쓰면 예측은 같아도, 절편에 어떤 수를 더하고 모든 계수에서 같은 수를 빼도 예측이 그대로이므로 계수가 하나로 정해지지 않는다. drop_first=True로 한 열을 빼면 계수가 하나로 정해지고, 각 계수는 “기준 범주(Card)보다 얼마나 큰가”를 뜻한다. 트리 계열 모델은 열 하나로 나누는 방식이므로 이 관계가 문제되지 않는다. 시험에서는 가이드가 지정할 때만 쓰며, 본 과목의 표준 처리 과정도 drop_first를 쓰지 않는다.

4. 라벨 인코딩

4.1 LabelEncoder의 fit_transform과 classes_

라벨 인코딩은 범주마다 0부터 k-1까지의 정수를 하나씩 주는 방식으로, 열의 수가 늘지 않는다. scikit-learn의 LabelEncoder가 이 일을 한다. scikit-learn의 변환기는 객체를 만들고, fit으로 규칙을 배우고, transform으로 적용하는 순서로 쓴다. fit_transform은 두 단계를 한 번에 한다.

# [예제 16]
from sklearn.preprocessing import LabelEncoder

le = LabelEncoder()
grade_le = le.fit_transform(df_clean["grade"])
print(grade_le[:5])
print(le.classes_)
[3 1 0 1 1]
['Bronze' 'Gold' 'Silver' 'VIP']

classes_는 fit이 배운 범주의 목록이며, 목록의 위치가 곧 번호이다. Bronze가 0, Gold가 1, Silver가 2, VIP가 3이다. 번호는 알파벳 순서로 매겨진다. 등급의 높낮이와 달리 Gold(1)가 Silver(2)보다 작은 번호를 받았다. 결과는 넘파이 배열이므로 앞의 5개를 [:5]로 보았다.

  • 확인 8 첫 줄이 [3 1 0 1 1], 둘째 줄이 ['Bronze' 'Gold' 'Silver' 'VIP']이다.

번호를 읽을 때에는 언제나 classes_를 함께 출력한다. 같은 범주라도 자료에 어떤 값들이 있었는가에 따라 번호가 달라진다. 예를 들어 Bronze가 없는 자료로 fit하면 Gold가 0번이 된다. 2.5절의 map은 0, 1, 2, 3을 Bronze, Silver, Gold, VIP에 주었으나 LabelEncoder는 Bronze, Gold, Silver, VIP에 준다. 순서가 있는 범주를 정해진 순서대로 바꾸려면 map을 쓴다. 표준 처리 과정(중심 실습)에서 grade를 map으로 바꾸는 까닭이다.

4.2 inverse_transform과 transform

inverse_transform은 번호를 원래의 범주로 되돌린다. 분류 모델의 예측은 번호로 나오므로, 결과를 사람이 읽을 이름으로 바꿀 때 쓴다(10장). 이미 fit한 인코더에 새 값을 주면 transform만 하므로, 같은 규칙을 다른 자료에 그대로 적용할 때 쓴다.

# [예제 17]
print(le.inverse_transform([0, 1, 2, 3]))
print(le.transform(["VIP", "Bronze"]))
['Bronze' 'Gold' 'Silver' 'VIP']
[3 0]

4.3 흔한 오류 두 가지

인코더는 배운 범주에만 번호를 줄 수 있으므로, fit할 때 없던 값을 transform에 주면 오류가 난다. 또 LabelEncoder는 열 하나(1차원)만 받는다. 공식 문서도 이 인코더를 목표 값(y)에 쓰고 입력(X)에는 쓰지 말라고 안내한다. 여러 입력 열을 정수로 바꾸려면 본 과목은 map을 쓴다(입력용인 OrdinalEncoder도 있다). 열 하나를 대괄호 둘(df_clean[["grade"]])로 고르면 2차원이 되어 경고가 나므로, 목표 열은 대괄호 하나로 고른다.

5.1 모델의 종류에 따른 선택

선형 모델은 입력에 계수를 곱해 더하므로 번호의 크기와 간격이 그대로 예측에 들어간다. 트리 모델은 “이 열의 값이 기준보다 작은가”를 묻는 분기를 거듭하므로 번호가 나누는 경계가 중요하다. 신경망은 입력의 크기에 대해 선형 모델과 비슷하게 동작한다.

인코딩 선형 모델(선형 회귀, 로지스틱 회귀) 트리 모델(의사결정나무, 랜덤 포레스트, XGBoost) 신경망(Keras)
원핫(순서 없는 입력) 알맞다. 계수를 해석하려면 drop_first를 검토한다(3.7절) 쓸 수 있다. 범주가 많으면 열이 많아져 학습이 느려진다 알맞다. 입력으로 흔히 쓰는 방식이다
라벨(순서 없는 입력에 임의의 번호) 쓰지 않는다. 없는 순서와 간격을 학습한다 쓸 수 있다. 분기를 여러 번 세워 범주를 나눌 수 있다 쓰지 않는다. 번호의 크기가 입력값으로 들어간다
순서형(map, 순서 있는 입력) 쓸 수 있다. 번호의 간격이 같다고 가정한다 알맞다 쓸 수 있다. 다른 열과 함께 스케일링한다(5장)
목표 열(분류) LabelEncoder로 정수 번호 정수 번호. XGBoost는 0부터 차례로 매긴 번호가 필요하다(7장. 1, 2, 3으로 주면 ValueError: Invalid classes inferred from unique values of y가 난다) 정수 번호 또는 그 번호의 원핫(9장)
목표 열(회귀) 인코딩하지 않는다 인코딩하지 않는다 인코딩하지 않는다

본 과목은 6~10장에서 세 종류의 모델을 같은 인코딩본(df_enc)으로 학습시킨다. 순서 없는 입력은 원핫, 순서 있는 입력과 이진 범주는 map으로 바꾸었으므로, 표의 어느 열에서도 “쓰지 않는다”에 해당하는 조합이 없다. 이것이 표준 처리 과정이 라벨 인코딩을 입력에 쓰지 않는 까닭이다.

5.2 훈련용과 검증용의 열 일치

본 과목은 먼저 인코딩하고 나중에 나누므로(5장) 훈련용과 검증용의 열이 언제나 같다. 두 데이터를 따로 인코딩하면 한쪽에만 있는 범주 때문에 열이 달라진다. 아래 셀은 훈련용 4행에는 결제 수단이 셋(Card, Mobile, Point) 있고 검증용 2행에는 둘(Card, Mobile)만 있는 작은 예로, 두 데이터를 따로 원핫 인코딩하고 훈련용으로 선형 회귀를 학습시킨다.

# [예제 18]
from sklearn.linear_model import LinearRegression

tr = pd.DataFrame({"payment": ["Card", "Mobile", "Point", "Card"], "visits": [3, 5, 8, 4],
                   "spend": [100, 150, 260, 120]})
va = pd.DataFrame({"payment": ["Card", "Mobile"], "visits": [6, 2], "spend": [180, 90]})
Xtr = pd.get_dummies(tr.drop(columns=["spend"]), columns=["payment"], dtype=int)
Xva = pd.get_dummies(va.drop(columns=["spend"]), columns=["payment"], dtype=int)
model = LinearRegression().fit(Xtr, tr["spend"])
print(list(Xtr.columns))
print(list(Xva.columns))
['visits', 'payment_Card', 'payment_Mobile', 'payment_Point']
['visits', 'payment_Card', 'payment_Mobile']

검증용에는 Point인 행이 없으므로 payment_Point 열이 생기지 않았다. 이 상태로 model.predict(Xva)를 실행하면 ValueError: The feature names should match those that were passed during fit.가 나고, 그 아래에 “학습할 때 보았으나 지금 없는 열”(Feature names seen at fit time, yet now missing:)로 payment_Point가 나온다. scikit-learn의 모델은 학습할 때의 열 이름과 순서를 기억하여 예측할 때 받은 데이터프레임과 대조하기 때문이다. 바로잡으려면 검증용의 열을 훈련용의 열 목록에 맞춘다. reindex(columns=목록, fill_value=0)은 목록의 순서대로 열을 늘어놓고, 없는 열은 0으로 채워 만든다.

# [예제 19]
Xva2 = Xva.reindex(columns=Xtr.columns, fill_value=0)
print(Xva2)
print(model.predict(Xva2).round(1))
   visits  payment_Card  payment_Mobile  payment_Point
0       6             1               0              0
1       2             0               1              0
[160.  90.]
  • 확인 9 표에 payment_Point 열이 생겨 값이 모두 0이고, 예측이 [160. 90.]이다.

새로 만든 열의 0은 “이 행들은 Point가 아니다”라는 사실과 일치한다. 반대로 검증용에 훈련용에 없던 범주(예: Transfer)가 나오면 reindex는 그 열을 버리고, 그 행은 “어느 결제 수단도 아닌 회원”으로 예측된다. 이 과목에서는 “전체를 먼저 인코딩하고 나중에 나눈다”는 순서로 이 문제를 피한다.

6. 목표 열의 인코딩

목표 열은 입력과 따로 다룬다. 회귀의 목표(annual_spend)는 숫자이므로 인코딩하지 않는다. 분류의 목표는 범주이므로 정수 번호로 바꾼다. 공통 자료의 churn은 이미 0과 1의 정수(int64, 이탈 573명)이다. 목표가 글자로 되어 있으면 LabelEncoder로 바꾼다. 아래 셀은 회원 등급을 예측하는 분류 문제를 가정하여, 목표 열 grade를 먼저 떼어 내어 번호로 바꾸고 나머지 열에서 입력을 만든 뒤, 번호를 등급 이름으로 되돌리고 입력에 목표 열이 남지 않았는지 확인한다.

목표의 번호는 4.1절과 같이 알파벳 순서이다. 분류 모델은 번호를 서로 다른 이름표로만 다루므로, 순서가 있는 등급이라도 목표 열이면 LabelEncoder를 써도 된다. 입력의 열 수 35는 3.5절의 식으로 검산한다. 목표를 뺀 15열 가운데 문자열 열 5개가 2 + 15 + 2 + 4 + 2 = 25개의 열로 바뀌므로 15 - 5 + 25 = 35이다. 목표 열을 떼어 낸 뒤에는 입력에 목표 열의 이름(또는 그 원핫 열)이 없는지와 목표의 길이가 입력의 행 수와 같은지를 확인한다.

목표 열을 떼어 내지 않고 columns 없이 get_dummies를 적용하면 목표 열까지 원핫 인코딩되어 원래 열이 사라진다. enc_all = pd.get_dummies(df_clean, dtype=int) 다음에 enc_all.drop(columns=["grade"])를 실행하면 grade가 grade_Bronze, grade_Gold 등 4개의 열로 바뀌었으므로 KeyError: "['grade'] not found in axis"가 난다. 정정하는 방법은 columns에 입력 열만 지정하거나, 목표 열을 먼저 떼어 낸 뒤 입력만 인코딩하는 것이다. 순서는 언제나 “목표 분리 → 입력 인코딩”이 안전하다.
