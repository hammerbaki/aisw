[부록 B] 명령어 카드

2027학년도 「AI에이전트 기획 및 개발」의 준비 중인 교재입니다. 편집 상태를 검토하기 위해 미리 공개한 것으로, 수업 전에 내용과 순서가 바뀔 수 있습니다.

「AI에이전트 기획 및 개발」 1~13장의 공통 부록 · 2026-11 기준(Windows 11의 Git Bash, 파이썬 3.13.7, Claude Code 2.1.296, git 2.55, GitHub CLI 2.88.1, pytest 9.2.0, coverage 7.17.3에서 확인)

자주 쓰는 명령을 도구별로 모은 참조표이다. 각 장은 명령을 처음 쓸 때 그 뜻을 설명하고, 이후에는 이 카드를 가리킨다. 앞 과목 「LLM 서비스 개발」의 부록 B(Claude Code 기본 명령, Git 기본, GitHub CLI 기본, 셸 기본)를 전제로 하며, 이 카드는 이 과목에서 새로 쓰는 것에 무게를 둔다. 기본 명령은 표 한 줄로만 다시 적는다. 장에서 「읽기」나 교수 시연으로 옮긴 명령(규칙 판정의 세부, 기록 세기, worktree 연습, 실행 권한, 잠금 파일)도 이 카드에 모았다.

명령은 모두 내 PC의 VS Code 통합 터미널(Windows는 Git Bash, macOS는 기본 셸)에서 친다. 꼬리표는 부록 A의 것과 같다([터미널], [Claude Code], [파일: 경로]). 파이썬은 가상 환경을 켠 뒤의 python, python -m pytest로 부른다(부록 A-9-1). 출력은 집필용 PC(Windows 11, Git Bash)의 스크래치에서 2026-11-17에 실행해 얻은 것이고, GitHub에 무엇을 만드는 원격 조작과 실제 모델을 부르는 명령의 출력은 「예시」로 밝혔다.

B-1-2. 헤드리스 실행(claude -p)

7·8장의 스크립트와 10장의 스크립트 조정자(교수 시연)가 쓰는 옵션이다. 인증과 사용량은 부록 A-15를 본다.

[터미널] (예시. 실제 모델을 부르므로 그 장의 실행 상한 안에서만 실행한다. 부록 A-12-3)

claude -p "python -m pytest -q를 실행하고 실패한 테스트 이름만 말하라" \
  --output-format json \
  --permission-mode dontAsk --allowedTools "Bash(python -m pytest *)" \
  --max-turns 5 --max-budget-usd 0.20 \
  --append-system-prompt "이 실행은 무인 실행이다. 사람에게 질문할 수 없다."
옵션 뜻 이 과목의 쓰임
-p "프롬프트" (--print) 대화 화면 없이 한 번 처리하고 끝낸다. 표준 입력을 함께 읽는다(10MB 상한) 7·8·10장
--output-format text\|json\|stream-json 최종 글 / 결과 객체 하나 / 사건마다 JSON 한 줄. stream-json은 --verbose와 함께 쓴다 8장 json, 7장 stream-json
--json-schema '<스키마>' 결과를 스키마 꼴로 받는다(structured_output 필드). 없을 수 있으므로 확인하고 쓴다 8장 2-2
--allowedTools "규칙…" 묻지 않고 허용할 도구(규칙 문법은 B-1-9) 8·10장
--disallowedTools "규칙…" 거부할 도구 8장
--tools "Bash,Read" / --tools "" 쓸 수 있는 내장 도구 자체를 좁힌다 / 모두 없앤다 8장 digest.sh(--tools "")
--permission-mode dontAsk 미리 허용한 것만 하고 물어야 할 것은 거부한다 8장 루프
--permission-prompts none 권한을 물을 사람이 없다고 알린다. 묻게 될 호출은 거부되고 Claude는 다시 시도하지 않는다 무인 실행
--max-turns N 턴 상한. 닿으면 subtype이 error_max_turns 7·8장
--max-budget-usd X 금액 상한(달러). 닿으면 error_max_budget_usd. 지출은 응답 하나만큼 넘을 수 있다 8·10장
--append-system-prompt "…" / --append-system-prompt-file 파일 기본 시스템 프롬프트를 두고 지시를 덧붙인다. --system-prompt는 통째로 바꾸므로 쓰지 않는다 8장
--resume <세션 ID> / --continue 앞 실행의 대화를 잇는다. 이은 실행의 비용은 대화 전체의 합이다 8장 2-6
--include-partial-messages stream-json에서 토큰 단위 조각까지 낸다
--no-session-persistence 세션을 디스크에 남기지 않는다(이어 볼 수 없다)
--bare 훅, 스킬, 플러그인, MCP, CLAUDE.md를 읽지 않고 API 키로만 인증한다. 이 과목은 쓰지 않는다(부록 A-15-1)

결과 객체(--output-format json)의 필드

필드 뜻
type 언제나 "result"
subtype success, error_max_turns, error_max_budget_usd, error_during_execution, error_max_structured_output_retries
is_error 오류로 끝났는가

명령 뜻

{
  "mcpServers": {
    "jobprep-ops": {
      "type": "stdio",
      "command": "python",
      "args": ["${CLAUDE_PROJECT_DIR:-.}/mcp/ops_server.py"],
      "env": {}
    }

  • 명령은 python 하나로 적고, Claude Code는 가상 환경을 켠 터미널의 저장소 맨 위에서 연다. Windows에서 가상 환경의 bin/ 아래 파이썬 경로를 적으면 ✘ Failed to connect — CONNECTION_CLOSED로 연결에 실패한다(5장 9-5, 부록 A-14-2).

  • 남이 만든 서버는 연결하기 전에 python ~/kits/Agent_05주차/도구/show_tools.py -- <서버 명령>으로 도구 설명을 먼저 읽는다(5장 10-5).

B-1-6. 훅

훅은 정해진 사건에 셸 명령을 실행해 규칙을 강제한다. 등록은 설정 파일의 hooks 키에 한다(어느 범위에 두는지는 부록 A-13). Windows에서 셸 형식의 훅은 Git Bash가 해석하며, Git for Windows가 없으면 PowerShell이 해석해 .sh 훅이 돌지 않는다(6장 2-7).

사건 언제 막을 수 있는가 이 과목의 훅
PreToolUse 도구 호출 직전 예(호출을 막는다) 6장 protect.sh, 11장 block_secrets.sh(실행기)와 block_secrets.py
PostToolUse 도구 호출이 성공한 직후 아니요(이미 실행됨). 글을 Claude에게 돌려준다 6장 run_tests.sh
Stop 주 에이전트가 응답을 마치려 할 때 예(끝내지 못하게 하고 이어 가게 한다) 6·7장 stop_gate.sh
UserPromptSubmit 프롬프트가 모델에게 가기 전 예
SessionStart 세션 시작이나 재개 아니요
SubagentStop 서브에이전트가 끝나려 할 때 예

[파일: .claude/settings.json의 hooks 부분] (6장 훅설정.json)

{
  "hooks": {
    "PreToolUse": [
      { "matcher": "Edit|Write",
        "hooks": [ { "type": "command", "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/protect.sh", "timeout": 30 } ] }
    ],
    "PostToolUse": [
      { "matcher": "Edit|Write",
        "hooks": [ { "type": "command", "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/run_tests.sh", "timeout": 120 } ] }
    ]
  }
}
항목 내용
입력 표준 입력의 JSON 하나. 공통으로 session_id, cwd, hook_event_name. PreToolUse는 tool_name, tool_input. Stop은 stop_hook_active(이미 한 번 막아 이어 가는 중이면 참. 끝없는 반복을 끊는 데 쓴다)
종료 코드 0 통과. 출력한 JSON의 결정 필드가 있으면 그것을 따른다
종료 코드 2 막는다. 표준 오류의 글이 까닭으로 Claude에게 간다
그 밖의 0 아닌 코드 막지 않는다. 사용자에게 오류 안내만 보인다. 규칙을 강제하는 훅은 반드시 2로 끝낸다[C3]
"onFailure": "block" 훅이 시작하지 못하거나 0·2 밖의 코드로 끝나거나 시간을 넘기면 그 호출을 막는다(v2.1.295 이상). 11장의 비밀 정보 보호 훅이 쓴다(11장 6-3)

B-1-8. worktree

10장은 구현 에이전트 둘이 서로의 파일을 덮지 않도록 각자의 git worktree에서 일하게 한다. Claude Code가 만드는 길과 git으로 직접 만드는 길이 있다. 10장의 스크립트는 git으로 직접 만든다(B-2-5).

하려는 일 명령
worktree를 만들어 그 안에서 Claude Code를 시작한다 claude -w <이름> → .claude/worktrees/<이름>/, 새 브랜치 worktree-<이름>[C4]
PR의 head에서 worktree를 만든다 claude -w "#<PR 번호>"
새 worktree에 .env 같은 무시된 파일을 복사해 넣는다 저장소 맨 위의 .worktreeinclude에 .gitignore 문법으로 적는다
서브에이전트를 매번 따로 된 worktree에서 돌린다 정의 파일의 머리말에 isolation: worktree
기준 브랜치를 지금 HEAD로 한다 설정 "worktree": {"baseRef": "head"}(기본값 fresh는 원격의 기본 브랜치)
  • .claude/worktrees/를 .gitignore에 넣는다. 넣지 않으면 원래 작업 폴더의 git status에 ?? .claude/가 보인다(2026-11-14 확인).
  • 대화형 worktree 세션은 끝낼 때 바뀐 것이 없으면 지우고, 있으면 남길지 묻는다. claude -p로 만든 worktree는 지우지 않는다. git worktree remove로 직접 지운다[C4].
  • .worktreeinclude에 .env를 넣으면 키가 worktree마다 복사된다. 10장의 구현 에이전트는 키가 필요 없으므로 넣지 않는다.
