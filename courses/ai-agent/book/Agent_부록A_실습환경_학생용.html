[부록 A] 실습 환경

2027학년도 「AI에이전트 기획 및 개발」의 준비 중인 교재입니다. 편집 상태를 검토하기 위해 미리 공개한 것으로, 수업 전에 내용과 순서가 바뀔 수 있습니다.

「AI에이전트 기획 및 개발」 1~13장의 공통 부록 · 2026-11 기준(Windows 11, Git Bash, 파이썬 3.13.7, git 2.55, GitHub CLI 2.88.1, Claude Code 2.1.296에서 확인)

이 부록은 실습 환경을 갖추는 절차를 한곳에 모은 것이다. 계정 준비, 내 PC의 도구 설치, 터미널, Claude Code의 로그인, Git과 GitHub CLI, 키트 받기, 기준 저장소, 가상 환경, 포트, 프로덕트의 API 키, 모의 모드, Claude Code 설정 파일의 범위, 헤드리스 실행, Agent SDK, Orca, CI의 비밀 정보와 보조 도구를 차례로 다룬다. 각 장의 0절은 이 절차를 되풀이하지 않고 이 부록을 가리킨다.

실습은 학생 각자의 계정으로, 개인 노트북(권장) 또는 실습실 PC에서 한다. 학과 실습 서버는 쓰지 않는다(사용자 결정 11, 2026-11-16). 실습실 PC는 Windows 11로 가정하고, 이 부록의 명령은 Windows의 Git Bash를 기준으로 적는다. macOS에서 다른 점은 해당 자리에 짧게 병기한다.

이 과목은 1학기 「LLM 서비스 개발」의 환경을 그대로 이어 쓴다. 앞 과목에서 이미 한 절차(계정, 도구 설치, Git 설정, GitHub CLI 로그인)는 확인만 하고 넘어간다. 처음 갖추는 학습자는 A-2부터 A-6까지를 차례로 한다. 이 과목에서 새로 생기는 것은 세 가지이다. 첫째, 학기 내내 저장소 하나(~/agent-lab/jobprep)를 운영한다. 둘째, Claude Code의 설정과 확장 기능을 직접 만들므로 설정 파일의 위치와 범위를 알아야 한다. 셋째, 사람이 아닌 프로그램이 Claude Code와 모델을 부르는 실습(헤드리스 실행, 루프, 멀티 에이전트, Agent SDK, CI)이 있으므로, 무엇이 어느 인증으로 얼마를 쓰는지를 미리 정해 둔다.

장 사이 약속

1~13장은 같은 저장소, 같은 가상 환경, 같은 포트 위에서 이어진다. 장마다 다르게 하면 앞 장의 결과를 다음 장의 도구가 찾지 못한다. 모든 장의 강의안과 키트가 지키는 약속은 다음과 같다(2026-11-16 기준).

A-4-4. Windows에서 한글이 깨질 때: 파이썬의 UTF-8 모드와 curl

Windows의 파이썬은 따로 정하지 않으면 한국어 Windows의 기본 문자 집합(cp949)으로 화면 출력을 내보내고 파일을 연다. 그래서 Git Bash에서 파이썬의 출력을 파이프(|)로 다른 명령에 넘기면 한글이 깨지고, 인코딩을 밝히지 않고 UTF-8 파일을 여는 프로그램은 UnicodeDecodeError: 'cp949' codec can't decode로 멈춘다. 환경 변수 PYTHONUTF8=1을 두면 파이썬이 UTF-8 모드로 돌아 화면 출력과 파일의 기본 인코딩이 UTF-8이 된다[P4]. Git Bash를 열 때마다 켜지도록 한 번 등록한다(macOS는 기본이 UTF-8이므로 하지 않아도 된다).

터미널 
echo 'export PYTHONUTF8=1' >> ~/.bashrc
source ~/.bashrc
python -c "import sys; print(sys.flags.utf8_mode, sys.stdout.encoding)" | cat
1 utf-8

등록하기 전에는 같은 명령이 0 cp949를 출력한다(집필용 PC, Windows 11, 파이썬 3.13.7, 2026-11-17). VS Code의 통합 터미널에서도 새 터미널을 연 뒤 위의 확인 명령이 1 utf-8을 출력하는지 본다.

curl의 한글 인자. Git Bash의 curl은 명령줄에 적은 한글을 cp949 바이트로 보낸다. 그래서 -d '{"question": "현장실습 학점은?"}'처럼 한글이 든 요청 본문을 인자로 주면, UTF-8을 기대하는 jobprep의 API가 본문을 읽지 못해 400 {"detail":"There was an error parsing the body"}를 돌려준다. 이것은 파이썬의 설정이 아니므로 PYTHONUTF8=1로 풀리지 않는다. 한글이 든 본문은 heredoc으로 표준 입력에 넣고 --data-binary @-로 보내거나, 파일로 써 두고 --data-binary @파일로 보낸다. heredoc과 파일의 내용은 바이트가 그대로 가므로 UTF-8로 간다.

[터미널] (API 서버를 8000번으로 띄운 뒤, A-10-1)

curl -s -X POST http://127.0.0.1:8000/api/ask \
  -H 'Content-Type: application/json' --data-binary @- <<'JSON'
{"question": "현장실습 학점은?"}

A-5. Claude Code의 판과 로그인

A-5-1. 판 확인과 갱신

터미널 
claude --version
claude doctor
2.1.296 (Claude Code)
명령 하는 일
claude --version 설치된 판을 출력한다
claude doctor 설치 상태와 설정 파일의 오류를 진단한다. 세션을 시작하지 않는다. 지금 폴더의 설정 파일을 신뢰 확인 없이 읽는다(claude --help)
claude update 지금 바로 최신판으로 갱신한다. 네이티브 설치는 백그라운드에서 스스로 갱신하고, 갱신은 다음 실행부터 적용된다[C1]
claude install <판> 정해진 판(stable, latest, 판 번호)을 설치한다(claude install --help)

이 교재의 명령과 출력은 Claude Code 2.1.296에서 확인한 것이다. Claude Code는 빠르게 바뀐다. 헤드리스 옵션, 플러그인 명령, 권한 모드의 기본값은 판에 따라 달라진 적이 있다. 예를 들어 헤드리스 실행에서 아무 모드도 정하지 않았을 때 Manual 모드로 시작하는 동작은 2.1.302부터라고 문서에 적혀 있다[C9]. 출력이 교재와 다르면 먼저 claude --version을 비교하고, 다르면 claude --help, claude <하위 명령> --help, 공식 문서를 우선한다. 13장은 CI에서 쓰는 Claude Code와 액션의 판을 고정하는 법을 다룬다.

[최신 자료 자리: Claude Code의 판과 판에 따라 바뀐 기본값] 확인할 곳: claude --version, https://code.claude.com/docs/en/setup, https://code.claude.com/docs/en/permission-modes, https://code.claude.com/docs/en/headless. 2026-11-15 확인 값: 집필용 PC의 판은 2.1.296이다(2026-11-16에 다시 확인). 문서는 터미널 세션이 v2.1.283부터 auto 모드로 시작하고, claude -p와 Agent SDK가 v2.1.302부터 Manual 모드로 시작한다고 적는다. 자동 갱신의 기본 채널은 latest이다(2026-11-16 확인). 1주차와 7·8·10·13장 전에 다시 확인한다.

A-5-2. 로그인

이 과목에서 Claude Code는 자기 구독 계정의 로그인으로 쓴다(A-2-1). 학생이 API 키를 Claude Code에 등록하지 않는다. Claude Code 터미널에서 claude를 실행하면 처음에 로그인 방식을 묻는다. 구독 계정의 로그인을 고르면 내 PC의 브라우저가 열리고, 브라우저에서 로그인하고 승인하면 터미널로 돌아온다. 브라우저가 열리지 않으면 화면의 로그인 주소를 c로 복사해 브라우저에 붙여 넣고, 브라우저가 보여 주는 코드를 터미널의 Paste code here if prompted 자리에 붙여 넣는다[C2]. 셸에서 로그인만 하려면 claude auth login을 쓴다.

[그림 자리: Claude Code 첫 실행의 로그인 화면과 /status] 로그인 방식 목록, 브라우저의 승인 화면, 로그인 뒤 /status의 Status 탭(로그인 방식, 계정, 모델, Setting sources). 찍을 곳: Windows 11의 VS Code 터미널에서 실행한 Claude Code. 이메일과 조직 이름은 가린다.

터미널 
claude auth status --text
Anthropic base URL: https://api.anthropic.com
Not logged in. Run claude auth login to authenticate.

위는 로그인하기 전의 출력이다(빈 설정 폴더에서 실행, 2026-11-16). 로그인한 뒤에는 같은 명령이 로그인 방식과 계정을 보이고, 만료되었으면 Login: Expired — log in again을 보인다. Claude Code 안에서는 /status의 Status 탭이 판, 모델, 계정, 읽은 설정 파일(Setting sources)을 보여 준다[C3].

  • 로그인 정보는 Windows와 리눅스에서 ~/.claude/.credentials.json에, macOS에서는 키체인에 저장된다[C2]. 이 파일을 복사하거나 저장소에 넣지 않는다. 코드에서 읽어 쓰지도 않는다(A-16).
  • 로그인이 만료되면 /login을 다시 한다. 다른 계정으로 바꾸려면 /logout 뒤 /login을 한다[C2]. 공용 PC에서는 수업이 끝날 때 /logout을 한다(A-2-4).
  • claude setup-token은 Claude 구독으로 장기 토큰을 만드는 명령이다(claude setup-token --help). CI에서 구독으로 Claude Code를 돌릴 때 쓰는 것이며, 이 과목의 학생은 쓰지 않는다(A-18).

[최신 자료 자리: 자격 증명의 저장 위치, 만료 안내, 장기 토큰] 확인할 곳: https://code.claude.com/docs/en/authentication. 2026-11-15 확인 값: 리눅스·Windows는 ~/.claude/.credentials.json(CLAUDE_CONFIG_DIR을 정하면 그 폴더 안), macOS는 키체인이다. 만료 사흘 전부터 Your login expires in 3 days · run /login to renew가, 만료 뒤에는 Login expired · Please run /login이 나온다. claude setup-token은 1년짜리 OAuth 토큰을 만들고 Pro·Max·Ultra·Team·Enterprise 요금제가 필요하다. Windows의 파일 위치는 2026-11-16에 집필용 PC에서 파일이 있음을 확인하였다. 수업 전에 다시 확인한다.

A-5-3. 셸에 키를 두지 않는 까닭

ANTHROPIC_API_KEY를 ~/.bashrc, 셸, Windows의 사용자 환경 변수에 등록하지 않는다. Claude Code는 이 변수가 있으면 계정 로그인보다 그 키를 먼저 쓴다[C2]. 키를 셸에 두면 생기는 일은 셋이다.

  1. 대화형 Claude Code와 헤드리스 루프가 구독 대신 그 키로 청구된다. 프로덕트 실습용으로 소액을 충전한 키가 개발 도구의 사용량으로 빠르게 소진된다.
  2. 셸에서 실행하는 모든 프로그램(훅, 루프의 에이전트, 실험 저장소의 테스트)이 키를 물려받는다. 11장의 위협 모델에서 이것은 비밀 정보가 퍼지는 통로이다.
  3. env 한 번, 오류 메시지 하나로 키가 화면에 드러난다.

다음은 가짜 값을 환경 변수로 주고 인증 상태를 본 결과이다(2026-11-14). 로그인 대신 환경 변수의 키가 인증 수단으로 잡힌다.

$ ANTHROPIC_API_KEY=가짜값 claude auth status --text
API key: ANTHROPIC_API_KEY
Anthropic base URL: https://api.anthropic.com

프로덕트 코드가 쓰는 키는 A-11의 방식으로 jobprep/.env에만 둔다. jobprep의 코드(api/llm.py)와 9장의 프로그램은 실행할 때 python-dotenv로 그 파일을 읽으므로, 셸에 없어도 동작한다.

Git Bash는 Windows의 환경 변수를 물려받으므로, 아래의 첫 줄은 Windows 사용자 환경 변수에 키가 등록된 경우도 잡는다.

터미널 
test -z "$ANTHROPIC_API_KEY" && echo "셸에 키 없음: 정상"
grep -n "ANTHROPIC_API_KEY" ~/.bashrc ~/.bash_profile ~/.zshrc 2>/dev/null || echo "설정 파일에 키 없음: 정상"
셸에 키 없음: 정상
설정 파일에 키 없음: 정상

첫 줄이 아무것도 출력하지 않으면 어딘가에 키가 등록되어 있다. 설정 파일에서 그 줄을 지우고, Windows이면 「시스템 환경 변수 편집」 → 「환경 변수」의 사용자 변수 목록에서 ANTHROPIC_API_KEY를 지운 뒤 VS Code를 새로 연다.

확인 4 새로 연 터미널에서 claude --version이 2.1.로 시작하는 번호와 (Claude Code)를 출력하고, /status의 계정이 자기 구독 계정이며, 위 두 명령이 「정상」을 출력한다.

A-6. Git과 GitHub CLI, 협업자 초대

앞 과목에서 한 설정이 그대로 쓰인다. A-6-1과 A-6-2의 확인만 한다.

A-6-1. Git 설정

터미널 
git config --global --list | grep -E "user\.|quotepath|defaultbranch"
user.name=홍길동
user.email=GitHub에_등록한_이메일
core.quotepath=false
init.defaultbranch=main

위 출력은 예시이다. 이름과 이메일은 사람마다 다르다. 비어 있는 줄이 있으면 다음을 한다.

비어 있는 것 명령 까닭
user.name, user.email git config --global user.name "이름", git config --global user.email "GitHub에 등록한 이메일" 커밋의 작성자. 이메일이 GitHub 계정과 같아야 커밋이 내 계정의 기여로 표시된다[H1]
core.quotepath git config --global core.quotepath false 한글 파일 이름(docs/운영/운영요건.md, Agent_01장)을 "Agent_01\354\243\274..."처럼 깨뜨리지 않고 그대로 보인다
init.defaultbranch git config --global init.defaultBranch main 1장에서 git init으로 만든 첫 브랜치를 main으로 한다

Git for Windows의 시스템 설정. Git for Windows는 설치할 때 모든 사용자에게 걸리는 시스템 설정 파일 C:/Program Files/Git/etc/gitconfig에 몇 가지 값을 넣는다. 집필용 PC에서 git config --system --list --show-origin으로 본 값 가운데 이 과목과 관계있는 것은 core.autocrlf=true, pull.rebase=false, init.defaultbranch=master이다(2026-11-17). 위의 --global 설정은 사용자 설정이므로 시스템 설정보다 앞선다. 그래서 init.defaultBranch main을 꼭 넣는다. 사용자 설정이 없는 채로 git init을 하면 첫 브랜치가 master가 된다(집필용 PC에서 확인). core.autocrlf=true는 git add 때 줄 끝을 바꾼다는 경고를 낼 수 있으나, 기준 저장소는 .gitattributes로 줄 끝을 LF로 고정하므로 jobprep에서는 경고가 나지 않는다(A-8-1). 어느 파일의 값이 쓰이는지 모르겠으면 git config --show-origin --get 설정이름으로 본다.

A-6-2. GitHub CLI 로그인

터미널 
gh auth status
github.com
  ✓ Logged in to github.com account 「GitHub 아이디」 (keyring)
  - Active account: true
  - Git operations protocol: https
  - Token: gho_************************************
  - Token scopes: 'gist', 'read:org', 'repo', 'workflow'

위 출력은 gh 2.88.1의 출력 형식을 따른 예시이다. 로그인되어 있지 않으면 gh auth login을 실행하고 GitHub.com, HTTPS, Git 인증에 예, 웹 브라우저 로그인을 고른다[H2]. 내 PC에서는 브라우저가 열리고, 화면의 한 번용 코드(XXXX-XXXX)를 브라우저에 입력해 승인한다.

  • 1장의 gh repo create, 10장의 PR, 13장의 gh pr checks, gh release, gh api가 이 로그인을 쓴다.
  • git push가 사용자 이름과 비밀번호를 물으면 gh auth setup-git을 실행한다. GitHub는 git push에서 계정 비밀번호를 받지 않는다.
  • 토큰 줄(Token: gho_…)은 화면 공유와 캡처에서 가린다. Token scopes에 workflow가 있어야 13장에서 .github/workflows/의 파일을 푸시할 수 있다. 없으면 gh auth refresh -s workflow를 실행한다(gh auth refresh --help).
  • 공용 PC에서는 수업이 끝날 때 gh auth logout을 한다(A-2-4).

[최신 자료 자리: GitHub CLI의 판과 토큰 범위] 확인할 곳: gh --version, gh auth status, https://cli.github.com/manual/. 2026-11-16 확인 값: 집필용 PC의 gh version 2.88.1 (2026-03-12). 13장에 workflow 범위가 필요하다는 점과 gh auth refresh -s workflow는 2026-11-14에 도움말로 확인하였다. 1주차 전에 다시 확인한다.

A-6-3. 협업자 초대의 수락

이 과목은 수업용 조직을 쓰지 않는다. 키트 저장소(A-7)는 공개 저장소이므로 초대 없이 받는다. 초대가 오는 것은 13장의 짝 리뷰 하나이다. 짝이 자기 비공개 저장소 jobprep에 나를 협업자로 초대하면(A-8-2), 내가 초대를 받아들여야 짝의 저장소를 읽고 리뷰할 수 있다[H7]. 개인 계정 저장소의 협업자는 읽기와 함께 쓰기 권한도 받으므로, 리뷰하는 동안 짝의 저장소에 푸시하지 않는다[H7].

  1. GitHub에 등록한 이메일로 초대 메일이 온다. GitHub에 로그인한 브라우저에서 메일의 링크를 열고 초대를 받아들인다.
  2. 메일을 찾지 못하면 아래 명령으로 받지 않은 초대를 보고, 초대 번호로 받아들인다[H8].
터미널 
gh api user/repository_invitations --jq '.[] | "\(.id) \(.repository.full_name)"'
gh api -X PATCH user/repository_invitations/「초대 번호」
(예시)
301234569 「짝의 GitHub 아이디」/jobprep

위 출력은 REST API 문서에 따른 예시이다. 집필 때 실제 초대로는 실행하지 않았다. 받아들인 뒤에는 첫 명령의 출력이 비어 있다.

[최신 자료 자리: 저장소 초대의 만료 기간] 확인할 곳: https://docs.github.com/en/account-and-profile/setting-up-and-managing-your-personal-account-on-github/managing-access-to-your-personal-repositories/inviting-collaborators-to-a-personal-repository. 2026-11-17에 만료 기간은 문서에서 확인하지 못하였다. 수업 전에 다시 확인한다.

확인 5 git config --global --list에 위 네 설정이 있고, gh auth status에 ✓ Logged in과 workflow 범위가 보인다. 13장 전에는 gh api user/repository_invitations의 출력이 비어 있다.

A-7-4. 교수가 키트를 고쳤을 때

cp -n은 이미 있는 파일을 덮지 않으므로, 교수가 고친 파일은 ~/kits/에 저절로 들어오지 않는다. git -C ~/kits-repo pull로 클론을 최신으로 만든 뒤, 내 사본의 이름을 바꾸어 보관하고 다시 복사한다.

터미널 
git -C ~/kits-repo pull
mv ~/kits/Agent_NN장 ~/kits/Agent_NN장_내사본
cp -rn ~/kits-repo/Agent_NN장 ~/kits/

~/kits-repo 안에서 파일을 고치면 다음 git pull이 충돌로 멈출 수 있다. git -C ~/kits-repo status --short에 고친 파일이 보이면, 필요한 내용을 ~/kits/ 쪽으로 옮긴 뒤 git -C ~/kits-repo restore <파일>로 되돌린다.

확인 6 ls ~/kits-repo에 Agent_ 폴더가 보이고, git -C ~/kits-repo pull이 오류 없이 끝나며, ls ~/kits/Agent_01장가 키트의 README.md를 보인다.

A-9. 파이썬 가상 환경과 장별 패키지

A-9-1. 저장소 안의 가상 환경 하나

이 과목은 가상 환경을 저장소 맨 위에 하나(~/agent-lab/jobprep/.venv) 만들어 학기 내내 쓴다. 저장소가 하나뿐이고 훅(6장), 하네스 점검(7장), 루프(8장)가 저장소의 .venv를 찾아 쓰기 때문이다. 기준 저장소의 .gitignore가 .venv/를 무시한다. 가상 환경은 1장 2-2에서 만든다.

터미널마다 가상 환경을 먼저 켜고, 그 뒤로는 python과 python -m pytest로 부른다. .venv/bin/python …처럼 경로로 부르는 것과 python3은 쓰지 않는다. Windows의 가상 환경에는 .venv/bin/이 없고 .venv/Scripts/가 있으며, Git Bash에는 python3이 없기 때문이다. Claude Code도 가상 환경을 켠 터미널에서 띄운다. 그래야 Claude Code가 실행하는 python이 같은 가상 환경을 쓴다.

[터미널] (Windows의 Git Bash. macOS는 첫 두 줄의 python을 python3으로, Scripts를 bin으로 바꾼다)

cd ~/agent-lab/jobprep
python -m venv .venv
source .venv/Scripts/activate
python -m pip install -r requirements.txt
python -m pytest -q
git check-ignore -v .venv
...........................................                              [100%]
43 passed in 1.16s
.gitignore:7:.venv/ .venv

위 출력은 2026-11-16에 Windows 11의 Git Bash와 파이썬 3.13.7로 기준 저장소 사본을 설치하고 실행한 결과이다(설치 과정의 출력은 줄였다). 실행 시간은 컴퓨터마다 다르다. 설치가 끝날 때 pip의 새 판을 알리는 [notice] 줄이 나올 수 있다. 무시해도 된다.

쓰는 법 뜻 쓰는 때
source .venv/Scripts/activate(macOS source .venv/bin/activate) 가상 환경을 켠다. 입력 줄 앞에 (.venv)가 붙는다 터미널을 열 때마다. Claude Code 터미널도 claude를 띄우기 전에 켠다
python …, python -m pytest -q, python -m pip … 켠 가상 환경의 파이썬과 도구를 쓴다 이 교재의 기본
deactivate 가상 환경을 끈다
command -v python 지금 쓰는 파이썬의 위치 의심스러울 때. 가상 환경을 켰으면 …/jobprep/.venv/Scripts/python이 나온다
  • 가상 환경을 켜지 않고 python을 치면 PC에 설치된 파이썬이 실행된다. No module named pytest나 No module named fastapi가 나오면 먼저 입력 줄 앞의 (.venv)를 본다.
  • pip는 python -m pip로 부른다. 켜지 않은 채 pip만 치면 다른 파이썬에 설치될 수 있다.
  • 가상 환경은 언제든 지우고 다시 만들 수 있는 것으로 다룬다. 그 안에 내 코드를 두지 않는다.

A-9-2. 가상 환경을 켜지 않고 도는 곳

훅(6장), 하네스 점검(7장), 루프와 멀티 에이전트 스크립트(8·10장)는 Claude Code나 다른 스크립트가 띄우므로 가상 환경을 켜지 않은 셸에서 돈다. 이런 곳은 운영체제를 가려 저장소의 가상 환경을 직접 고른다. 규칙은 하나이다. .venv/Scripts/python.exe가 있으면 그것을, 없으면 .venv/bin/python을 쓴다.

파일: 훅과 스크립트에서 파이썬을 고르는 줄 
if [ -x "$ROOT/.venv/Scripts/python.exe" ]; then PY="$ROOT/.venv/Scripts/python.exe"; else PY="$ROOT/.venv/bin/python"; fi

6장 키트의 run_tests.sh, stop_gate.sh, check_hooks.sh는 이 순서(Scripts/python.exe 먼저, 없으면 bin/python)로 찾는다(2026-11-17 키트에서 확인). 11장의 비밀 정보 보호 훅 실행기 block_secrets.sh도 HOOK_PYTHON, .venv/Scripts/python.exe, .venv/bin/python, python, python3의 순서로 찾는다(11장 6-3). 가상 환경이 없거나 이름이 다르면 훅이 「.venv를 찾지 못하였다」로 멈춘다. 학습자가 훅이나 스크립트를 새로 쓸 때도 이 규칙을 따른다.

스크립트의 실행 권한. Windows의 파일에는 실행 권한이 없으므로, Git Bash에서 git add한 .sh 파일은 실행 권한 없는 파일(모드 100644)로 기록된다. 이 저장소를 macOS나 리눅스(13장의 CI 러너)에서 받으면 ./파일.sh로 실행할 수 없고, git 훅(3장의 .githooks/commit-msg)과 경로만 적어 등록한 Claude Code 훅(6장의 protect.sh, run_tests.sh)이 실행되지 않는다. 11장의 block_secrets.sh처럼 bash …로 부르는 등록은 실행 권한이 없어도 돈다. 실행 권한이 필요한 파일은 스테이징할 때 함께 준다(3장 8-8, 6장 7-2).

터미널 
git add --chmod=+x .githooks/commit-msg
git ls-files -s .githooks/commit-msg
100755 742e13d6fd4cee1fed1d410fb79e43f9f4e8e523 0   .githooks/commit-msg

(2026-11-17, 집필용 PC의 시험용 저장소. 해시는 파일 내용에 따라 다르다.) 첫 칸이 100755이면 실행 권한이 기록된 것이다. 이미 커밋한 파일은 git update-index --chmod=+x 파일로 바꾼 뒤 커밋한다. 커밋 출력의 create mode 100755로도 확인할 수 있다.

확인 8 가상 환경을 켠 터미널에서 command -v python이 저장소의 .venv 안을 가리키고, python -m pytest -q의 마지막 줄이 passed로 끝나며(1장 기준 43 passed), git check-ignore -v .venv가 .gitignore의 줄을 출력한다.

  • 서버를 멈출 때는 그 터미널에서 Ctrl+C를 누른다. 백그라운드로 띄웠으면(&) kill %1로 멈춘다(1장 11-2). 터미널만 닫으면 프로그램이 남아 포트를 계속 차지할 수 있다.

부분 뜻
netstat -ano \| findstr :8000 8000번을 쓰는 연결과 그 프로세스 번호(PID, 맨 오른쪽 열). LISTENING 줄이 포트를 차지한 프로그램이다. TIME_WAIT 줄은 끝난 연결의 흔적이므로 무시한다. Git Bash에서는 findstr 대신 grep ":8000 "을 써도 된다
tasklist //FI "PID eq 번호" 그 번호의 프로그램 이름. python.exe이면 내가 띄운 파이썬 서버일 가능성이 크다
taskkill //PID 번호 //F 그 프로그램을 멈춘다. 내가 띄운 것이 아니면 멈추지 않는다
  • Git Bash에서는 Windows 명령의 옵션을 //PID처럼 빗금 두 개로 적는다. 하나만 쓰면 Git Bash가 /PID를 폴더 경로로 바꾸어 넘긴다. PowerShell에서는 taskkill /PID 16592 /F 또는 Stop-Process -Id 16592이다.
  • macOS는 lsof -nP -iTCP:8000 -sTCP:LISTEN으로 PID를 보고 kill <PID>로 멈춘다.
  • 멈출 수 없는 프로그램(다른 과목의 도구 등)이 쓰고 있으면 다른 번호를 쓴다. API를 8001로 띄우고(uvicorn api.main:app --port 8001), 웹을 8101로 띄우면 common.js가 API를 8001에서 찾는다. 웹을 8100 그대로 두려면 http://localhost:8100/?api=8001로 연다. 바꾼 번호는 그 장의 명령(curl의 주소)에도 똑같이 준다.

확인 9 uvicorn을 8000번으로 띄웠을 때 Uvicorn running on http://127.0.0.1:8000이 나오고, 다른 터미널에서 curl -s http://127.0.0.1:8000/api/health가 "status":"ok"를 담은 응답을 보이며, netstat -ano | findstr :8000으로 그 서버의 PID를 찾을 수 있다.

A-11. 프로덕트의 API 키와 .env

A-11-1. 키가 필요한 곳

jobprep의 요약과 질의응답, 9장의 에이전트 루프, 12장의 실제 모델 평가는 Anthropic의 Messages API를 부른다. 이 호출은 API 키로 인증한다. Claude Code에 로그인한 구독 계정은 쓸 수 없다. Claude Code 문서 「Legal and compliance」는 구독 계정의 로그인(OAuth)을 Claude Code와 Anthropic의 앱을 통상적으로 쓰기 위한 것으로 두고, Claude의 기능을 쓰는 제품이나 서비스를 만드는 개발자는 Agent SDK를 쓰는 경우를 포함해 Claude Console의 API 키(또는 지원되는 클라우드 제공자)로 인증해야 한다고 적는다. 개발자가 Claude.ai의 자격 증명이나 세션 토큰을 「collect, store, or intermediate」(수집, 저장, 중개)해서는 안 된다는 문장도 있다[C4].

[최신 자료 자리: 인증 수단의 용도에 관한 약관 문구] 확인할 곳: https://code.claude.com/docs/en/legal-and-compliance, https://code.claude.com/docs/en/agent-sdk/overview. 마지막으로 확인한 날짜: 2026-11-14(이 절의 요약과 인용, A-15-2의 사용 한도 전제, A-16-2의 Agent SDK 인증 제한). 약관은 바뀔 수 있으므로 학기 전에 다시 읽는다.

키가 없어도 모든 장의 실습은 모의 모드로 끝까지 할 수 있다. 이것이 이 과목의 기본이다. 실제 응답을 직접 보고 싶은 학습자만 자기 Console 계정에서 키를 발급하고(A-2-3), 각 장의 「실제 모델로 확인」 단계에서 한 번씩 쓴다(A-12-3). 키를 발급할 때는 Console에서 작업 공간의 지출 한도를 작게 정해 둔다.

A-11-2. .env 만들기

기준 저장소의 .env.example은 변수의 이름과 기본값만 적은 견본이다. ANTHROPIC_API_KEY의 값은 비어 있다. 이 파일은 커밋하고, 실제 값은 복사본 .env에만 적는다.

[최신 자료 자리: 실습에 쓸 모델 이름과 가격] LLM_MODEL의 값, 그 모델의 가격과 기본 effort, 지원 종료 예정. 확인할 곳: https://platform.claude.com/docs/en/about-claude/models/overview, https://platform.claude.com/docs/en/about-claude/pricing. 2026-11-15 확인 값: claude-haiku-5-5(Claude Haiku 5.5)는 현행 모델 목록에 있고, 가격은 입력 100만 토큰당 0.10달러부터, 출력 100만 토큰당 0.50달러부터이며, 기본 effort는 medium, 퇴역은 2027-10-07보다 이르지 않다고 적혀 있다. 수업 직전에 다시 확인한다.

  • 키를 발급했으면 VS Code에서 .env를 열어 ANTHROPIC_API_KEY= 뒤에 붙여 넣는다. 따옴표와 공백 없이 한 줄로 넣는다. echo "ANTHROPIC_API_KEY=…" >> .env로 넣지 않는다. 명령이 셸의 기록(~/.bash_history)에 키와 함께 남는다.
  • Windows에서는 chmod 600 .env가 효과가 없으므로 쓰지 않는다. 사용자 폴더 자체가 다른 사용자에게 막혀 있으므로, 공용 PC에 실제 키를 두지 않는 것으로 대신한다(A-2-4). macOS에서는 chmod 600 .env로 소유자만 읽고 쓰게 할 수 있다.
  • git check-ignore -v .env가 아무것도 출력하지 않으면 무시되지 않는 것이다. 커밋하기 전에 .gitignore를 고친다.
  • api/main.py와 9장의 프로그램은 python-dotenv로 저장소의 .env를 읽되, 이미 정해진 환경 변수는 덮어쓰지 않는다. 그래서 명령 앞에 붙인 값(LLM_FAKE=0 …)이 .env의 값보다 앞선다(A-12-2).
  • 임베딩은 Ollama가 없으면 키트의 대체 구현을 쓴다. 이 과목은 Ollama를 설치하지 않아도 된다.

A-12. 모의 모드와 실제 모델 호출

A-12-1. 두 가지 바꿔 끼우기

이 과목에서 모델을 부르는 코드는 두 자리에서 바꿔 끼울 수 있게 되어 있다. 하나는 제품 코드의 LLM 호출이고, 다른 하나는 스크립트가 띄우는 에이전트 명령이다.

자리 변수 모의 값 실제 값 쓰는 장
제품 코드의 LLM 호출(api/llm.py, 9장 agent_loop) LLM_FAKE 1(정해진 응답) 0(API 키로 호출) 1·2·9·12장
12장 평가의 모델 --backend sim(변동 모의 모델, 기본값) real 12장
루프와 파이프라인의 에이전트 명령 AGENT_CMD python ops/loop/fake_agent.py 비우면 claude(헤드리스) 8장
멀티 에이전트의 구현 에이전트 AGENT_CMD python ops/multi/fake/impl_agent.py bash ops/multi/claude_impl.sh 10장
가짜 에이전트의 각본 FAKE_SCENARIO success, fail, budget, cheat, digest(8장), T2=fail_once 등(10장) 쓰지 않음 8·10장

모의 모드를 두는 까닭은 셋이다. 키가 없거나 한도에 닿아도 수업이 멈추지 않는다. 같은 입력에 늘 같은 출력이 나오므로 테스트가 매번 같은 결과를 낸다. 비용이 들지 않는다. 가짜 에이전트는 2장에서 배운 테스트 더블을 에이전트 자리에 쓴 것이다. claude -p와 같은 옵션을 받고 같은 모양의 결과 객체를 내므로, 루프 스크립트는 바꾸지 않고 AGENT_CMD만 바꾼다.

모의 모드로 확인하는 것은 흐름(입력 검사, 판정, 재시도, 상한, 기록, 사람 넘김)이다. 응답의 품질과 실제 에이전트의 행동은 실제 호출로만 확인할 수 있다.

A-12-2. 값을 주는 자리와 우선순위

자리 쓰는 법 적용 범위
명령 앞 LLM_FAKE=0 python -m agent_loop.loop "질문" 그 명령 한 번
export export AGENT_CMD="python ops/loop/fake_agent.py" 그 터미널을 닫거나 unset할 때까지

  • 테스트(tests/conftest.py)는 .env와 상관없이 LLM_FAKE=1을 강제한다. 테스트를 아무리 돌려도 모델을 부르지 않는다.
  • .env의 LLM_FAKE=1은 바꾸지 않는다. 실제 호출은 명령 앞에 LLM_FAKE=0을 붙여 그 명령에만 준다. 이 꼴은 Git Bash와 macOS에서 그대로 된다(PowerShell에서는 되지 않는다).

A-13. Claude Code 설정 파일의 위치와 범위

3장부터 학습자는 Claude Code의 설정을 직접 만든다. 같은 설정이라도 어느 파일에 두는가가 「누구에게 적용되는가」를 정한다. 이 절은 3~7장에서 만드는 파일들이 어디에 놓이는지를 한 표로 모은다. 각 파일의 내용과 문법은 그 장에서 다룬다.

A-13-1. 네 범위와 파일

A-13-2. 개인 파일을 저장소에서 빼기

.claude/settings.local.json과 CLAUDE.local.md는 개인 파일이다. Claude Code는 확인 창에서 처음 로컬 설정을 쓸 때 그 파일을 git의 전역 제외 목록에 더한다. 손으로 만든 경우에는 그렇게 하지 않으므로 저장소의 .gitignore에 직접 적는다[C3]. 이 과목은 3장에서 두 줄을 .gitignore에 넣는다.

터미널 
cd ~/agent-lab/jobprep
git check-ignore -v .claude/settings.local.json CLAUDE.local.md
.gitignore:26:.claude/settings.local.json   .claude/settings.local.json
.gitignore:27:CLAUDE.local.md   CLAUDE.local.md

줄 번호는 저장소마다 다르다. 아무것도 출력하지 않으면 .gitignore에 없는 것이다(3장 7-3).

A-13-3. 읽은 설정의 확인

어느 설정 파일이 실제로 읽혔는지는 Claude Code 안의 /status에서 Setting sources 줄로 본다. 이 줄은 읽은 파일만 알려 주고, 어느 키가 어느 파일에서 왔는지는 알려 주지 않는다. 문법이 깨진 설정 파일이나 거부된 항목은 셸의 claude doctor가 보여 준다[C3]. 헤드리스 실행(claude -p)은 대화 상자를 띄우지 않고 깨진 설정 파일을 조용히 건너뛴다(claude --help). 루프가 이상하게 규칙을 지키지 않으면 claude doctor를 먼저 돌린다.

[그림 자리: /status의 Setting sources 줄과 claude doctor의 설정 오류 보고] 프로젝트 설정을 읽은 세션의 Setting sources 줄, 일부러 JSON 문법을 깨뜨린 settings.json에 대한 claude doctor의 보고를 나란히 둔다. 찍을 곳: 연습 폴더(~/agent-lab/ops-demo)의 Claude Code와 Git Bash 터미널.

A-13-4. 연습용 격리: CLAUDE_CONFIG_DIR

4장(플러그인의 user 범위 설치)과 7장(하네스 플러그인)처럼 사용자 범위의 설정을 바꾸는 연습은, 실제 내 설정(~/.claude/)을 어지럽힐 수 있다. 환경 변수 CLAUDE_CONFIG_DIR을 정하면 Claude Code는 사용자 폴더의 설정, 세션 기록, 플러그인을 그 폴더에 둔다[C3]. 연습용 빈 폴더를 정하면 내 설정과 섞이지 않는 사용자 범위를 따로 하나 갖게 된다.

터미널 
mkdir -p ~/agent-lab/cc-practice
export CLAUDE_CONFIG_DIR=~/agent-lab/cc-practice
claude auth status --text
claude plugin list
ls -A ~/agent-lab/cc-practice
Anthropic base URL: https://api.anthropic.com
Not logged in. Run claude auth login to authenticate.
No plugins installed. Use `claude plugin install` to install a plugin.
.claude.json
backups

위 출력은 2026-11-16에 Windows 11의 Git Bash에서 스크래치의 빈 폴더를 정하고 실행한 결과이다. 실행 뒤 그 폴더에 .claude.json이 생긴다. 빈 설정에 미리 등록된 마켓플레이스는 claude plugin marketplace list로 보면 anthropic-plugin-directory 하나이다(2026-11-14). 격리의 성질은 다음과 같다.

  • 로그인도 격리된다. 위처럼 Not logged in이 나온다. claude plugin과 claude mcp의 관리 명령은 로그인 없이 돌지만, 그 폴더로 대화를 하려면 다시 로그인해야 한다. 연습에서는 관리 명령의 결과(어느 파일에 무엇이 기록되는가)만 보고, 대화는 원래 설정으로 한다.
  • 사용자 범위만 격리된다. 프로젝트 범위(.claude/settings.json, .mcp.json)와 프로젝트 로컬 범위(.claude/settings.local.json)는 여전히 저장소 폴더에 쓰인다. 연습은 저장소가 아닌 빈 폴더(예: ~/agent-lab/ops-demo)에서 한다.
  • export는 그 터미널에만 남는다. 연습이 끝나면 unset CLAUDE_CONFIG_DIR로 지운다. 그대로 두면 그 터미널의 Claude Code가 로그인되지 않은 연습 폴더를 계속 쓴다. 한 명령에만 주려면 CLAUDE_CONFIG_DIR=~/agent-lab/cc-practice claude plugin list처럼 명령 앞에 붙인다.
  • 세션을 띄울 때 설정 출처만 줄이려면 --setting-sources user,project처럼 읽을 범위를 정하는 옵션도 있다. 설정의 문제를 가리기 위해 모든 사용자 정의(CLAUDE.md, 스킬, 플러그인, 훅, MCP)를 끄고 시작하는 --safe-mode도 있다(claude --help). 둘 다 파일을 바꾸지 않는다.

확인 12 CLAUDE_CONFIG_DIR을 연습 폴더로 정한 터미널에서 claude plugin list가 No plugins installed를 출력하고, unset CLAUDE_CONFIG_DIR 뒤의 claude auth status --text는 원래 계정을 보인다.

A-14. 플러그인 마켓플레이스와 MCP 서버의 등록 범위

4장(플러그인)과 5장(MCP)은 무엇인가를 Claude Code에 등록한다. 등록 명령에는 모두 --scope(또는 -s)가 있고, 생략했을 때의 기본값이 명령마다 다르다. 기본값을 모르고 등록하면 의도와 다른 파일에 기록된다.

명령 범위의 값 생략하면 근거
claude plugin marketplace add <출처> user, project, local user claude plugin marketplace add --help
claude plugin install <플러그인>@<마켓플레이스> user, project, local user claude plugin install --help
claude mcp add <이름> -- <명령> local, user, project local claude mcp add --help

project 이 저장소에서 일하는 모든 사람 .claude/settings.json 예
local 나, 이 저장소에서만 .claude/settings.local.json 아니요

같은 플러그인이 여러 범위에 있으면 local이 project를, project가 user를 덮는다[C6]. project 범위의 기록을 커밋하면 팀원에게 「켜짐」으로 기록되지만 팀원의 컴퓨터에 내려받아지지는 않는다. 팀원은 저장소를 받은 뒤 한 번 claude plugin install <이름>@<마켓플레이스> --scope project를 실행한다[C6].

  • 대화형 세션은 .mcp.json의 서버를 쓰기 전에 하나씩 승인을 묻는다. 승인하지 않은 서버는 claude mcp list에 ⏸ Pending approval로 보인다. 선택을 되돌리려면 claude mcp reset-project-choices를 실행한다(claude mcp --help).
  • 헤드리스 실행(claude -p)과 Agent SDK는 승인 창을 띄울 수 없으므로 .mcp.json의 서버를 묻지 않고 띄운다[C5]. 같은 이유로 claude -p는 처음 보는 폴더에서도 그 폴더의 .claude/settings.json 훅을 실행한다[C9]. 남의 저장소나 PR의 사본에서 claude -p를 돌리지 않는 까닭이다(8장 3-5, 11장).
  • 키가 필요한 MCP 서버는 -e KEY=값으로 넣지 않는다. 그 값이 ~/.claude.json이나 .mcp.json에 평문으로 남는다. 이 과목의 서버는 키가 필요 없다.

확인 13 연습 폴더에서 claude mcp add를 범위 없이 실행하면 출력에 to local config가, -s project로 실행하면 .mcp.json이 나타나는 것을 확인하였다. 확인한 뒤 claude mcp remove <이름>으로 지우고 unset CLAUDE_CONFIG_DIR을 실행한다.

  • 「Legal and compliance」는 Pro, Max 같은 요금제의 사용 한도가 Claude Code와 Agent SDK의 통상적인 개인 사용을 전제로 한다고 적는다[C4]. 루프를 밤새 돌리거나 여러 세션을 한꺼번에 띄우는 일은 한도에 금방 닿는다. 실습은 장마다의 실행 상한(A-12-3) 안에서 상한을 건 한 번의 실행으로 그친다.

A-15-3. 헤드리스 실행의 안전 수칙

  1. 신뢰하는 폴더에서만 실행한다. 자기 저장소, 자기가 만든 실험 저장소(7장 ~/agent-lab/exp/), 자기 worktree(10장)만이다. 남의 PR 사본이나 내려받은 저장소에서 claude -p를 돌리지 않는다. 그 폴더의 훅이 묻지 않고 실행된다.
  2. 권한을 좁게 준다. 루프는 --permission-mode dontAsk와 --allowedTools로 목록 밖을 모두 거부한다(8장 3절). --dangerously-skip-permissions와 bypassPermissions는 도움말이 인터넷이 막힌 격리 환경에서만 쓰라고 하는 옵션이므로 쓰지 않는다(claude --help). 내 PC는 격리 환경이 아니며, Windows에서는 샌드박스도 없다(A-1-2).
  3. 상한을 건다. 금액(--max-budget-usd), 턴(--max-turns), 시간(스크립트의 시간 상한)을 함께 건다.
  4. 기록을 남긴다. --output-format json 또는 stream-json의 출력을 파일로 남기고, 세션 ID로 claude --resume <세션 ID>를 열어 사람이 살펴볼 수 있게 한다.

확인 14 위 claude --help | grep … 명령이 여덟 줄을 출력하고, /usage로 지금 계정의 사용 한도를 볼 수 있다.

A-16. Agent SDK 설치

A-16-1. 설치

9장은 직접 만든 에이전트 루프와 같은 일을 Claude Agent SDK로 만든 판과 견주어 읽는다(9장 10절). SDK의 설치는 선택이고, 실제 실행은 교수 시연이다. Agent SDK는 Claude Code를 라이브러리로 쓰게 하는 파이썬·타입스크립트 패키지이며, 파이썬 패키지 이름은 claude-agent-sdk이다[C7]. 9장은 판 0.2.182를 고정한다.

항목 내용(2026-11-14 확인)

A-16-2. 인증: API 키만

Agent SDK 문서는 사전 승인이 없는 한 제3자 개발자가 Agent SDK로 만든 에이전트를 포함해 자기 제품에서 claude.ai 로그인이나 그 사용 한도를 쓰게 하는 것을 허용하지 않으며, API 키 인증을 쓰라고 한다[C7]. 「Legal and compliance」도 Agent SDK를 쓰는 개발자는 Console의 API 키나 지원되는 클라우드 제공자로 인증해야 한다고 적는다[C4]. 그래서 이 과목은 다음과 같이 나눈다.

프로그램 인증
학습자가 쓰는 Claude Code(대화형, 헤드리스) 구독 계정의 로그인
9장 agent_loop/loop.py(직접 만든 루프) jobprep/.env의 API 키(발급한 경우)

A-17-2. 에이전트 계정과 PC 자원

Orca는 에이전트를 돌리는 그릇이고, 모델을 부르는 것은 Orca 안에서 실행하는 Claude Code이다. 작업 공간의 에이전트는 내 PC에서 돌므로, 내 PC의 Claude Code에 자기 구독 계정으로 로그인되어 있으면 된다(A-5). ANTHROPIC_API_KEY를 셸에 등록하지 않는 원칙(A-5-3)은 Orca에서도 같다. 10장 9-4에서 쓰는 사용량은 세션 둘, 시도 상한 2회이므로 많아야 세션 넷이다. 실습 전후에 Claude Code 안에서 /usage로 사용량을 본다.

동시에 돌리는 에이전트는 2개로 한다(장 사이 약속의 병렬 상한). 에이전트는 모델의 답을 기다리는 동안 자원을 거의 쓰지 않지만, 테스트를 돌리는 동안에는 CPU 코어 하나 안팎과 수백 MB의 메모리를 쓴다. 자기 PC의 코어와 메모리가 넉넉하지 않으면 하나씩 돌린다.

(2026-11-16, 집필용 PC의 Git Bash. macOS에서는 sysctl -n hw.ncpu와 sysctl -n hw.memsize.) nproc는 쓸 수 있는 CPU 코어 수이고, MemFree는 지금 비어 있는 메모리이다. 코어가 4개 이하이거나 비어 있는 메모리가 2GB(약 2,000,000kB)에 못 미치면, 다른 프로그램(브라우저 탭, 다른 편집기)을 닫거나 작업 공간 둘의 테스트를 번갈아 돌린다. 이 기준은 Claude가 권장한 값이며 10장에서 실제로 재어 고칠 수 있다.

A-18. GitHub Actions의 비밀 정보

13장의 CI 워크플로(ci.yml)는 비밀 정보를 하나도 읽지 않는다. 테스트(test), 회귀 평가(eval), 비밀 탐지(secrets), 규칙 검사(rules)가 모두 모의 모드로 돌기 때문이다. 학생 저장소에 API 키를 비밀 정보로 등록하지 않는다. 키가 꼭 필요한 Claude Code의 PR 검토(claude-code-action)는 교수 시연으로 본다(13장 4-4). 이 절은 그 시연과 프로젝트실습에서 쓸 때를 위한 절차이다.

A-18-1. 등록

GitHub은 키를 저장소, 환경(environment), 조직 단위의 비밀 정보(secrets)로 맡아 두고 워크플로에서 ${{ secrets.이름 }}으로 꺼내 쓰게 한다.

방법 절차
웹 화면 저장소의 Settings → 왼쪽 Security 무리의 Secrets and variables → Actions → Secrets 탭 → New repository secret → 이름과 값 → Add secret[H9]
GitHub CLI gh secret set ANTHROPIC_API_KEY를 실행하면 값을 묻는다. 붙여 넣고 Enter[H9]
확인 gh secret list(값은 보이지 않고 이름과 갱신 시각만 보인다)
Claude Code /install-github-app이 Claude GitHub App 설치, 비밀 정보 등록, 워크플로 PR 준비를 차례로 안내한다. 저장소 관리자 권한이 필요하다[C10]

[그림 자리: 저장소의 Actions 비밀 정보 화면] 저장소 Settings → Secrets and variables → Actions의 Secrets 탭과 「New repository secret」 단추, 등록 뒤 이름과 갱신 시각만 보이는 목록. 찍을 곳: 교수 시연 저장소. 값은 화면에 나오지 않으나 저장소 이름은 가린다.

gh secret set에 --body "값"으로 값을 주지 않는다. 셸 기록에 남는다. gh secret set -f .env는 .env의 모든 줄을 한꺼번에 비밀 정보로 올리는 기능이다(gh secret set --help). .env에는 필요 없는 값까지 들어 있으므로 쓰지 않는다.

A-18-2. 쓰는 규칙

  • 비밀 정보를 출력하지 않는다. 실행 기록에 찍힌 값은 가려지지만 문서는 이 가림이 보장되지 않는다고 적는다(13장 2-7).
  • 비밀 정보 하나에 값 하나만 넣는다. JSON 묶음을 통째로 넣으면 가림이 제대로 동작하지 않는다.
  • 비밀 정보가 필요한 작업에만 넘긴다. ci.yml의 네 작업에는 넘기지 않는다.
  • 포크에서 온 PR이 일으킨 워크플로에는 비밀 정보가 넘어가지 않는다(GITHUB_TOKEN은 예외)[H9]. 외부인의 PR에 키가 쓰이지 않게 하는 장치이다.
  • 워크플로의 임시 토큰 GITHUB_TOKEN의 권한은 permissions로 좁힌다. ci.yml은 contents: read만 쓴다(13장 2-7).
  • 비밀 정보를 지워도 그 안에 있던 키는 여전히 유효하다. 키를 더 쓰지 않으려면 Console에서 키 자체를 폐기한다[C10].
  • 구독으로 CI의 Claude Code를 돌리는 길(claude setup-token으로 만든 토큰을 CLAUDE_CODE_OAUTH_TOKEN으로 등록)도 문서에 있다[C10]. 학생 계정의 장기 토큰을 저장소에 맡기는 일이므로 이 과목에서는 하지 않는다.
